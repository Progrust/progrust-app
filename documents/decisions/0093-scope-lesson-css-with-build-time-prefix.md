## 背景

動画のシーンには、レッスン専用の部品と CSS を作ってよい（[ADR 0062](0062-write-video-scenes-in-unrestricted-tsx.md)）。そのままでは、レッスン専用の CSS が、ほかのレッスンの動画とアプリの画面にも効く。この CSS を閉じ込める方法が、教材データ形式の未決事項として残っていた。

Issue #5 の技術検証で、5 つの候補（そのまま・CSS Modules・`@scope`・ビルド時の接頭辞・Shadow DOM）を、2 本のレッスンを同時に開いた状態で試した（[レッスン専用の CSS の閉じ込め方の技術検証](../verification/issue-5-scope-lesson-css.md)）。

- そのままでは、閉じたレッスンの CSS も文書に残り、後から開いたレッスンの規則が前のレッスンの動画を上書きした。
- CSS Modules では、要素だけのセレクタ（`h5 {}` など）がアプリとほかのレッスンに漏れた。
- `@scope` とビルド時の接頭辞は、自分のクラス・要素のセレクタ・デザインシステムの部品の上書きのどれも、そのレッスンの中にだけ効いた。違いは、`@scope` の中の `:root` がどこにも効かず、接頭辞では `:root` をレッスンの根に置き換えられたこと。
- Shadow DOM は最も強く閉じ込められた。ただし、レッスンの CSS を文字列で集める仕組み、デザインシステムの CSS の `:root` を `:host` に書き換えること、テーマと章を Shadow の中に渡すこと、デザインシステムの CSS を Shadow ごとに持つことが要る。
- どの候補でも、デザインシステムの CSS（トークンと部品のクラス）は効いた。

対応環境は作者の Mac だけで（[ADR 0090](0090-support-only-authors-mac-until-completion.md)）、その WebKit ではすべての候補が動いた。`@scope` は Safari 17.4 から使え、それより前の WebKit では `@scope` の中の規則が丸ごと無視される。

Claude は、ビルド時の接頭辞を推奨した。ユーザーは、「今後バージョンやOS互換をする可能性があるので、候補3で良さそう」と示し、ビルド時の接頭辞に決めた。

## 決定

- レッスン専用の CSS は、ビルド時に、すべてのセレクタの前にレッスンの属性セレクタ（`[data-lesson="{レッスン ID}"]`）を付けたものに変えて、そのレッスンの動画の中に閉じ込める。`:root` は、その属性セレクタに置き換える。アプリは、各レッスンの動画を、その属性を持つ要素の中に描く（[動画を構成するファイル](../spec/content-format/video/structure.md)）。
- 作者は、普通の CSS を書く。CSS Modules のような書き方の決まりは設けない（[動画のシーンの書き方](../spec/content-format/video/scenes.md)）。
- この判断は、[ADR 0090](0090-support-only-authors-mac-until-completion.md) の対応環境を変えず、他の環境での確認も加えない。対応環境では、候補 2（`@scope`）と候補 3（接頭辞）の閉じ込めの結果は同じだった。
- 次の細部は Claude が決めた。
  - 検証で、この方法を選ぶなら合わせて決める必要があるとした 2 点（アプリの画面の CSS が動画の中にも効くこと（逆向きの漏れ）の扱いと、レッスン専用の CSS で動画のデザインシステムの部品を上書きしてよいか）は、決めずに未決事項として残す（[教材データ形式の未決事項](../spec/content-format/open-questions.md)）。理由: ユーザーが決めたのは閉じ込めの方法で、この 2 点の判断はまだ示されていない。

## 検討した他の案

- 案: そのまま（Vite が塊の CSS として文書に入れる）
  - 採用しなかった理由: ほかのレッスンの動画とアプリの画面に効く。閉じたレッスンの CSS も文書に残る
- 案: CSS Modules
  - 採用しなかった理由: 要素だけのセレクタが漏れる。防ぐには lint で禁じる必要があり、デザインシステムの部品を上書きするには `:global()` が要って、それも全体に効く
- 案: `@scope` で包む
  - 採用しなかった理由: 対応環境では接頭辞と同じ範囲に閉じ込められるが、Safari 17.4 より前の WebKit では使えない。今後、対応する macOS のバージョンや OS を広げる可能性がある
- 案: Shadow DOM
  - 採用しなかった理由: 閉じ込めは最も強いが、レッスンの CSS を文字列で集める仕組み、デザインシステムの CSS の書き換え、テーマと章を Shadow の中に渡すこと、デザインシステムの CSS の二重持ちが要る

## 影響

- 変換の出力は普通のセレクタなので、`@scope` に対応しない WebKit でも閉じ込められる。
- 閉じ込めは、レッスン専用の CSS からほかへの向きだけである。アプリの画面の CSS は、動画の中にも効く（検証では、アプリの `h6 {}` の規則が動画の中に効いた）。
- レッスン専用の CSS のセレクタは、属性セレクタの分だけ詳細度が上がり、動画のデザインシステムの部品の規則に勝ちやすくなる。
- 次の 2 点は、変換の仕組みから見込まれることで、検証では確かめていない。
  - セレクタの前に付けた属性セレクタは子孫を選ぶので、レッスンの動画を描く要素の外の祖先（テーマ・章の属性を持つ要素）を見るセレクタは、レッスン専用の CSS では当たらない。
  - 変換するのはセレクタだけなので、`@font-face`・`@property` など、文書全体で名前を共有する規則は閉じ込められない。
- レッスン専用の CSS をセレクタごとに変換するビルドの処理（Vite のプラグイン）を、アプリ側で用意して保守する。
