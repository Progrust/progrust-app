- 置き換え: なし

## 背景

デザインシステム「Progrust」「Progrust Video」の README と部品ごとの README は、仕様の文書を、`documents/spec/` からのパスをインラインコードで書いて参照している（例: 仕様の `screens/appearance.md`「書体のファイル」）。

Issue #61 では、デザインシステム（当時は Claude のアーティファクト）に、いまは無い仕様のファイルへの参照が 23 か所あった。デザインシステムをリポジトリに移しても（[ADR 0152](0152-keep-design-system-files-in-repository.md)）、ドキュメントの検査（`python3 tools/check-documents.py`）は `documents/` だけを見るので、この種の古い参照は見つからないままだった（ADR 0152 の「影響」）。`python3 tools/design-system.py check` も README の中の参照を確かめていなかった。Issue #68 は、これを問題として挙げた。

2026-11-22、ユーザーが呼んだ Issue の仕分け（`/triage-issues`）で、Claude は Issue #68 を直すと決めた。いまの参照を調べると、どれも「インラインコードのパス」に「「小見出し」」を続ける形だった。仕様の小見出しは、`## 見出し` のほかに、1 行だけの太字（`**共通部品**` など）でも書かれていた。どちらも見出しとして数えると、いまの参照はすべて、実在する文書と小見出しを指していた。

この判断は、アプリの操作感に関わらない技術的な判断で、`CLAUDE.md` はそのような判断を Claude に任せている。以下の決定と理由は、Claude の判断である。

## 決定

- `python3 tools/design-system.py check` に、デザインシステムの中の `.md` のファイルの参照を確かめる規則（`spec-ref`）を足す（[デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)「検査」）。
  - 理由: 仕様のファイルを移したり、小見出しを変えたりしたときに、デザインシステムの参照が古いまま残るのを、検査で見つけられる。
- 仕様の文書（`documents/spec/`）を移したり、名前や小見出しを変えたりしたときも、`python3 tools/design-system.py check` を実行する（[テストの方針](../spec/non-functional/testing.md)「実行するとき」、[ドキュメントの検査](../conventions/checks.md)「実行」）。
  - 理由: それまでは、デザインシステムの検査を実行するのは、デザインシステムを変えたときと CI だけだった。仕様だけを変えたときに実行しないと、この規則が見つけるはずの古い参照が残る。CI は push のたびにデザインシステムの検査を実行すると定めているが（[テストの方針](../spec/non-functional/testing.md)「CI」）、2026-11-22 の時点では、CI の設定はまだリポジトリに無い。
  - 運用ルールにも書くのは、`documents/` を変える AI エージェントが、変える前に運用ルールを読むからである（`CLAUDE.md`）。`CLAUDE.md` の「必ず守ること」には、`documents/` を変えたら `python3 tools/check-documents.py` を実行することだけが書かれている。この判断では、`CLAUDE.md` は変えていない。
- 確かめる範囲は、インラインコードで書いた `.md` のパスと、その直後に続く「小見出し」とする。
  - 理由: いまの参照は、すべてこの形で書かれている。この形なら、文の中の他の言葉を参照と取り違えずに見つけられる。
- `/` を含むパスは `documents/spec/` からのパスとし、`components/`・`assets/` で始まるパスと `/` を含まないパスは、そのデザインシステムのディレクトリからのパスとする。
  - 理由: `chapter-colors.md` のように、デザインシステムの中のファイルを指す参照もある。デザインシステムの中のディレクトリは `components/` と `assets/` だけで、仕様のディレクトリ名と重ならない。
- 小見出しは、`## 見出し` などの見出しと、1 行だけの太字の行の両方と照らす。
  - 理由: 仕様の文書は、小見出しを太字の行で書くことがある（「背景」を参照）。見出しだけと照らすと、正しい参照を誤りと指摘する。
- 仕様のディレクトリは、既定ではリポジトリの `documents/spec/` とし、`--spec-root` で差し替えられるようにする。
  - 理由: `--root` でデザインシステムのディレクトリを差し替えて試すときに、仕様の側も差し替えて試せる。

## 検討した他の案

- 案: `python3 tools/check-documents.py` に、`design-system/` の参照を確かめる規則を足す
  - 採用しなかった理由: `check-documents.py` は OKF のバンドル（`documents/`）を検査する道具で、デザインシステムのファイルは OKF の決まりに従わない（[ADR 0152](0152-keep-design-system-files-in-repository.md)）。デザインシステムの置き方を確かめる道具は `tools/design-system.py` にまとまっている。
- 案: パスのファイルが実在するかだけを確かめ、小見出しは確かめない
  - 採用しなかった理由: 仕様の小見出しを変えたときの古い参照を見つけられない。小見出しまで確かめても、いまの参照で誤った指摘は出ない（「背景」を参照）。
- 案: インラインコードで書いていない参照（ADR の番号、「README「寄せ方」」のような README の中の節への参照など）も確かめる
  - 採用しなかった理由: 書き方の形が決まっておらず、文の中の他の言葉と取り違えずに見つける方法がない。

## 影響

- 仕様のファイルを移したり、名前や小見出しを変えたりすると、デザインシステムの検査が、古い参照を指摘する。仕様を変えた人は、デザインシステムの検査も実行し、デザインシステムの参照も直す。実行を忘れると、CI の設定ができるまでは、見つからないまま残る。直した後は、アーティファクトへ送る（[デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)「変更の手順」）。
- 参照の中身が正しいかは、確かめない。たとえば、README が「未決事項」と書いた事項が仕様で決まっても、検査は見つけない（Issue #66 の、書体の同梱の説明がその例）。
- インラインコードで書いていない参照は、確かめない。
- ADR 0152 の「影響」の、デザインシステムの README から仕様への参照が古くなってもドキュメントの検査では見つからないことは、この判断で、インラインコードのパスで書いた参照については、デザインシステムの検査で見つかるようになった。
