- 置き換え: なし

## 背景

動画画面のプレーヤーの操作とキーボードショートカットは、アプリの仕様で決めている（[動画画面](../spec/screens/video-screen.md)）。Remotion の Player にも、組み込みの操作とキー操作がある。アプリの操作と重ならないようにするための Player の設定は、未決事項として残っていた。実装計画の M1 で、動画画面を作るために決める必要があった。

[独自のプレーヤー操作を Player の API で作れるかの技術検証](../verification/issue-3-player-custom-controls.md) では、動画画面の操作をすべて Player の外に作れた。キー操作の衝突を避けるには `controls={false}` と `spaceKeyToPlayOrPause={false}` にするとよい、と残った事項に書いた。

## 決定

- Player の操作の表示、Space キーでの再生と一時停止、クリックでの再生と一時停止、ダブルクリックでの全画面表示を無効にする。末尾まで再生したら先頭に戻さず、繰り返さない（[動画を構成するファイル](../spec/content-format/video/structure.md)）。Claude が決めた。
  - 理由: 技術検証のとおり、組み込みの操作とアプリの操作が両方動くと、同じキーで二重に切り替わる。動画画面の仕様では、動画を押しても再生は切り替わらず、全画面表示も無い。最後まで再生したら末尾で止まる（[動画画面](../spec/screens/video-screen.md)）。

## 検討した他の案

- 案: Player の組み込みの操作を使い、見た目だけをデザインシステムに合わせる
  - 採用しなかった理由: 組み込みの操作には、5 秒のスキップ、シーンの区切りの印、字幕の切り替えが無く、デザインシステムの操作の部品（VideoControls）とも形が違う

## 影響

- 再生の操作は、すべてアプリの部品が Player の API で行う。
- 本物のキー入力での確かめは、技術検証では済んでいない（合成したイベントだけで確かめた）。動画画面を作ったあと、人が操作して確かめる。
