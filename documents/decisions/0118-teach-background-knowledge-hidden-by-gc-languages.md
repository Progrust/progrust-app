## 背景

想定する学習者は他のプログラミング言語の経験者で、一般的なプログラミングの概念は既知としている（[ADR 0002](0002-target-experienced-programmers.md)）。カリキュラムは TRPL を網羅の目安にして組み立てた（[ADR 0077](0077-curriculum-uses-trpl-as-coverage-guide.md)）。

ユーザーは次のように示した。「今のカリキュラムでは、Rust言語を理解するうえで必要な周辺知識（ヒープメモリやスタックメモリなど）も学べる内容になっていますか？一応Rust以外の言語をある程度知っている前提ですが、PythonやJavaScriptなら意識しなくても良いものも、Rustだと意識する必要がある概念があると思っています。これらも学べるようにしておきたいです。」

章とレッスンの一覧を調べると、スタックとヒープ、整数の大きさとオーバーフロー、UTF-8 のバイト数と文字数などは「主に扱う内容」に書かれていた。一方で、コンパイル時と実行時の区別、ガベージコレクションがないこと、変数が値そのものを持つこと、String の形、参照の実体、スタックフレーム、型の大きさ、スレッドとデータ競合、単相化、未定義動作は、どのレッスンにも書かれていなかった。

## 決定

- ガベージコレクションのある言語では意識しなくてよいが Rust では意識する必要がある周辺知識を、既知としない（[想定する学習者](../spec/content-guidelines/target-learner.md)）。
  - 理由: 上の「背景」のユーザーの発言のとおり。
- 周辺知識は、TRPL が扱っていないものも扱う（[カリキュラムの方針](../spec/curriculum/policy.md)）。
  - 理由: OS のスレッドと JavaScript のイベントループ・Python の GIL との違いのように、TRPL が扱っていない周辺知識があり、TRPL の網羅だけを基準にすると入らない。
- 周辺知識のうち、特定の Rust の要素の理由になるものはその要素のレッスンの「主に扱う内容」に含め、複数のレッスンの前提になるものは動画のみのレッスンにする（[カリキュラムの方針](../spec/curriculum/policy.md)）。Claude が提案し、ユーザーが採用した。
  - 理由: 特定の要素の「なぜ」にあたる知識は、その要素のレッスンの中で説明するほうが自然である。メモリの仕組みと、スレッドとデータ競合は、章の中の複数のレッスンの前提になる。
- 章とレッスンの一覧を、次のように変えた。

  | 周辺知識 | 扱うレッスン |
  | --- | --- |
  | コンパイル時と実行時の区別 | ch01-01 に追加 |
  | スタックとヒープ、スタックフレーム、ガベージコレクションがないこと、二重解放・解放後の使用 | ch04-01「メモリの仕組み」を新設（動画のみのレッスン）。スタックとヒープは、それまでの「スコープと値の破棄」から移した |
  | String の形（ポインタ・長さ・容量） | ch04-03 に追加 |
  | 変数が値そのものを持つこと、ムーブでコピーされるのはスタック上の部分だけであること | ch04-04 に追加 |
  | 参照の実体がアドレスであること、スライスがアドレスと長さの組であること | ch05-01・ch05-05・ch05-06 に追加 |
  | 関数から戻るとローカル変数がスタックフレームごと消えること | ch05-04 に追加 |
  | Vec の容量と再確保 | ch08-01 に追加 |
  | 単相化 | ch12-01 に追加 |
  | 型の大きさがコンパイル時に決まっている必要があること | ch17-01 に追加 |
  | OS のスレッド、データ競合 | ch20-01「スレッドとデータ競合」を新設（動画のみのレッスン） |
  | デッドロック | ch20-06 に追加 |
  | 未定義動作 | ch23-03 に追加 |

- 次の細部は Claude が決めた。
  - 新設した 2 つのレッスンは章の最初に置き、それより後ろのレッスンの ID を 1 つずつ後ろにずらした（ch04-01〜ch04-05 を ch04-02〜ch04-06 に、ch20-01〜ch20-09 を ch20-02〜ch20-10 に）。理由: レッスン ID の番号を学習順に合わせておく。教材もアプリもまだなく、付け直しは仕様書の中だけで済む。
  - デバッグビルドとリリースビルドでオーバーフローの挙動が違うことと、`size_of`・アライメントは、優先度が低いとして入れなかった。入れるかどうかを、ユーザーには確かめていない。

## 検討した他の案

- 案: レッスンを増やさず、すべてを既存のレッスンの「主に扱う内容」に書き足す（Claude の最初の提案）
  - 採用しなかった理由: この案は、概念だけのレッスンでは演習が作りにくいことを主な理由にしていた。動画のみのレッスンを設けることにしたので（[ADR 0119](0119-video-only-lessons-for-background-knowledge.md)）、この理由がなくなった。メモリの仕組みを「スコープと値の破棄」に足すと、1 つのレッスンの内容が重くなる
- 案: 新設したレッスンに、後ろのレッスンの ID をずらさずに済む ID を付ける
  - 採用しなかった理由: ID の番号が学習順と合わなくなる。いまなら付け直しは仕様書の中だけで済む

## 影響

- ADR 0002 は置き換えない。「一般的なプログラミングの概念は既知とする」の範囲から、周辺知識を除いたことになる。
- 網羅の目安は TRPL のままである（ADR 0077）。周辺知識だけは、TRPL を超えて扱う。
- カリキュラムは 23 章・167 レッスン（うち章末復習レッスン 23、動画のみのレッスン 2）になった。
- ch04 と ch20 のレッスン ID が変わった。この ADR より前の ADR と技術検証の結果の本文に出る「4-3 所有権のムーブ」は、いまの ch04-04 である。
- 既存のレッスンに足した内容の分だけ、そのレッスンの動画が長くなる。
