## 背景

教材チェックツールは CI でも実行する。描画のチェックでは、シーンごとに、最初のフレーム、各文の開始位置のフレーム、最後のフレームを描画する（[教材チェックツール](../spec/content-guidelines/check-tool.md)）。CI の描画のチェックで、毎回すべてのレッスンを描画するか、変更したレッスンだけを描画するかは決まっていなかった。

Issue #7 の技術検証で、描画のチェックを macOS と GitHub Actions の ubuntu-latest で試した（[動画の描画チェックを CI で実行できるかの技術検証](../verification/issue-7-render-check-in-ci.md)）。

- 8 シーン・40 文の合成のレッスンで、1 本あたり macOS で約 20 秒、ubuntu-latest の runner（2 コア）で約 22〜28 秒だった。
- 見つかるのは、描画したフレームで実行された処理のエラーだけだった。ほかのフレームだけで起きるエラーは、そのフレームを描画しないと見つからなかった。

Claude は、毎回すべてのレッスンを描画することを推奨した。ユーザーは、「このあたりの技術的な話は私はあまく詳しくないのであなたの推奨でお願いします。理由もあなたが書いてください。」と示し、判断と理由を Claude に任せた。以下の理由は Claude が書いた。

## 決定

- CI の描画のチェックでは、毎回すべてのレッスンを描画する（[教材チェックツール](../spec/content-guidelines/check-tool.md)）。
  - 理由: レッスンの動画は、共通部品（`src/video/`）と動画のデザインシステムを使う。これらを変えると、変えていないレッスンの描画が壊れることがある。変更したレッスンだけを描画すると、それを見つけられない。1 本あたり約 20〜30 秒なら、すべてのレッスンを描画しても許容できる見込みである。
- 描画のチェックで見つかるのは、描画したフレームで実行された処理のエラーだけである、と仕様に書く。
  - 理由: 検証で確かめた。ほかのフレームだけで起きる誤りは、レビューのチェックリストの「再生位置を途中に移しても、その位置の絵が正しく表示される」で見つける（[教材レビューのチェックリスト](../spec/content-guidelines/review-checklist.md)）。
- 描画以外のチェック項目を、CI でどの範囲のレッスンに行うかは、この判断の対象にしない。

## 検討した他の案

- 案: CI で、変更したレッスンだけを描画する
  - 採用しなかった理由: 共通部品と動画のデザインシステムを変えたときの壊れを見つけられない

## 影響

- 所要時間は、合成のレッスンで測った値である。実際の教材で、すべてのレッスンの描画に時間がかかりすぎると分かったら、描画する範囲を見直す（新しい ADR にする）。
- レッスンが増えるほど、CI の時間が延びる。1 本約 25 秒で数十本なら、並列にしなければ 10〜20 分程度になる。
