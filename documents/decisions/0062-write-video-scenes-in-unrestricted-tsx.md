## 背景

スライドは、使える部品を決めた HTML で書いていた（0005）。0005 は「制限のない HTML」を、デザインの統一・ダークモード対応・セキュリティを作者の注意に頼ることになるとして採用しなかった。
試作では、シーンをレッスンごとに制限のない React（TSX）で手書きした。動画のシーンをどの形式で書くかと、0005 の 3 つの問題にどう対処するかを決める必要があった。

## 決定

- 動画のシーンは、制限のない React（TSX）で書く（`content-format.md`「シーン」）。教材用の共通部品を用意するが、よりわかりやすい表現のために、レッスンごとに専用の部品を作ってよい。
- 最低限の lint として、色の直接指定（動画のデザインシステムのトークン以外）と、Tauri の API・ネットワーク・ファイルへのアクセスを禁じる。教材チェックツールでエラーにする（`content-format.md`「禁止事項」、`content-guidelines.md`「教材チェックツール」）。lint では、部品の作り方や動きは制限しない。
- 0005 の 3 つの問題は、動画では次のように扱う。
  - ダークモード対応: 色の直接指定を禁じて、ライト／ダークと章カラーへの追従を守る。
  - セキュリティ: Tauri の API・ネットワーク・ファイルへのアクセスを禁じて、アプリの権限を守る。
  - デザインの統一: lint では禁じない（「影響」を参照）。

## 検討した他の案

- 案: 台本・合図・画面に出すコードは JSON にし、絵は「教材用の部品だけを import できる TSX」として lint で検査する
  - 採用しなかった理由: 用意された共通部品だけしか使ってはいけないというのは、より良い表現を潰してしまう
- 案: 絵もすべて宣言的なデータにして、アプリが解釈する
  - 採用しなかった理由: 上の案と同じ
- 案: lint では外部アクセスだけを禁じる
  - 採用しなかった理由: ライト／ダークと章カラーへの追従を守るため、色の直接指定も禁じる
- 案: lint を定めない
  - 採用しなかった理由: ライト／ダークと章カラーへの追従と、アプリの権限を守るため、最低限の lint を置く

## 影響

- デザインの統一は lint では守られない。共通部品、動画のデザインシステム（0075）、教材のレビューに頼ることになる。
- 新しい表現が必要になったとき、仕様を変えずに、レッスン専用の部品として作れる。
- 動画のコードはフロントエンドのビルドに含まれ、実行時に外部から読み込まない（`architecture.md`「役割分担」、`non-functional.md`「アプリ自体」）。スライドの HTML を表示前にサニタイズする処理はなくなる。
- 共通部品（`src/video/`）と lint を用意する必要がある。
- lint の外にも、シーンの書き方の決まりがある。現在のフレームだけから絵を決める、最初のシーン（表紙）に `LessonTitle` を出す、画面に出すコードを台本の `code_blocks` に書いて `CodeBlock` で表示する、などである（`content-format.md`「シーン」「コードの表示」）。これらは、描画のチェックなどの教材チェックツールの項目とレビューで確かめる（`content-guidelines.md`「教材チェックツール」「レビューのチェックリスト」）。
