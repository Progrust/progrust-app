## 背景

実行中は、コンソールの入力欄から学習者のプログラムの標準入力に 1 行ずつ送る（[ADR 0013](0013-interactive-stdin.md)）。演習画面は、入力欄を、`main` の実行でプログラムが動いている間だけ有効にする。ビルド中に `send_stdin` を呼ぶと `invalid_state` になる（[実行のコマンドとイベント](../spec/architecture/commands/run.md)「send_stdin」）。

しかし、プログラムが起動したことをフロントエンドに知らせるイベントや戻り値が、仕様に無かった（Issue #207）。ビルドの出力は、ビルドが終わってから送る（[ADR 0139](0139-send-build-output-after-build-ends.md)）。ビルドが警告なしで成功し、プログラムが何も出力していない間は、フロントエンドは、ビルド中とプログラムの実行中を区別できなかった。演習画面の状態の実装（`src/exercise/exerciseState.ts`）は、暫定で「最初の `run_output` が届いたら、プログラムの実行中に移る」としていた。この扱いでは、プロンプトを出さずに入力を待つプログラムで、入力欄が無効のままになり、学習者が入力できない。

Claude が決めた。以下の理由は Claude が書いた。

## 決定

- 新しいイベント `run_started`（項目は `request_id`）を、`run_code` の `mode` が `main` の実行で、学習者のプログラムを起動したときに 1 回送る。演習画面は、受け取ったらプログラムの実行中に移り、入力欄を有効にする（[実行のコマンドとイベント](../spec/architecture/commands/run.md)「イベント」、[コードの実行（run）](../spec/exercise-runner/run.md)「対話的な標準入力」）。
  - 理由: 起動したかどうかを知っているのは、プロセスを起動するバックエンドだけである。出力の有無に頼らずに、起動したときに合図を送れば、何も出力しないプログラムにも入力できる。
- バックエンドは、`send_stdin`・`close_stdin` を受け付けるようにしてから `run_started` を送る。
  - 理由: 受け取ってすぐに `send_stdin` を呼んでも、`invalid_state` にならないようにする。
- 学習者のプログラムの出力の `run_output` と `run_started` の前後は決めない。ビルドの出力の `run_output` より後、`run_finished` より前であることだけを決める。
  - 理由: プログラムの出力は、起動した直後から別のスレッドで受け取って送る（[コードの実行（run）](../spec/exercise-runner/run.md)「出力の送り方」）。前後を保つには、出力を送るスレッドと合図を送るスレッドを待ち合わせる仕組みが要る。演習画面は、出力をどちらの段階で受け取っても同じように表示するので、前後を保たなくても困らない。
- テスト実行と提出では送らない。プログラムを起動しなかったとき（ビルドの失敗、`crates_unavailable`、起動する前に止めたとき、アプリの側の失敗）も送らない。起動した後に止める指示が来ていたときは、送る。
  - 理由: テスト実行は標準入力を起動した直後に閉じ、入力欄を表示しない（[コードの実行（run）](../spec/exercise-runner/run.md)「テスト実行」）。提出は標準入力を受け付けない。入力欄を有効にする必要が無い。起動した後は、止めるのと送るのとが重なっても、続けて `run_finished` が届き、入力欄はすぐに無効に戻る。
- 演習画面の、最初の `run_output` でプログラムの実行中に移る暫定の扱いは、無くす。

## 検討した他の案

- 案: いまの暫定の扱いのまま、最初の `run_output` が届いたらプログラムの実行中に移る
  - 採用しなかった理由: プロンプトを出さずに入力を待つプログラムで、入力欄が無効のままになる。ビルドの警告が届いたときは、プログラムを起動する前に、プログラムの実行中に移ってしまう
- 案: `run_code` の戻り値で、プログラムを起動したことを知らせる
  - 採用しなかった理由: `run_code` は、実行を始めたら返し、経過と結果はイベントで知らせる（[ADR 0147](0147-define-command-and-event-payloads-in-architecture.md)）。起動まで返さないと、ビルドの間、コマンドの戻りを待たせることになる
- 案: プログラムを起動したときに、`run_output` に目印の断片（新しい `stream` の値など）を入れて送る
  - 採用しなかった理由: `run_output` は、コンソールに表示する出力を運ぶ。表示しない合図を混ぜると、出力を扱う側がすべて目印を除く必要がある
- 案: 入力欄を実行の間はずっと有効にし、ビルド中に `send_stdin` が `invalid_state` になったら、少し待って送り直す
  - 採用しなかった理由: ビルド中に入力した行が、いつプログラムに届くか学習者に分からない。ビルドが失敗したときに、入力した行の行き場が無い

## 影響

- 演習画面は、`run_started` を受け取るまで入力欄を無効にし、受け取ったら有効にする。何も出力しないまま入力を待つプログラムにも入力できる。
- イベントが 1 つ増え、バックエンドのイベントの送り先（`RunEvents`）にも、送る操作が 1 つ増える。
- `run_started` より前に、プログラムの出力が届くことがある。そのときは、入力欄はまだ無効のまま、出力だけが表示される。
