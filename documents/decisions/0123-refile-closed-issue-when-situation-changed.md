## 背景

AI エージェントは、起票する前に、閉じた Issue も含めて同じ問題の Issue を検索し、閉じた Issue があれば起票しないことにしていた（[ADR 0088](0088-agents-file-found-problems-as-issues.md)）。例外は、直したと書かれた問題がまた起きているときだけだった。ADR 0088 は、この理由を「閉じた Issue を検索から外すと、ユーザーが対応しないと決めて閉じた問題が、また起票される」としていた。

ユーザーの求めで、Claude は、開いている `AI起票` の Issue を、対応する時期で3つに分けた。そのとき、「やらなくてもよい課題」とした2件（#39、#42）について、閉じた Issue と同じ問題は AI エージェントが今後起票しないことと、#39 は一般公開するときに、#42 は演習のビルドが遅いと感じたときに、また問題になりうることを伝えた。

ユーザーは、2件を閉じるよう求めたうえで、次のように求めた。

- 「運用ルールの「閉じた Issue と同じ問題は、AI エージェントが今後起票しない」というのは、そのときは本当に問題になっている可能性があるのに見逃してしまう危険性があるので、変えたいです。いい感じのルールに変えれますか？」

決まりの内容は、ユーザーが Claude に任せた。

## 決定

- 閉じた Issue と同じ問題を見つけたときは、閉じたときから状況が変わっていれば起票し、変わっていなければ起票しない。ADR 0088 の「閉じた Issue があれば起票しない」を、このように変える。変えることはユーザーの求めによる。決まりは [Issue の起票](../conventions/issues.md)「閉じた Issue と同じ問題」「対応しない Issue を閉じるとき」に定める。
- 次の内容は Claude が決めた。
  - 状況が変わったかどうかは、閉じた Issue の本文とコメントを読み、いま見ている事実と比べて決める。調査はしない。理由: 起票の手間を小さくするという ADR 0088 の方針を保つ。
  - 状況が変わったとするのは、コメントに書かれた「また問題になる条件」が起きているとき、閉じた理由の前提が成り立たなくなっているとき、起きるかもしれないとされていた問題が実際に起きているか影響が大きくなっているとき、直したと書かれた問題がまた起きているときとする。理由: どれも、ユーザーが閉じると決めたときには無かった事実で、ユーザーの判断が変わりうる。
  - 状況が変わっていなければ、起票しない。閉じた Issue の元になった文書の記述を読み直しただけでは、状況が変わったとしない。理由: 元になった記述（技術検証の結果の「残った事項」など）は文書に残る。それを読むたびに起票すると、ユーザーが対応しないと決めて閉じた問題が、また起票される（ADR 0088 の理由）。
  - 状況が変わったかどうかを迷ったら、起票する。理由: ADR 0088 の「迷ったら起票する」と同じにする。要らない起票はユーザーが閉じれば済むが、見逃した問題は誰にも伝わらない。
  - 起票するときは、新しい Issue にし、閉じた Issue の番号と、閉じたときから変わったことを本文に書く。閉じた Issue は開き直さない。理由: 新しい Issue には `AI起票` と `未判断` が付き、ユーザーが判断する Issue の一覧に出る。閉じた Issue を開き直すと、ユーザーがした判断を AI エージェントが変えることになる。
  - AI エージェントがユーザーに頼まれて、対応しない Issue を閉じるときは、`not planned` で閉じ、閉じた理由と、また問題になる条件を、Issue のコメントに書く。理由: 後で同じ問題を見つけたときに、状況が変わったかどうかを比べるものが要る。

## 検討した他の案

- 案: 閉じた Issue があれば起票しない（それまでの決まり）
  - 採用しなかった理由: ユーザーが挙げた理由（「背景」を参照）。そのときは本当に問題になっているのに、見逃すおそれがある。
- 案: 閉じた Issue を検索から外し、同じ問題でも常に起票する
  - 採用しなかった理由: ユーザーが対応しないと決めて閉じた問題が、状況が変わっていなくても、また起票される（ADR 0088 の理由）。
- 案: 新しい Issue を起票せず、閉じた Issue を開き直すか、閉じた Issue にコメントする
  - 採用しなかった理由: 開き直すと、ユーザーがした判断を AI エージェントが変えることになる。閉じた Issue へのコメントは、`未判断` の一覧に出ないので、ユーザーが気づきにくい。

## 影響

- 閉じた Issue と同じ問題でも、状況が変わっていれば、また起票される。ユーザーは、その Issue を改めて判断する。
- 状況が変わったかどうかは、AI エージェントが読んで決めるので、決め方に幅がある。迷ったら起票するので、要らない起票が混じることがある。
- 閉じた理由が書かれていない Issue（ユーザーが GitHub の画面で閉じたものなど）は、比べるものが本文だけになる。
- Issue を閉じるときに、コメントを書く手間が増える。
