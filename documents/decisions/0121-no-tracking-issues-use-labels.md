- 日付: 2026-11-21
- 関連仕様: [Issue の起票](../conventions/issues.md)「Issue の一覧」
- 置き換え: なし

## 背景

技術検証の Issue（#1〜#22）は、ラベル `技術検証` を付けたうえで、一覧のための Issue #23 にもチェックリストで並べていた。#23 には、`確認事項` の Issue や、一般公開をする場合に扱う Issue も並べていた。技術検証の Issue をすべて閉じたときに、#23 も閉じた。

ユーザーは次のように求めた。

- 「今後#23のようなIssueの一覧のためのIssueはつくらないようなルールを追加したいです。ラベルと一覧で2重管理になってしまうので、管理しやすいラベルで統一します。」

## 決定

- Issue の一覧のための Issue は作らない。Issue のまとまりはラベルで表し、一覧はラベルで絞り込んで見る。決まりは [Issue の起票](../conventions/issues.md)「Issue の一覧」に定める。ユーザーの求めによる。
- 次の細部は Claude が決めた。
  - 決まりを、AI エージェントの Issue の起票の決まり（ADR 0088）に加える。ユーザーに頼まれて、技術検証などの Issue をまとめて起票するときも含める。理由: Issue を起票するのは AI エージェントで、`Convention` の範囲（[frontmatter の書き方](../conventions/frontmatter.md)「type の語彙」）を変えずに済む。

## 検討した他の案

- 案: 一覧のための Issue を残し、ラベルと併用する
  - 採用しなかった理由: ユーザーが挙げた理由（「背景」を参照）。一覧とラベルの2重管理になる。

## 影響

- Issue の一覧は、ラベルで絞り込んだ `gh issue list` や GitHub の画面で見る。どの Issue を閉じたかと、そのつどの判断は、各 Issue のコメントに残す。
- 一覧の Issue に書いていた、Issue をまたぐ説明（項目をどの順で進めるか、項目をどの段階で扱うかなど）を置く場所がなくなる。そのような説明は、各 Issue の本文か、`documents/` の仕様・ADR に書く。
