## 背景

画面と動画の見た目の値（色・書体・余白・部品）は、デザインシステム「Progrust」「Progrust Video」を唯一の定義とし、仕様書には書かないと決めている（[ADR 0044](0044-design-system-as-source-of-visuals.md)、[ADR 0075](0075-video-design-system-progrust-video.md)）。動画には、アプリが動画のデザインシステムの CSS を適用する（[動画を構成するファイル](../spec/content-format/video/structure.md)）。

デザインシステムは claude.ai のアーティファクトで、リポジトリの外にある。アプリはオフラインで動き、ビルドに含めたファイルだけを読み込む（[ADR 0111](0111-bundle-monaco-and-set-csp.md)）ので、アーティファクトを実行時に読むことはできない。デザインシステムの CSS を、リポジトリのどこに置き、デザインシステムを変えたときにどう合わせるかが、仕様に無かった。

実装を始める前の調査（2026-11-22）で、デザインシステム「Progrust」の `components/bundle.css` の先頭に、書体を Google Fonts から読み込む `@import` があることを確かめた。書体のファイルはアプリに同梱すると決めている（[ADR 0116](0116-bundle-upstream-variable-fonts-unmodified.md)）。

Claude は、デザインシステムの取り込み方を決めることをユーザーに提案し、ユーザーは提案のとおりでよいと示した。以下の決定と理由は、Claude の判断である。

## 決定

- デザインシステムの CSS（`tokens.css`、`components/bundle.css`）とアイコンを、リポジトリに写して使う（[画面の見た目とテーマ](../spec/screens/appearance.md)「デザインシステムの写し」、[リポジトリ構成](../spec/architecture/repository.md)）。
  - 理由: アプリは、ビルドに含めたファイルだけを読み込む。
- 写しは編集しない。値や部品を変えるときは、デザインシステムを変えてから、写しを取り直す。
  - 理由: 値の定義をデザインシステムの 1 か所に保つ（ADR 0044）。写しを直すと、デザインシステムと食い違い、次に写しを取り直したときに変更が消える。
- 例外として、書体を外部から読み込む `@import` の行は、写しから取り除く。
  - 理由: アプリは外部のサイトから読み込まない（ADR 0111）。書体は同梱したファイルから読む（ADR 0116）。
- 写しを取ったときのデザインシステムの版と日付を、写しと同じディレクトリに記録する。
  - 理由: 写しがデザインシステムのどの時点のものかが分かり、取り直しが要るかどうかを確かめられる。
- アプリのための CSS は、写しとは別のファイルに書く。
  - 理由: 写しを取り直しても、アプリのための CSS が消えない。
- デザインシステムの README は写さない。
  - 理由: 同じ説明を 2 か所に持つと、食い違う。

## 検討した他の案

- 案: デザインシステムの値をもとに、アプリのテーマ CSS を手で書き起こす
  - 採用しなかった理由: 値を書き写す手間がかかり、書き写しの誤りと、デザインシステムを変えたときの直し漏れが起きる。デザインシステムは CSS のファイルを持っていて、そのまま使える
- 案: 写しをリポジトリで編集し、リポジトリの写しを正とする
  - 採用しなかった理由: 値はデザインシステムを唯一の定義とすると決めている（ADR 0044）。ユーザーが見て確かめる場所も、デザインシステムである

## 影響

- デザインシステムを変えたら、写しを取り直す作業が要る。取り直しを忘れると、アプリの見た目がデザインシステムと食い違う。
- 写しを取り直すたびに、`@import` の行を取り除く作業が要る。
- 部品の使い方を確かめるには、リポジトリの外のデザインシステムを読む。
