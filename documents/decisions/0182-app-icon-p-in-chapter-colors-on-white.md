## 背景

Issue #72 は、次のことを挙げていた。本番ビルドの `.app` と開発時の起動のウィンドウには、アプリのアイコン（Dock と Finder に表示する絵）が要る。仕様には、アイコンの絵柄も、元になる画像の置き場所も定められていない。デザインシステム「Progrust」の `assets/Icons/` にあるのは、画面の中で使うアイコンである。アイコンが決まるまで、Tauri が用意する仮のアイコンを使っていた。

2026-11-23、ユーザーは、Issue #72 について、アプリに合いそうなアイコンの案をいくつか作って比べられるようにすることを、Claude に頼んだ。Claude は、次の 5 つの案を描き、Dock に並べたときの見え方、大きさごと（128〜16px）の見え方、地の色を変えた場合を比べるページを作った。

- A「P と再生」: 墨色の地に白い「P」。字の中の空きを再生の三角にした
- B「再生とカーソル」: 白い地に、再生の三角とカーソル（端末の「>_」の「>」を再生の三角にした）
- C「章カラーの P」: 白い地に、線を第1〜4章の章カラーで塗り分けた「P」
- D「P と進み具合」: 墨色の地に白い「P」と、章カラーで区切った進み具合の棒
- E「カニ」: 淡い橙の地に、この案のために描いたカニ

Claude は、C の絵柄を墨色の地にしたものを勧めた。ユーザーは「C の 白い地が良さそうですが、茶色の部分を別の章の色に変えられますか？」と尋ねた。茶色に見えていたのは、第3章の章カラーのライトテーマの値である。Claude は、次の 3 つを描き、C2 を勧めた。

- C1: 第3章の場所を、第5章の紫にした（青・緑・紫・マゼンタ）
- C2: 第3章を飛ばし、章の順に並べた（青・緑・マゼンタ・紫）
- C3: 第3章のまま、ダークテーマの値（明るい橙）にした（青・緑・橙・マゼンタ）

ユーザーが墨色の地の版も求めたので、Claude は、墨色の地の 3 つ（橙のまま、C1、C2）も描いた。ユーザーは「C3 の白い地で進めてください。理由は言語化できないですが、一番しっくりきたからです。」と示した。

同じ日、Claude は、作者の Mac（macOS 27.2.1）で次のことを確かめた。

- Tauri CLI（`tauri icon`）は、SVG の元の絵から、`icon.icns` と PNG を作れる。
- 1024 × 1024 の中央の 824 × 824 の角丸四角に地を描いた絵から `icon.icns` を作り、試験用に作った `.app` に入れて、macOS がその `.app` のアイコンとして返す絵（`NSWorkspace` の `icon(forFile:)`）を画像に書き出した。絵は、システムの角丸の形に切り抜かれ、同じ方法で書き出した macOS の標準のアプリ（計算機）と同じ大きさと形で表示された。別の台の上に小さく載せられることはなかった。
- 本番ビルド（`npm run build`）の `.app` には、この絵から作った `icon.icns` が入った。この `.app` でも同じ方法で 512px・64px・16px を書き出し、同じ形で表示されることと、16px でも「P」の形が読めることを確かめた。

## 決定

- アプリのアイコンを、C3 の白い地の絵にする（[アプリのアイコン](../spec/screens/app-icon.md)「絵柄」）。
  - 理由: ユーザーが選んだ。理由は、ユーザーの言葉で「理由は言語化できないですが、一番しっくりきたからです」である（好み）。
- 「P」は、比べるページで描いた図形のまま使い、書体（Murecho）の字形に合わせない。位置だけは、「P」が上下の中央に来るように、1024 の絵の中で 10 だけ上げた（Claude の判断）。
  - 理由: ユーザーが選んだのは、この図形で描いた絵である。字形に合わせると、選んだ絵から形が変わる。比べるページの絵は、「P」が中央より少し下にあった。
- 色の値は、元の絵のファイルに直接書き、デザインシステムのトークンに連動させない（Claude の判断）。
  - 理由: アイコンの色は、ユーザーが見た目で選んだものである。トークンの値は、画面での読みやすさのために変えることがある。そのときに、アイコンの色まで変わらないようにする。
  - 画面の見た目の値はデザインシステムを唯一の定義とする（[ADR 0044](0044-design-system-as-source-of-visuals.md)）が、アプリのアイコンは画面の見た目ではないので、この決まりの対象にしない。仕様には、値ではなく、値を取った元のトークンを書く。
- 元の絵は、1024 × 1024 の中央の 824 × 824 の角丸四角に地を描き、影を描かない（Claude の判断。[アプリのアイコン](../spec/screens/app-icon.md)「形と余白」）。
  - 理由: 「背景」で確かめたとおり、この形で、macOS が標準のアプリと同じ大きさと形で表示する。
- 元の絵を `src-tauri/app-icon.svg` に置き、アプリに入れるファイルを Tauri CLI で作る。`src-tauri/icons/` には、いまあるファイルと同じ 5 つだけを置く（Claude の判断。[アプリのアイコン](../spec/screens/app-icon.md)「ファイル」「変える手順」）。
  - 理由: Tauri CLI は、既に依存に入っていて、SVG から `icon.icns` を作れる。アプリは macOS だけを対象にしていて、Tauri CLI が一緒に作る Windows・iOS・Android のためのファイルは使わない。
- 作り直しを、npm のコマンド `npm run icon` にする（Claude の判断。[開発環境と依存の版](../spec/architecture/development-environment.md)「開発で使うコマンド」）。
  - 理由: 開発で使うコマンドは、`package.json` の npm のスクリプトにすると定めてある。作ることと、使うファイルだけを写すことを、1 つのコマンドにまとめられる。
- ヘッダーのロゴ（デザインシステム「Progrust」の README「ロゴ」）は、この判断では変えない。アプリのアイコンの絵を画面の中で使うかどうかは、決めていない。

## 検討した他の案

- 案: A「P と再生」、B「再生とカーソル」、D「P と進み具合」、E「カニ」
  - 採用しなかった理由: ユーザーが C を選んだ（好み）
- 案: C の、第3章をライトテーマの値のままにする（最初の C）、C1、C2
  - 採用しなかった理由: ユーザーが C3 を選んだ（好み）。最初の C は、ユーザーが、茶色に見える部分を別の色に変えることを求めた
- 案: C の絵柄を、墨色の地にする
  - 採用しなかった理由: ユーザーが白い地を選んだ（好み）
- 案: 「P」を、ヘッダーのロゴの書体（Murecho）の字形に合わせる
  - 採用しなかった理由: ユーザーが選んだ絵から、形が変わる
- 案: アイコンの色を、デザインシステムのトークンに連動させる（トークンを変えたら、アイコンも作り直す）
  - 採用しなかった理由: 画面のためにトークンを変えたときに、ユーザーが見た目で選んだアイコンの色まで変わる
- 案: 元の絵を、デザインシステム「Progrust」のディレクトリ（`design-system/progrust/assets/`）に置く
  - 採用しなかった理由: このディレクトリは、アーティファクトの `project/` の下と同じ形で置き、アイコンは索引に記録して表示用のアーティファクトへ送る（[デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)）。アプリのアイコンは、画面の部品ではなく、Tauri がバンドルに入れる素材である
- 案: Tauri CLI が作るファイルを、すべて `src-tauri/icons/` に置く
  - 採用しなかった理由: 使わないファイル（Windows・iOS・Android のためのもの）が、リポジトリに増える

## 影響

- Tauri の仮のアイコンが、アプリのアイコンに替わる。
- 白い地なので、明るい背景の上では、地の輪郭が薄く見える。
- アイコンの第3章の色は、ダークテーマの値である。白い地の上で使うが、文字ではないので、文字のコントラストの基準（デザインシステム「Progrust」の README「コントラスト」）の対象にしない。
- アイコンの色は、トークンに連動しない。章カラーを変えてアイコンも合わせたいときは、元の絵を直して作り直す。
- 開発時の起動（`npm run dev`）での Dock の表示は、確かめていない。
