## 背景

画面（レッスン一覧、トップページ、動画画面）と動画（共通部品 `useLesson()`）は、章の番号とレッスンの番号（例: `4-4`）を表示する。番号を ID（`ch04-04`）から決めるか、並び順から決めるか、章末復習レッスン（`ch04-review`）の番号をどう表すかは、未決事項として残っていた。章カラーを `chapters.json` に持たせるか、章の順番で決めるかも、未決事項だった。実装計画の M1 で、レッスン一覧と動画画面を作るために決める必要があった。

デザインシステム「Progrust」の README は、章カラーが章の順番で決まる前提で書かれている（第N章に `chapter-((N − 1) mod 12 + 1)`）。レッスン一覧の部品の見本は、第4章の章末復習レッスンを、6 レッスンの後の `4-7` と表している。

## 決定

- 章の番号は `chapters.json` での章の位置、レッスンの番号は「{章の番号}-{章の中での位置}」とする。章末復習レッスンと準備中のレッスンにも、同じ決め方で番号を付ける（[章とレッスンの並びの形式（chapters.json）](../spec/content-format/chapters-json.md)「章とレッスンの番号」）。Claude が決めた。
  - 理由: 章末復習レッスンの ID（`ch04-review`）には数字が無く、ID からは番号を決められない。並び順なら、どのレッスンにも同じ決め方で番号が付き、デザインシステムの見本（`4-7`）とも合う。いまのカリキュラムでは、章とレッスンの ID の数字と並び順の位置は一致している（[章とレッスンの一覧](../spec/curriculum/chapters/index.md)）。
- 章カラーは、章の番号で決める。デザインシステムの README の「第N章」の N を、章の番号とする（[画面の見た目とテーマ](../spec/screens/appearance.md)「デザインシステム」）。`chapters.json` に章カラーを持たせない。Claude が決めた。
  - 理由: デザインシステムが、章の順番で決まる前提で書かれている。`chapters.json` の形式を変えずに済む。

## 検討した他の案

- 案: 番号を ID の数字から決め、章末復習レッスンは「復習」などの別の表し方にする
  - 採用しなかった理由: 章末復習レッスンだけ決め方が変わる。デザインシステムの見本と合わない
- 案: 章カラーを `chapters.json` に持たせる
  - 採用しなかった理由: `chapters.json` の形式が増え、カリキュラムとの照合の対象も増える。章の順番で決めれば足りる

## 影響

- 章やレッスンの並びを変えると、番号と章カラーも変わる。
