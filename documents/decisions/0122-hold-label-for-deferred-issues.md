- 関連仕様: [Issue の起票](../conventions/issues.md)

## 背景

AI エージェントが起票した Issue のラベルは、`AI起票`、`未判断`、種類の4つ（`不具合`・`仕様`・`ドキュメント`・`改善`）の6つだった（[ADR 0088](0088-agents-file-found-problems-as-issues.md)）。ユーザーは、対応すると決めた Issue から `未判断` を外し、対応しない Issue を閉じることにしていた。対応すると決めた Issue のうち、今は対応しないものを分けるラベルは無かった。

ユーザーの求めで、Claude は、開いている `AI起票` の Issue 10件を「実装前に対応するべき課題」「今はやらなくてもよいがいつかやるべき課題」「やらなくてもよい課題」の3つに分け、Issue ごとに理由と対応するきっかけを示した。ユーザーは、2つ目に分けた Issue（#44、#38、#40）について、次のように求めた。

- 「「保留」のラベルを新しく作成して付与してください。また保留の理由といつ対応するかもあなたが記載したとおりの内容でよいので追記しておいてください。」

## 決定

- ラベル `保留` を作り、対応するが今は対応しない Issue に付ける。保留の理由と、対応するきっかけを、Issue に書く。ユーザーの求めによる。ADR 0088 の「ラベルは…6つにする」を、`保留` を加えた7つに変える。決まりは [Issue の起票](../conventions/issues.md)「ラベル」「起票した後」に定める。
- 次の細部は Claude が決めた。
  - `保留` を付ける Issue からは `未判断` を外す。理由: `未判断` は、対応するかどうかをユーザーがまだ決めていないことを示す。保留は、対応すると決めた後の状態である。`未判断` を残すと、`未判断` の一覧に、判断を済ませた Issue が混じる。
  - `保留` を付ける・外すかどうかは、ユーザーが決める。AI エージェントは、自分から付けたり外したりしない。理由: 対応するかどうかと、いつ対応するかは、ユーザーが決める（ADR 0088）。
  - 保留の理由と対応するきっかけは、Issue のコメントに書く。理由: 本文は、起票したときに見た事実を書く場所である。Issue ごとの判断はコメントに残すことにしている（[ADR 0121](0121-no-tracking-issues-use-labels.md)「影響」）。
  - AI エージェントは、作業中に、保留の Issue の対応するきっかけが来たことに気づいたら、その Issue にコメントし、応答でユーザーに伝える。理由: 開いている Issue と同じ問題は起票しないので、何もしないと、きっかけが来たことがユーザーに伝わらない。

## 検討した他の案

- 案: ラベルを作らず、対応すると決めた Issue と同じく `未判断` を外すだけにする（それまでの決まり）
  - 採用しなかった理由: ユーザーがラベルの作成を求めた。
- 案: `保留` を付けた Issue に `未判断` も残す
  - 採用しなかった理由: 「決定」に書いたとおり、`未判断` の一覧に、判断を済ませた Issue が混じる。

## 影響

- 保留の Issue は、`gh issue list --label "保留"` で一覧できる。
- 対応するきっかけが来たかどうかは、ユーザーか、作業中の AI エージェントが気づく必要がある。自動では知らされない。
- 保留を解いて対応するときは、ユーザーが `保留` を外す。
