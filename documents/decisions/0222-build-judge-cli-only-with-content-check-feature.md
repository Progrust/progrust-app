## 背景

[ADR 0208](0208-content-check-runs-judge-via-backend-cli.md) で、教材チェックツールの「模範解答」「初期コード」を、バックエンドのクレートの `src-tauri/src/bin/` に置いた判定だけを行うプログラムで判定すると決めた。実装計画の M2 で、このプログラムと検査を作るときに、次のことを決める必要があった。

- `src/bin/` に実行ファイルを足して `npm run build`（`tauri build`）を実行すると、Tauri は、クレートの実行ファイルをすべて `Progrust.app/Contents/MacOS/` に入れた（試して確かめた）。開発用のプログラムが、配布するアプリに入る。
- 判定結果のほかに、何を返すか。`compile_error` のときに理由が分からないと、教材の作者が直せない。
- プログラムが判定できなかったとき（教材を読めない、cargo を起動できない、など）の扱い。
- 許可クレートを使う演習（`dependencies` が空でない演習）は、判定に作業領域の初回準備（ネットワークが要る）が要る。ADR 0208 で、検査のしかたは初回準備を作るときに決めるとした。それまでの扱いを決める必要があった。

## 決定

Claude が決めた（[教材チェックツール](../spec/content-guidelines/check-tool.md)）。

- 判定だけを行うプログラム（`progrust-judge`）は、Cargo の feature `content-check` を付けたときだけビルドする（`Cargo.toml` の `[[bin]]` の `required-features`）。`npm test` の `cargo test`、`npm run lint` の Clippy、教材チェックツールの `cargo run` は、この feature を付けて実行する。
  - 理由: `tauri build` は feature を付けずにビルドするので、このプログラムをビルドせず、`.app` にも入れない（試して確かめた）。テストと lint は、プログラムも対象にする。
- プログラムが返す判定結果は、提出の判定結果（[コードの提出（submit）](../spec/exercise-runner/submit.md)「判定結果」）と同じ項目に、ビルドの出力（ANSI エスケープを除いたもの）を足したものにする。教材チェックツールは、`compile_error` のエラーの文に、ビルドの出力の先頭を入れる。
  - 理由: 模範解答がコンパイルできないとき、理由を見ずに直せるとは限らない。
- プログラムが判定結果を返さなかったときは、その検査（「模範解答」か「初期コード」）のエラーにする。
  - 理由: 判定できなかったことを「`passed` でない」と扱うと、「初期コード」の検査が、判定せずに通ってしまう。
- 許可クレートを使う演習は、「模範解答」「初期コード」を検査しない。検査しないことは、結果に表示しない。プログラムも、許可クレートを使う演習を渡されたら、判定せずに失敗する。
  - 理由: 初回準備を作るまでは、判定できない。いまの `content/` には、許可クレートを使う演習が無い。警告の項目は仕様で決めた 3 つで、検査しなかったことを知らせる表示を新しく作るほどの理由が、まだ無い。

## 検討した他の案

- 案: プログラムを `.app` に入れたままにする
  - 採用しなかった理由: 配布するアプリに、学習者が使わない開発用のプログラムが入る
- 案: プログラムを `src/bin/` ではなく、例（`[[example]]`）にする
  - 採用しなかった理由: ADR 0208 の置き場所と食い違う。`cargo test` のテストから、実行ファイルの場所を Cargo の仕組み（`CARGO_BIN_EXE_{名前}`）で得られない
- 案: 許可クレートを使う演習を、エラーにする
  - 採用しなかった理由: 初回準備を作るまで、教材に許可クレートを使う演習を足せなくなる
- 案: 許可クレートを使う演習を検査しなかったことを、警告として表示する
  - 採用しなかった理由: 警告は教材の内容の問題を知らせるもので、検査しなかったことは教材の問題ではない。いまは該当する演習が無い

## 影響

- `cargo build` や `cargo test` を、feature を付けずに実行すると、このプログラムとそのテスト（`src-tauri/tests/judge_cli.rs`）はビルドされない。プログラムのテストは、`npm test` で実行する。
- feature を付けたビルドと付けないビルドでは、ライブラリのビルドの結果を使い回せない。`npm run dev` の後に `npm test` を実行すると、ライブラリをビルドし直す。
- 許可クレートを使う演習を足すときは、初回準備を作るときに、検査のしかたを決め直す。
