## 背景

実装のループは、始めたときとタスクの切れ目に、`AI起票` の Issue を仕分ける（[ADR 0164](0164-loop-triages-issues-between-tasks.md)）。ユーザーの判断が要る Issue は、ユーザーに尋ねずに `未判断` のまま残す。同じ実行の中では仕分け直さないが、ループを始めるたびに、`未判断` の Issue はまた仕分けられる。

ループの試運転（Issue #77）で、同じ Issue #114 の仕分けが、実行ごとに変わった（Issue #118）。

- 2 回目の実行の仕分けは、#114 を「画面デザインを消すかどうかはデザインの判断で、ユーザーに決めてもらう必要がある」として、`未判断` のまま残した。コメントは書かなかった。
- 数分後の 3 回目の実行の仕分けは、同じ #114 を「直す」に仕分け、ループのタスクにした。ループは PR #116 でマージし、#114 を閉じた。

ユーザーに回すと決めた Issue が、ユーザーが答える前に、別の実行の仕分けで「直す」になり、マージされた。ADR 0164 で、ユーザーの判断が要る Issue を残すのは、ユーザーがスキル `triage-issues` を呼んだときに尋ねるためである。

## 決定

- ループの仕分けで、ユーザーの判断が要るとして `未判断` のまま残す Issue には、1 行目が `ユーザーの判断が要るので、未判断のまま残した（YYYY-MM-DD、Claude の判断）。` のコメントを書き、続きに、ユーザーに決めてほしいことと、その理由を書く。決まりは [実装のループ](../conventions/implementation-loop.md)「Issue の仕分け」に、書き方はスキル `triage-issues` に定める。Claude が決めた。
  - 理由: ループが、前の実行でユーザーに回した Issue を見分けられるようにする。ユーザーも、なぜ残ったのかを、Issue だけを読んで分かる。
- このコメントがあり、`未判断` が付いたままの Issue は、ループでは、次の実行からも仕分けない。スクリプトが、仕分ける Issue を集めるときに外す。Claude が決めた。
  - 理由: 仕分けをする AI の判断は、実行ごとに揺れる。仕分けをする側の判断に任せず、スクリプトで外せば、ユーザーに回した Issue がユーザーより先に処理されることがない。
  - `未判断` が外れた Issue（ユーザーが答えて、対応すると決めたもの）は、コメントが残っていても、これまでどおり仕分ける。対応すると決めた Issue は、直せるようになったかを確かめる対象だからである（[ADR 0133](0133-triage-also-picks-up-accepted-open-issues.md)）。
- ADR 0164 の「ループの仕分けでは、ユーザーに尋ねない。ユーザーの判断が要る Issue は、`未判断` のまま残す」に、コメントを書くことと、次の実行からも仕分けないことを足した。

## 検討した他の案

- 案: ユーザーの判断が要る Issue に、新しいラベル（「判断待ち」など）を付ける。
  - 採用しなかった理由: ラベルを足すと、[Issue の起票](../conventions/issues.md)「ラベル」とスキル `triage-issues` の処理に、付け外しの決まりが要る。コメントなら、いまの「処理した Issue には必ずコメントを書く」の形のままで済み、理由も残る。
- 案: スクリプトでは外さず、仕分けをする側が、前の実行のコメントを読んで、そのまま残す。
  - 採用しなかった理由: #114 で問題になったのは、仕分けをする側の判断が揺れたことである。読んで判断させると、同じことが起こりうる。
- 案: ループでは、`未判断` の Issue を、前の実行で仕分けたものも含めて、一度しか仕分けない（仕分けた記録をリポジトリの外に残す）。
  - 採用しなかった理由: 「直す」でも「ユーザーの判断が要る」でもなく残った Issue は無いので、ユーザーに回した Issue だけを外せば足りる。記録をリポジトリの外に置くと、ループを動かす場所が変わったときに失われる。

## 影響

- ループがユーザーに回した Issue は、ユーザーがスキル `triage-issues` で答えるまで、`未判断` のまま残る。状況が変わって問題が無くなっていても、ループは閉じない。
- ループは、仕分ける Issue を集めるときに、Issue のコメントも読む（`gh issue list --json comments`）。
- この決定の前にループが残した Issue には、コメントが無いので、これまでどおり、次の実行で仕分けられる。
