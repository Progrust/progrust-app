## 背景

それまでの仕様は、macOS（13 以降、Apple Silicon と Intel）と Windows（10・11）を対応環境とし、GitHub Releases で配布することを定めていた。実装前の技術検証（Issue #23）も、各項目を macOS と Windows の両方で確かめることにしていた。

技術検証を進めるときに、ユーザーは「2つのOSでやると範囲が膨れて開発に時間もかかってしまうので、まずはmacosで集中してやりたいです。」と示し、検証は macOS だけで行った。この方針は仕様にも ADR にも書かれていなかった（Issue #31）。macOS 13 の実機が無いために確かめられず、開いたままになった検証の項目もあった。

ユーザーは、対応する OS とバージョン、公開範囲を、次のように変えると示した。

- アプリ完成まで: 「このmacのバージョンで動くこと。このmac以外のバージョンやwindowsなど他のOSは、アプリ開発時は考慮しない。アプリを外部に一般公開しない前提で進める。」
- 一般公開をする場合: 「公開するうえで必要な検証やライセンスの確認、署名などを考える。」
- 一般公開後: 「macの他のバージョンやwindowsなどについて考える。」

理由は次のとおり示した。「このアプリは私が実際にRustを勉強するために作っているものなので、私が使えれば十分。私が実際に使ってみて公開する価値があると思えれば公開したいという願望はあれど、これが目的ではない。アプリ開発では他のバージョンやOSの確認、公開する際の懸念のために手を止めたくない。私が早く使えるようにアプリの完成を優先させたい。」

## 決定

- アプリの完成までは、対応環境を作者が使っている Mac だけとする。macOS の他のバージョン、Intel の Mac、Windows などの他の OS は、開発で考慮しない（[対応環境](../spec/non-functional/environments.md)）。
- アプリの完成までは、一般公開しない前提で開発する（[公開範囲と配布](../spec/non-functional/distribution.md)）。配布と更新の扱いは [ADR 0091](0091-no-distribution-or-auto-update-until-publication.md) に分けて記録する。
- 一般公開するかどうかは、アプリの完成後に、作者が使ってみてから決める。公開するうえで必要な検証、ライセンスの確認、署名は、一般公開をする場合に決める。macOS の他のバージョンと他の OS への対応は、一般公開した後に決める。どちらも未決事項として残す（[非機能要件の未決事項](../spec/non-functional/open-questions.md)）。
- 学習者の Claude Code をアプリから `claude -p` で呼び出すことが Anthropic の利用規約に照らして問題ないかの確認（Issue #27）も、一般公開をする場合に決めることに入れる。Claude が「一般公開をする場合に確認」と「完成までに確認する」を示し、ユーザーは前者を選んだ。
- 次の細部は Claude が決めた。
  - 対応バージョンは「作者の Mac に入っているバージョン（現在は 27.2.1）」、アーキテクチャは Apple Silicon と書く。理由: ユーザーが示したのは「このmacのバージョン」で、作者の Mac は macOS 27.2.1 の Apple Silicon（arm64）である。
  - Windows についての記述（外部ツールの探索先、キーボードショートカットの Windows の列、Ctrl を使う表記）は、注記を足さずに仕様から消す。理由: 仕様には現時点の事実を書く。
  - 書体（Murecho、Red Hat Mono）のライセンスの確認を、画面仕様の未決事項から、非機能要件の未決事項の「一般公開をする場合に決めること」に移す。理由: ライセンスの確認を一般公開をする場合にまとめる。同梱する方法は、画面仕様の未決事項に残す。
  - 技術検証の結果の「確かめた OS」に、確かめていない OS を書く決まりをやめ、対応環境と違う環境で確かめたときにそのことを書く決まりにする（[技術検証の結果の書き方](../conventions/verification-reports.md)）。

## 検討した他の案

- 案: macOS（13 以降、Apple Silicon と Intel）と Windows を対応環境にしたまま開発する（それまでの仕様）
  - 採用しなかった理由: 他のバージョンと OS の確認のために開発の手が止まる。作者が使えれば十分で、アプリの完成を優先する。

## 影響

- 実装と検証は、作者の Mac で動くことだけを確かめればよい。
- 作者の Mac 以外の環境で動くことは保証しない。一般公開をする場合と、一般公開した後に、決めることと確かめることが残る。
- 作者の Mac の macOS を更新したら、対応環境の「現在は」のバージョンを直す。
- 採用している ADR の中には、「背景」や「検討した他の案」で macOS と Windows の両方に対応することを理由にしているものがある（0014、0016、0021、0077 など）。それらの判断は変えていない。見直すときは、この ADR の前提を踏まえる。
- 技術検証の Issue（#1〜#22）と結果の文書（`documents/verification/`）の、基準・判定・残った事項から、macOS の他のバージョンと Windows を外した。Windows だけを扱う Issue #17 と、macOS 13 を前提にした Issue #34 は閉じた（ユーザーの選択による）。
