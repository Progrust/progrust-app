## 背景

演習画面のコンソールは、標準出力・標準エラー出力・アプリの知らせ（`run_output` の `system`）・学習者の入力を見分けて表示する（[コードの実行（run）](../spec/exercise-runner/run.md)「対話的な標準入力」の「入力として区別できる色で表示する」）。しかし、それぞれの文字の色は、デザインシステムの Console の README にも、画面デザインにも決まっていなかった。色はデザインシステムを唯一の定義とする（[画面の見た目とテーマ](../spec/screens/appearance.md)「デザインシステム」）。

コンソールの部品の実装（Issue #167）では、色を仮に決めていた。一方、画面デザイン（`design-system/ui-design/Exercise.dc.html`）では、コンパイラの出力（標準エラー出力として届く）の色の付いていない部分を既定の文字の色で、学習者の入力を `ansi-cyan` で描いていて、仮の色と違っていた（Issue #201）。コンソールの文字の色は学習者が出力の種類を見分けるときの見た目なので、ユーザーに尋ねた。

## 決定

- 出力の文字の色を、仮に決めた色のとおり、出力の種類で分ける。標準出力は `ink`、標準エラー出力（ビルドの出力を含む）は `ink-3`、アプリの知らせと区切りの行と「古い出力を省略しました」の行は `muted`、学習者が入力した行は `link` にする。ANSI の色が付いた部分は、どの種類でも ANSI の色にする。色と、使うクラスは、デザインシステムの Console の README（`design-system/progrust/components/Console/README.md`）に書く。
  - 理由: ユーザーの選択による。選択肢として示した理由は、標準エラー出力が標準出力より淡く見え、見分けられることである。学習者の入力の色は、画面デザインの `ansi-cyan` と比べて、改めてユーザーが選んだ。
- 画面デザインの、コンパイラの出力と学習者の入力の色を、この決定に合わせて直す。
  - 理由: 画面デザインとデザインシステムが食い違ったままだと、実装とレビューがどちらに合わせるか迷う。直し方は、ユーザーの選択に合わせただけである。

## 検討した他の案

- 案: 標準エラー出力を、画面デザインに合わせて既定の文字の色（`ink`）にし、標準出力と色で見分けない
  - 採用しなかった理由: ユーザーが、仮に決めた色のままにすることを選んだ
- 案: 学習者が入力した行を、画面デザインにあった `ansi-cyan` にする
  - 採用しなかった理由: ユーザーが `link` を選んだ。選択肢として示した理由は、`ansi-cyan` はコンパイラの診断の help の行にも使われ、入力と見分けにくいことである

## 影響

- デザインシステムの部品の CSS（`components/bundle.css`）に、出力の種類の色のクラス（`.pg-out-stderr`・`.pg-out-system`・`.pg-out-input`）がある。
- コンパイラの出力のうち、ANSI の色が付いていない部分（ソースコードの行など）は、標準出力より淡く表示される。
