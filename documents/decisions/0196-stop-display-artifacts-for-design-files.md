- 日付: 2026-11-23
- 関連仕様: [デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)、[画面デザインのファイルと変更の手順](../spec/screens/ui-design-files.md)、[画面の見た目とテーマ](../spec/screens/appearance.md)「画面デザイン」
- 置き換え: なし

## 背景

デザインシステム「Progrust」「Progrust Video」と画面デザイン「Progrust UIデザイン」は、リポジトリのファイルを正とし、claude.ai のアーティファクトを表示用として残していた。変えるたびに、リポジトリを直してからアーティファクトへ送り、送った後に中身を確かめていた（[ADR 0152](0152-keep-design-system-files-in-repository.md)、[ADR 0181](0181-keep-ui-design-files-in-repository.md)）。

Issue #117 は、次のことを挙げていた。実装のループの試運転で、ループは `design-system/ui-design/Video.dc.html` を変えた PR #116 をマージした。ループの中ではアーティファクトへ送らないが、送る作業が残っていることは、閉じた Issue のコメントにしか残らなかった。

2026-11-23、Issue #117 の仕分けで、Claude はユーザーに、表示用のアーティファクトをこれからも使うかを尋ねた。ユーザーは「ページをやめる」を選んだ。ユーザーが挙げた理由（選んだ選択肢と、ユーザーの言葉）は、次のとおりである。

- ページを見ていない
- 送る手間を無くしたい
- 画面は実装で見ればよい
- 「そもそもループからclaude.aiに接続できないからアーティファクトをやめたので、送る作業が残るのならデザインをリポジトリに移した意味がない。」

同じ日、Issue #117 の対応で、Claude はユーザーに次のことを尋ねた。

- claude.ai に残っている 3 つのページを消すかどうか。ユーザーは「消す」を選んだ。
- ページをやめた後に、まだ実装していない画面のデザインと部品の見本を、ユーザーが手元のブラウザで見られる仕組みを作るかどうか。Claude は、リポジトリの `.dc.html` は種類「Design」が配る `support.js` とデザインシステムの写しが無いと表示できないこと、部品の見本（`preview.html`）はデザインシステムの CSS を自分で読み込まず、ページが差し込んでいたことを説明した。ユーザーは「作らない」を選んだ。
- まだ実装していない画面のレイアウトを、これまでどおり画面デザインのファイルに従って作るかどうか。[ADR 0150](0150-screen-layouts-follow-ui-design-until-implemented.md) がそう決めた理由は「いまは、ユーザーが画面を見て確かめられるものが、アーティファクトの画面デザインしか無い」で、ページをやめると、この理由は無くなる。ユーザーは「従う（変えない）」を選んだ。

## 決定

- デザインシステムと画面デザインの、表示用のアーティファクトをやめる。リポジトリのファイルだけを正とし、リポジトリの外に、写しや表示用のページを置かない（[デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)「置き場所」、[画面デザインのファイルと変更の手順](../spec/screens/ui-design-files.md)「置き場所」）。
  - 理由: ユーザーが決めた。理由は「背景」のユーザーの理由である。
  - ADR 0152 の「決定」の次の文を変えた。「アーティファクトは、リポジトリのファイルを送ったものとして残し、表示に使う」「アーティファクトを残す理由（Claude の提案。Issue #67）: …ユーザーが見て確かめる場所は、これまでどおりアーティファクトのページである」「ユーザーが見て確かめる場所も、リポジトリから送ったアーティファクトのページのままである」「アーティファクトのページは読み取り専用にする（索引に `"editing": "code"`）。ページでは編集しない」「デザインシステムを変えるときは、リポジトリのファイルを直してから、アーティファクトへ送り、送った後に、リポジトリとアーティファクトの中身が同じことを確かめる。画面デザイン「Progrust UIデザイン」が中に持つ写し…も、デザインシステムを変えたら取り直し、確かめる対象に含める」。
  - ADR 0181 の「決定」の次の文を変えた。「アーティファクトは、リポジトリのファイルを送ったものとして残し、表示に使う」「ページでは編集しない。読み取り専用にする指定が無いので、決まりとして守り、送る前に、アーティファクトの中身がリポジトリと同じことを確かめる」「デザインシステムを変えて画面デザインの中の写しを取り直すときに送る索引を、…リポジトリの `canvas.json` にする」「`tools/design-system.py` で、…送る引数を出し（`files ui-design`）、取得したファイルと比べる（`compare ui-design`）」。
- claude.ai に残っていた 3 つのページ（「Progrust」「Progrust Video」「Progrust UIデザイン」）を消す。
  - 理由: ユーザーが決めた。
  - 消す前に、Claude は次のことを確かめた。「Progrust UIデザイン」のページのファイルの一覧の sha256 を、リポジトリと比べた。ページの `project/` の下（`project/ds/` の下を除く）で、HEAD（f1287e6）と違ったのは `Video.dc.html` の 1 件だけで、その中身はコミット a15f25e の版（PR #116 の前）と同じだった。「Progrust」「Progrust Video」のページは、読み取り専用にしていたので、比べていない。
- ユーザーが、まだ実装していない画面のデザインと部品の見本を見るための仕組みは作らない。画面は、実装してからアプリで見て確かめる。Claude と実装のループは、これまでどおりリポジトリのファイルを読む（[画面デザインのファイルと変更の手順](../spec/screens/ui-design-files.md)「読み方」）。
  - 理由: ユーザーが決めた。ユーザーは、ページを見ておらず、画面は実装で見ればよいと示した。
- まだ実装していない画面のレイアウトは、これまでどおり画面デザインに従う。ADR 0150 は変えない（[画面の見た目とテーマ](../spec/screens/appearance.md)「画面デザイン」）。
  - 理由: ユーザーが決めた。ADR 0150 が挙げた理由（ユーザーが見て確かめられるのがアーティファクトだけであること）は無くなったが、ユーザーは決まりを変えないことを選んだ。
- アーティファクトへ送るための道具（`tools/design-system.py` の `files` と `compare`）を消す（Claude の判断）。
  - 理由: 送る先と、取得して比べる先が無くなった。使わない道具を残すと、手順に送る作業が残っているように読める。
- 索引のうち、表示用のページのためだけにあった項目を消し、検査でも求めない（Claude の判断。[デザインシステムのファイルと変更の手順](../spec/screens/design-system-files.md)「ディレクトリの中身」「検査」、[画面デザインのファイルと変更の手順](../spec/screens/ui-design-files.md)「ディレクトリの中身」）。消すのは、デザインシステムの索引の、ページを読み取り専用にする指定（`editing`）、アイコンのアセットの id（`blob`）、最後の変更の記録（`lastChange`）と、画面デザインの索引の、中のデザインシステムの写しの記録（`designSystems`）である。
  - 理由: どれも、表示用のページが使うか、ページへ送るときにだけ要る値だった。`blob` は消したアーティファクトの id で、新しいアイコンには付けられない。`lastChange` は、ページに出していた最後の変更の記録で、変更の記録は Git の履歴に残る。`designSystems` は、ページの中の写しを取った版と時刻で、写しが無くなる。
- ディレクトリの構成とファイルの形は、上の索引の項目を消すほかは変えない。種類「Design System」「Design」の形のまま置く（Claude の判断）。
  - 理由: 形を変えるのは、表示用のページをやめることとは別の判断である。いまの検査と、実装と計画のための読み方は、この形を前提にしている。

## 検討した他の案

- 案: 表示用のアーティファクトを残し、実装のループが `design-system/` を変えたときに、送る作業が残っていることを Issue のラベルなどで残す（Issue #117 が挙げた案の 1 つ）
  - 採用しなかった理由: ユーザーがページをやめることを選んだ（「背景」）。
- 案: 実装のループに `design-system/` を変えさせない（保護するパスにする。Issue #117 が挙げた案の 1 つ）
  - 採用しなかった理由: ページをやめると、ループが変えても残る作業が無い。ループが画面デザインのファイルを直せなくなる。
- 案: ページを消さずに、更新しないまま残す
  - 採用しなかった理由: ユーザーが消すことを選んだ。
- 案: 画面デザインと部品の見本を、手元のブラウザで見られる仕組みを作る
  - 採用しなかった理由: ユーザーが作らないことを選んだ。
- 案: 索引のページのための項目を、値は使わないまま残す
  - 採用しなかった理由: 消したアーティファクトの id や URL が残ると、どこかにページがあるように読める。新しいアイコンには `blob` を付けられないので、検査で求め続けることもできない。

## 影響

- デザインシステムと画面デザインを変えるときに、アーティファクトへ送る作業と、送った後に確かめる作業が無くなる。実装のループが `design-system/` を変えても、残る作業は無い。
- ユーザーは、まだ実装していない画面と部品の見本を、絵として見られなくなる。画面は、実装してからアプリで見て確かめる。
- ADR 0153 が `components/bundle.css` の先頭の `@import` の行を取り除かない理由に挙げた、アーティファクトのページの見本が書体を読み込むことは、無くなった。
- ADR 0155 が索引に項目を足さない理由に挙げた、アーティファクトのページがどう扱うか分からないことも、無くなった。
- ADR 0150 の「決定」の理由に書かれた「いまは、ユーザーが画面を見て確かめられるものが、アーティファクトの画面デザインしか無い」は、当時の事実で、いまは当たらない。決定は変わらない。
