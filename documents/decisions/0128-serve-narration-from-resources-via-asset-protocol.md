## 背景

動画のコードと音声は、どちらもフロントエンドのビルドに含め、ビルド済みのアセットとして読むことにしていた。Tauri は、ビルド済みのアセットを `tauri://` で配る。

技術検証で、次のことが分かった（[レッスンごとの動画の遅延読み込みの技術検証](../verification/issue-4-lazy-load-lesson-video.md)「音声の置き方 2 通りの比較」）。

- `tauri://` は、ファイルの一部だけを求める要求（Range リクエスト）を無視し、ファイルの全体を返す（206 ではなく 200）。
- `<audio>`（Remotion の `Html5Audio`）で音声を鳴らすと、読み込みとシークのとき、約 3 秒の間に、同じ 52KB のファイルの全体を 81 回配った。読み込みとシークが済んだ後の再生中は、5 秒で 3 回だった。
- 同じ音声を Tauri のリソースに置き、アセットプロトコル（`convertFileSrc` で作る `asset://` の URL）で配ると、Range リクエストに 206 で答え、音声も鳴った。`asset://` での配信の回数は、数えられなかった。
- どちらの置き方でも、再生に問題は見えなかった。81 回の配信による CPU や待ち時間への影響は、測っていない。ユーザーが聞いて音声の部品を決めたとき（[ADR 0092](0092-play-narration-with-html5audio.md)）の試作は、`tauri://` で音声を配っていた。

音声の置き方は、検証の「残った事項」で、ユーザーの判断が要る点として残っていた（Issue #35）。

Claude は、害が観測されていないことと、仕様と設定の変更が要ることから、今のまま変えないことを推奨し、もう一方の案として `asset://` に変えることを示した。ユーザーは次のように示し、`asset://` にすると決めた。

- 「`asset://` のほうが使い方として正しいと思うので`asset://` にしましょう。これにより検証が必要な場合は新規で技術検証Issueを作成してください。いまは検証しなくてよいです。」

## 決定

- 動画の音声を、フロントエンドのビルドに含めず、アプリ同梱データ（Tauri のリソース）に置き、フロントエンドは Tauri のアセットプロトコル（`asset://`）で読む（[フロントエンドとバックエンドの役割分担](../spec/architecture/responsibilities.md)）。ユーザーの判断による。理由は、`asset://` のほうが使い方として正しいから、である（「背景」のユーザーの言葉）。
- 動画のコードと、動画が読み込む画像は、今までどおりフロントエンドのビルドに含める。
- 次の細部は Claude が決めた。
  - アセットプロトコルで読める範囲（スコープ）を、アプリ同梱データの音声ファイルに限る（[Tauri の権限](../spec/architecture/tauri-permissions.md)）。理由: アセットプロトコルは、スコープの中のファイルを WebView から読めるようにする。フロントエンドに許可する権限を最小限にする方針に合わせ、要るファイルだけにする。
  - 音声のディレクトリの絶対パスは、バックエンドが `get_lesson` で返し、フロントエンドは `convertFileSrc` で URL に変える。理由: アプリ同梱データの場所を知っているのはバックエンドである。フロントエンドに Tauri のパスの API を許可しなくて済む。
  - CSP の音声の読み込み先（`media-src`）に、アセットプロトコルを加える（[セキュリティとプライバシー](../spec/non-functional/security-privacy.md)「アプリ自体」）。理由: 加えないと、CSP が `asset://` の音声を拒否すると見ている。[ADR 0111](0111-bundle-monaco-and-set-csp.md) は、読み込み先を加える必要があれば仕様に書いて加える、としている。

## 検討した他の案

- 案: 音声をフロントエンドのビルドに含めたままにする（それまでの仕様）
  - 採用しなかった理由: ユーザーが、`asset://` のほうが使い方として正しいと判断した。`tauri://` は Range リクエストに全体を返し、読み込みとシークのたびに同じファイルを何十回も配る
- 案: 音声を、フロントエンドのビルドに含めたまま、別の方法で読む（一度だけ読み込んで Blob の URL にする、など）
  - 採用しなかった理由: どの方法も確かめていない。`asset://` は、検証で 206 で答えて音声が鳴ることを確かめてある

## 影響

- 次の点は確かめていない。Issue #46 の技術検証で確かめる。うまくいかなかったときは、スコープと CSP の定め、または音声の置き方を見直す。
  - 仕様の CSP の下で、`asset://` の音声を再生できるか。検証の試作には CSP が無かった。
  - スコープを音声ファイルだけに絞っても再生できるか。検証では、スコープをリソースの全体（`$RESOURCE/**`）にしていた。
  - 読み込みとシークのときの配信の繰り返しが、`asset://` で減るか。
  - 人が見て聞いて、音声と絵のずれ、シークの直後、再生速度を変えたときが気にならないか。ADR 0092 の試聴は `tauri://` で行った。
  - 開発時の起動（`tauri dev`）でも、同じ方法で音声を読めるか。
- 音声の URL には、アプリの絶対パスが入る。
- 音声は、フロントエンドのビルドで名前にハッシュが付かなくなり、アプリ同梱データの中に元の名前のまま入る。
- アプリのビルドの設定で、アセットプロトコルを有効にし（Tauri の feature `protocol-asset`）、スコープを設定する必要がある。
