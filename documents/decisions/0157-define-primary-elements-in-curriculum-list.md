## 背景

カリキュラムの仕様は、各レッスンの主要素・副要素を「レッスンを作るときに `lesson.json` に定める」とし、章とレッスンの一覧には「主に扱う内容」として範囲だけを書いていた。Issue #64 は、各レッスンの主要素・副要素を、要素の一覧と一緒に決めるか、レッスンを作るときに決めるかを、決めることとして挙げていた。

要素マスタの要素は、レッスンを作る前にすべて決めた（[ADR 0156](0156-define-all-elements-before-lessons-one-per-lesson.md)）。要素は、レッスンごとに 1 つまたは 2 つを置く形で決めたので、どのレッスンがどの要素を主要素にするかは、要素を決めた時点で決まっている。

関係する判断が 2 つある。

- [ADR 0007](0007-derive-introduced-lesson.md) は、要素の導入レッスンを要素マスタに持たせない、と決めた。同じ事実を 2 か所に書くと、値がずれる可能性が残り、レッスンの順序を変えるたびに要素マスタも直す必要があるからである。
- [ADR 0078](0078-curriculum-spec-as-source-of-chapters-json.md) は、カリキュラムの唯一の定義を仕様とし、`chapters.json` と `lesson.json` の `title` をそれに合わせて、一致を教材チェックツールで検証する、と決めた。

Claude は、主要素をいま決めて章とレッスンの一覧に書き、副要素はレッスンを作るときに決める案を推奨し、レッスンを作るときに決める案も示した。ユーザーは、推奨案のとおりにすると答えた。理由は Claude が書いた。

## 決定

- 各レッスン（動画のみのレッスンと章末復習レッスンを除く）の主要素を、章とレッスンの一覧の「主要素」の列に定め、これを唯一の定義とする。`lesson.json` の `primary_elements` はそれに合わせ、一致を教材チェックツールで検証する（[カリキュラムの目的とスコープ](../spec/curriculum/scope.md)、[章とレッスンの一覧の読み方](../spec/curriculum/chapters/how-to-read.md)、[教材チェックツール](../spec/content-guidelines/check-tool.md)）。
  - 理由: 対応は、要素を決めた時点で決まっている。書き残さないと、レッスンを作るたびに、要素の名前と説明から対応を推測し直すことになる。
  - 理由: 実装時に判断が残るものを減らす、という要素を先に決めた理由（ADR 0156）にも合う。
- 副要素は、これまでどおり、レッスンを作るときに `lesson.json` に定める。
  - 理由: 副要素は、演習に登場する既習の要素で、演習の内容が決まらないと決まらない。
- ADR 0007 の判断は変えない。導入レッスンは、これまでどおり、学習順と `lesson.json` の `primary_elements` から求め、要素マスタには持たせない。
  - 主要素を一覧と `lesson.json` の 2 か所に持つことは、ADR 0007 が避けた重複と同じ種類のものである。ADR 0007 が挙げた理由のうち、順序を変えるたびに直す手間は、一覧では主要素がレッスンの行にあり、行ごと動くので生じない。値がずれる可能性は、ADR 0078 がレッスンのタイトルでそうしたように、教材チェックツールの検証で防ぐ。
- 次の細部は Claude が決めた。
  - 一覧の「主要素」と要素マスタの照合（教材チェックツールの「要素と一覧」）は、準備中のレッスンがあっても行う。理由: `lesson.json` を使わずに検査できる。どのレッスンの主要素にもならない要素を、全レッスンがそろう前に見つけられる（[ADR 0145](0145-show-unprepared-lessons-as-in-preparation.md) の「影響」に書いた、気づけない期間を無くす）。
  - 章末復習レッスンの主要素は、一覧では定めない（[ADR 0158](0158-chapter-review-has-two-to-five-primary-elements.md)）。理由: 章末復習レッスンは、タイトルも一覧では定めていない。主要素は、演習で組み合わせる要素で決まる。

## 検討した他の案

- 案: 主要素も、レッスンを作るときに `lesson.json` に定める（これまでの仕様）
  - 採用しなかった理由: 要素とレッスンの対応がどこにも残らない。対応の誤り（どのレッスンの主要素にもならない要素など）は、全レッスンがそろうまで、教材チェックツールで見つけられない
- 案: 要素マスタに、導入レッスンを持たせる
  - 採用しなかった理由: ADR 0007 が採らなかった案である。レッスンの順序を変えるたびに、要素マスタも直すことになる

## 影響

- 主要素を、章とレッスンの一覧と `lesson.json` の 2 か所に持つ。主要素を変えるときは、先に一覧を変え、`lesson.json` を合わせる。
- 一覧の主要素を変えるのは、カリキュラムの変更にあたる。理由のある変更は ADR に記録する（[ADR 0131](0131-record-reasons-for-later-lesson-changes.md)）。
- 教材チェックツールは、章ごとのファイルの表から、「主要素」の列も読み取る必要がある。
- 学習順には準備中のレッスンも含むので、導入レッスンが準備中のレッスンになる要素は、一覧に主要素として書いてあっても、まだ既習の要素にならない（ADR 0145 の「影響」のとおり）。
