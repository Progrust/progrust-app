## 背景

画面と動画の書体には Murecho と Red Hat Mono を使う（デザインシステム）。書体のファイルをアプリに同梱する方法が未決事項になっていた（Issue #26）。

Issue #20 の技術検証で、ファイルの大きさを測った（[配布物と更新のサイズの技術検証](../verification/issue-20-distribution-size.md)）。Murecho の可変フォントは、TTF で約 1.43MB、woff2 に変換すると約 0.62MB で、サブセット化しても約 0.1MB しか減らない。Red Hat Mono の可変フォントは TTF で約 0.07MB である。

2026-11-21 に配布元を調べた。どちらも SIL Open Font License 1.1 で、OFL の FAQ では、形式の変換とサブセット化は改変版（Modified Version）に当たる。Red Hat Mono は、配布元の `OFL.txt` には予約フォント名（改変版に使えない名前）が無いが、配布元の README には予約フォント名「Red Hat」と書かれている。Murecho の可変フォントは、配布元が TTF だけを配っている（woff2 はウェイトごとの静的なファイルだけ）。

Claude は、可変フォントを全グリフのまま入れるか、サブセット化するかを決める必要があることと、ライセンスの面ではサブセット化しないほうが扱いが簡単であることを示した。ユーザーは「扱いやすい方でお願いします。」と示し、判断と理由を Claude に任せた。以下の決定と理由は Claude が書いた。

## 決定

- 配布元が配っている可変フォントのファイルを、形式の変換もサブセット化もせずに同梱する。ライセンスの本文（配布元の `OFL.txt`）も同梱する（[画面の見た目とテーマ](../spec/screens/appearance.md)「書体のファイル」）。
  - 理由: 変換やサブセット化の作業と道具が要らず、書体を更新するときも配布元のファイルを置き換えるだけで済む。改変版にならないので、予約フォント名の食い違いを気にせずに済む。1 書体 1 ファイルで、すべてのウェイトを使える。
  - 理由: 大きさの差（Murecho で約 0.8MB）は、アプリの完成までは配布しない（[ADR 0091](0091-no-distribution-or-auto-update-until-publication.md)）ので問題にならない。
- 画面と動画で同じファイルを使う。
  - 理由: 動画はアプリの中で Remotion Player で描画する（[ADR 0061](0061-render-videos-with-remotion-player.md)）ので、同じファイルを読み込める。

## 検討した他の案

- 案: woff2 に変換し、使う文字だけにサブセット化する
  - 採用しなかった理由: 減るのは約 0.9MB で、変換の手順を持つ手間に見合わない。改変版になり、Red Hat Mono では名前を変えるべきかの判断が要る
- 案: Murecho はウェイトごとの静的な woff2（配布元が配っているもの）を使う
  - 採用しなかった理由: 使うウェイトの数だけファイルが要り、1 つで約 0.6MB あるので、2 つ以上使うと可変フォントの TTF より大きくなる
- 案: Google Fonts などからネットワーク経由で読み込む
  - 採用しなかった理由: オフラインのときに書体が変わる。アプリのページの CSP は、フォントの読み込み先にアプリ自身と `data:` だけを許している（[セキュリティとプライバシー](../spec/non-functional/security-privacy.md)）

## 影響

- 書体のファイルは合わせて約 1.5MB になる。
- 一般公開するときのライセンスの確認は、別に残っている（[非機能要件の未決事項](../spec/non-functional/open-questions.md)）。そのときに大きさを減らす必要が出たら、変換やサブセット化を改めて検討する。
