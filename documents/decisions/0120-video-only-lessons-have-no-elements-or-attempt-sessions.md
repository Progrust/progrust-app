## 背景

演習のない動画のみのレッスンを設けることにした（[ADR 0119](0119-video-only-lessons-for-background-knowledge.md)）。

レッスン・学習記録・分析・問題生成の設定は、すべて要素マスタの要素 ID で Rust の要素を参照し、要素 ID は公開したら消せない（[ADR 0006](0006-element-ids-are-permanent.md)）。`lesson.json` の主要素は 1〜2 件と定めていた。

試行セッションはレッスンを開いたときに始まり、提出で正解した後にだけ終わる。学習記録は、終わった試行セッションの試行ログから作る。動画の再生中の質問は、試行ログに記録している。

## 決定

- 動画のみのレッスンには、主要素も副要素も持たせない（[レッスン定義の形式（lesson.json）](../spec/content-format/lesson-json.md)）。Claude が次の 2 案を示して持たせない案を勧め、ユーザーが採用した。
  - 理由: 持たせると、「スタックとヒープ」のような概念が要素マスタに入る。要素 ID は公開後に消せず、問題生成の設定画面で選べるようになる。レッスンの演習がないので、生成問題を解かない限り「未学習」と表示されたままになる。
- 動画のみのレッスンでは、試行セッションを作らない（[試行ログ（attempts/*.json）](../spec/learning-record-and-analysis/attempt-log.md)「試行セッションのライフサイクル」）。これは Claude が決めた。ユーザーには、動画のみのレッスンで学んだ概念については理解度のデータが残らないことを伝えてあり、そのうえで動画のみのレッスンを設ける案が採用された。
  - 理由: 試行セッションは正解の後にだけ終わるので、演習のないレッスンでは終わらない。学習記録は演習の解き方と躓きを要素ごとに記録するもので、要素のないレッスンの記録は分析のどの要素にも結びつかない。

## 検討した他の案

- 案: 動画のみのレッスンにも要素を持たせる（周辺知識を要素マスタに入れる）
  - 採用しなかった理由: 上の「決定」の理由のとおり
- 案: 動画のみのレッスンでも試行セッションを作り、完了したときに終わらせて、質問だけの学習記録を作る
  - 採用しなかった理由: 要素のない記録は分析のどの要素にも結びつかず、使い道がない

## 影響

- 動画のみのレッスンでも、動画の再生中に質問できる（[質疑応答を利用できる場面](../spec/qa-chat/availability.md)）。
- 動画のみのレッスンでの質問は、試行ログに残らない（[質疑応答の試行ログへの記録](../spec/qa-chat/attempt-log.md)）。学習記録と分析に使えない。
- 動画のみのレッスンの質疑応答では、AI に主要素の説明が渡らない。タイトルと台本は渡る（[質疑応答で AI に渡す入力](../spec/qa-chat/ai-input.md)「動画の再生中」）。
- 動画のみのレッスンには主要素がないので、動画には既習の要素だけを登場させる（[未登場の要素を使わない](../spec/content-guidelines/no-unseen-elements.md)）。動画のみのレッスンで新しい Rust の要素を導入することはできない。
- 周辺知識は要素ではないので、教材チェックツールは、周辺知識が既習かどうかを検証できない。周辺知識を前提にするレッスンは、章とレッスンの一覧の「主に扱う内容」に「ch04-01 を既習とする」のように書いて示す。
- 周辺知識は要素マスタに入らないので、問題生成の設定で要素として選べない。
