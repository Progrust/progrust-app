## 背景

動画のシーンは制限のない TSX で書き、最低限の lint として、色の直接指定と、Tauri の API・ネットワーク・ファイルへのアクセスを禁じている（[ADR 0062](0062-write-video-scenes-in-unrestricted-tsx.md)）。

Issue #7 の技術検証で、この lint を ESLint（標準のルールと独自のルール 2 つ）と stylelint で試した（[動画の描画チェックを CI で実行できるかの技術検証](../verification/issue-7-render-check-in-ci.md)）。

- 禁止事項の大部分は検出できた。実行時に組み立てた文字列と、別名を経由したアクセスは検出できなかった。
- `eval`・`new Function`、型アサーションした `window`（`(window as any).__TAURI__`）、`window[...]` の動的なアクセスを使うと、名前を直接書かずに禁止事項を使えてしまい、検査をすり抜けられる。検証では、仕様にないこれらも禁止に加えて試した。
- 色の名前（`red` など）は、画面の文章の語と区別できない。検証では、`style` のプロパティの値と SVG の色の属性の中だけで色の名前を検査した。16 進表記と色の関数は、どの文字列でも検査した。
- stylelint の標準のルールでは、CSS の `@import` のうち外部の URL のものだけを禁じることができない。検証では、`@import` をすべて禁じた。
- 仕様の「`window.__TAURI__` など」の「など」の範囲は決まっていなかった。検証では `__TAURI__` と `__TAURI_INTERNALS__` にした。
- ESLint は `.css` を検査しない。検証では、`.css` を stylelint で検査した。

Claude は、`eval` などの検査をすり抜ける書き方を禁止に加えることを推奨し、ほかの点は検証で試した構成にすることにした。ユーザーは、「このあたりの技術的な話は私はあまく詳しくないのであなたの推奨でお願いします。理由もあなたが書いてください。」と示し、判断と理由を Claude に任せた。以下の理由は Claude が書いた。

## 決定

- 動画のコードの禁止事項に、検査をすり抜ける書き方（`eval`・`new Function`、引数が文字列リテラルでない動的 import、`window` などへの `[...]` でのアクセスと型アサーションを通した使用）を加える（[動画のコードの禁止事項](../spec/content-format/video/prohibited-code.md)）。
  - 理由: これらを使うと、ADR 0062 で禁じた Tauri の API とネットワークへのアクセスを、名前を直接書かずに使える。レッスンの動画にこれらが要る場面は見当たらない。
- ファイルへのアクセスに、`require()` を明記する。
  - 理由: Node.js の組み込みモジュールを、import を使わずに読む手段である。検証で検出できた。
- Tauri の API へのアクセスとして検査する名前を、`__TAURI__` と `__TAURI_INTERNALS__` にする。
  - 理由: 検証で試した範囲であり、どちらもバックエンドを呼び出す入口の名前である。
- 色の名前は、CSS の宣言、`style` のプロパティの値、SVG の色の属性に、文字列で直接書いたものだけを検査する。16 進表記と色の関数は、動画のコードのどの文字列に書いても検査する。
  - 理由: 色の名前は `red` のような普通の語なので、どの文字列でも検査すると画面の文章を誤検出する。16 進表記と色の関数は、画面の文章にはほとんど出ない。
- lint は、書かれたとおりの文字列と名前を検査し、実行時に組み立てた文字列や、変数・別名を経由したものは検出しない、と仕様に書く。そうした書き方で禁止事項を避けてはならない、とも書く。
  - 理由: 静的な検査では検出できないことを、検証で確かめた。変数を経由して書いた色は、lint では見つからない。テーマによって読めなくなるものは、レビューのチェックリストの「ライト・ダークのどちらのテーマでも、動画の文字と図が読める」で見つけられる。どちらのテーマでも読める色は、レビューでも見落とすことがある（[教材レビューのチェックリスト](../spec/content-guidelines/review-checklist.md)）。
- CSS の `@import` は、参照先によらず使わない。CSS は TSX から import する。
  - 理由: stylelint の標準のルールでは、外部の URL の `@import` だけを禁じることはできない。TSX からの CSS の import は、Remotion Studio・チェックツール・アプリの Vite ビルドの 3 か所で動いた。
- `.css` は stylelint で、`.tsx`・`.ts` は ESLint で検査する、と仕様に書く。
  - 理由: ESLint は `.css` を検査しない。

## 検討した他の案

- 案: 禁止事項を、これまでの仕様の範囲にとどめる（`eval` などを加えない）
  - 採用しなかった理由: 名前を直接書かずに Tauri の API とネットワークを使う抜け道が残る
- 案: 色の名前を、どの文字列でも検査する
  - 採用しなかった理由: 画面の文章の `red` などの語を誤検出する
- 案: CSS の `@import` のうち、外部の URL のものだけを禁じる（独自のルールか postcss のスクリプトを作る）
  - 採用しなかった理由: 自作の検査を保守する必要がある。CSS は TSX から import すれば足りる

## 影響

- この ADR で加えた禁止は、`@import` を除き、ADR 0062 の最低限の範囲（色・Tauri の API・ネットワーク・ファイル）を守るための書き方である。`@import` は、外部の URL のものだけを禁じられないため、ローカルのものも禁じた。部品の作り方、動き、レイアウトは、引き続き lint で制限しない。
- 16 進表記はどの文字列でも検査するので、`"#123 番"` のような文字列もエラーになる。画面の文章にこう書くときは、書き方を変える。
- 引数が文字列リテラルでない動的 import の禁止は、検証では試していない（検証で試したのは、禁止したモジュールを文字列で指す動的 import だけ）。lint を作るときに確かめる。
- 実行時に組み立てた文字列、別名、ライブラリの中で行われるアクセスは、lint では見つからない。lint は作者の書き間違いを防ぐもので、すり抜けようとして書いたコードまでは防げない。
