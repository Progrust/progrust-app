## 背景

C のレッスンでも質疑応答を使えるようにする（[ADR 0265](0265-c-lessons-without-elements-records-and-generation.md)）。動画の再生中の質疑応答では、AI に、主要素の説明と既習の要素の一覧を渡している（[ADR 0261](0261-derive-learned-elements-for-chat-from-bundled-content.md)）。AI が、まだ学んでいない内容を使って答えないようにするためである。C のレッスンは要素を持たない（[ADR 0265](0265-c-lessons-without-elements-records-and-generation.md)）ので、渡すものが無い。

C のレッスンが扱う内容は、章とレッスンの一覧の「主に扱う内容」に定めているが、アプリは章とレッスンの一覧を持たない。

## 決定

以下は、どれも Claude が決めた。

- C のレッスンの動画の再生中は、既習の要素の代わりに、学習順でそのレッスンより前にある、準備中でない C のレッスン（章末復習レッスンを除く）の `title` と `summary` を渡す（[質疑応答で AI に渡す入力](../spec/qa-chat/ai-input.md)）。
  - 理由: アプリが同梱した教材から求められる。何を学んだ後のレッスンかが、AI に伝わる。
- Rust のレッスンの動画の再生中にも、C の章で学んだ内容として、C のレッスンの `title` と `summary` を渡す（同上）。
  - 理由: Rust のレッスンは、C の章と対比して説明する（[ADR 0268](0268-contrast-rust-lessons-with-c-chapters.md)）。AI も、学習者が C で何を体験したかを知っていれば、対比して答えられる。
- AI に渡す入力に、レッスンの言語を足す。回答の方針は、言語ごとに定める（[質疑応答の回答の方針](../spec/qa-chat/answer-policy.md)）。C のレッスンでは、C17 と Apple の clang を前提に答え、未定義動作になるコードはそうであることを明示し、Rust について聞かれたら短く答えて Rust の章で学ぶことを伝える。解説表示中は、Rust らしい書き方の代わりに、メモリの誤りを避ける書き方について答えてよいとする。
  - 理由: C の章の目的（メモリの扱いの難しさを体験すること。[ADR 0262](0262-teach-c-chapters-before-rust.md)）に合わせる。Rust に深入りしないのは、Rust の基本と C の基本が混ざらないようにするためである。
- C のレッスンの `title` と `summary` を渡すのは、動画の再生中だけにする。解説表示中には渡さない。
  - 理由: 解説表示中は、もともと既習の要素の一覧を渡していない。問題文・解説・模範解答・正解したコードがあれば、その演習の範囲が伝わる。
- 指示文のファイルは増やさず、同じファイルに、言語に応じた指示を書く（[指示文（プロンプト）の置き場所と書き方](../spec/claude-integration/prompts.md)）。
  - 理由: 共通の指示（日本語で簡潔に答える、演習の答えを書かない など）を 2 つのファイルに書き写さずに済む。

## 検討した他の案

- 案: C のレッスンの `lesson.json` に、扱う内容の一覧のフィールドを足して渡す
  - 採用しなかった理由: 章とレッスンの一覧の「主に扱う内容」と同じことを 2 か所に書くことになり、教材チェックツールで照合する対象も増える
- 案: C のレッスンでは、既習の内容を渡さない
  - 採用しなかった理由: AI が、まだ学んでいない C の構文や関数を使って答えやすくなる

## 影響

- `title` と `summary` は 1 行ずつの説明なので、既習の要素の一覧ほど細かくは伝わらない。細かい範囲は、台本と `ai_note` で伝える。
- C のレッスンの `summary` は、質疑応答の入力にもなる。
