## 背景

`cargo`・`rustc` の検出を実装するとき（Issue #152）、仕様には探索順（設定で指定したパス → `PATH` → `~/.cargo/bin`）と必要条件（`rustc --version` が 1.100.0 以上）だけがあり、次のことが決まっていなかった。

- 設定の `tool_paths.cargo` を指定したときに、`rustc` をどこから探すか。
- 設定のパスが無いときや、ある場所に `cargo` はあるが `rustc` が無いとき、`rustc --version` が失敗するときに、次の場所を探すか。
- 先の場所の `rustc` が古く、後の場所に新しい `rustc` があるときに、どちらを使うか。
- バージョンの取り出し方と比べ方。

プロジェクトの方針（`CLAUDE.md`）で、アプリの操作感に関わらない技術の詳細は、Claude が最適と思う方法で決めることになっている。以下の決定と理由は、すべて Claude の判断である。

## 決定

[外部ツール（cargo・claude）への依存](../spec/architecture/external-tools.md)「検出」のとおりにする。要点は次のとおり。

- 探索順の場所ごとに、`cargo` と、同じディレクトリの `rustc` を組で調べる。設定のパスは `cargo` の実行ファイルの絶対パスとし、`rustc` はその隣のものを使う。
  - 理由: rustup（`~/.cargo/bin`）も Homebrew も、`cargo` と `rustc` を同じディレクトリに置く。別々の場所から探すと、版の違う `cargo` と `rustc` を組み合わせることがある。設定の項目は `tool_paths.cargo` の 1 つだけなので、`rustc` の場所を別に指定させない。
- 設定のパスが無いとき、`cargo` か `rustc` が無いか実行できないとき、`rustc --version` が失敗するか終わらないとき、出力からバージョンを取り出せないときは、その場所を飛ばして次の場所を調べる。
  - 理由: 探索順は、先の場所を優先する順である。先の場所が使えないときに、後の場所にある使えるツールを見落とさない。設定のパスを書き間違えても、既定の場所にある Rust で演習を実行できる。
- `rustc --version` が成功した最初の場所を使い、`rustc` のバージョンが必要条件に満たなくても、後の場所を調べない。
  - 理由: 設定でパスを指定したときに、そのパスを確実に使う。後の場所に新しい版があっても切り替えると、どの Rust が使われるかが、置かれたツールの版で変わり、分かりにくい。古い版を使うときは、更新の案内が出る（[ADR 0117](0117-raise-min-rustc-only-when-author-decides.md)）。
- 相対パスの場所（設定のパスと `PATH` のディレクトリ）は調べない。
  - 理由: アプリの作業ディレクトリは起動の方法で変わり、相対パスが指す場所が定まらない。
- バージョンは、出力の 1 行目の 2 つ目の語とし、メジャー・マイナー・パッチを数として比べる。`-nightly` などの後ろの部分は比べない。
  - 理由: 文字列として比べると `1.99.1` が `1.100.0` より大きくなる。nightly・beta の版（`1.100.0-nightly` など）は、日ごとや段階ごとに中身が変わり、後ろの部分からは stable の `1.100.0` より機能が多いか少ないかを決められないので、数だけで比べる。比べ方が実際の機能とずれても、バージョンが足りないときも実行はできるので（[ADR 0117](0117-raise-min-rustc-only-when-author-decides.md)）、使えなくなることはない。
- `rustc --version` は 10 秒で打ち切る。
  - 理由: 応答しない実行ファイルがあっても、検出が終わらないままにしない。`rustc --version` は、ふつう 1 秒もかからない。

## 検討した他の案

- 案: `rustc` を、`cargo` とは別に、同じ探索順で探す
  - 採用しなかった理由: 版の違う `cargo` と `rustc` を組み合わせることがある
- 案: 設定のパスが使えないときは、ほかの場所を探さずに見つからないとする
  - 採用しなかった理由: 設定を書き間違えただけで、既定の場所の Rust も使えなくなる
- 案: 必要条件を満たす `rustc` が見つかるまで、すべての場所を調べる
  - 採用しなかった理由: 設定で指定したパスが、古いという理由で使われないことがある。使われる Rust が分かりにくい
- 案: 設定のパスにディレクトリ（`cargo` と `rustc` のあるディレクトリ）を指定させる
  - 採用しなかった理由: 項目の名前が `tool_paths.cargo` で、`claude` と同じく実行ファイルを指すほうが分かりやすい

## 影響

- `cargo` と `rustc` を別のディレクトリに置いた環境では、検出できない。そのときは、`cargo` と `rustc` が並ぶディレクトリ（rustup の `~/.cargo/bin` など）を設定で指定する必要がある。
- 先の場所に古い Rust があると、後の場所に新しい Rust があっても古いほうを使い、更新の案内が出る。
- 設定のパスに `~` を書いても、ホームディレクトリとしては扱わない（相対パスとして飛ばす）。
