## 背景

教材では、標準入力の読み込みのように、どうしても未学習の構文が要る部分を初期コードに完成した形で用意している。その部分には、「今はおまじないとして使う。詳しくは第 N 章で学ぶ」と書く決まりだった。見本の教材 ch04-04 の演習のコメントにも、この書き方があった。

ユーザーは、「おまじない」という語を使わないことにした。理由は、学習者をばかにしている（知能が低い子ども向けの表現のような）印象を受けるからである。代わりに、どのようなものかを簡単に説明しつつ、「後のレッスンで詳しく学びます」のような正確な表現にすることを示した。

## 決定

- 未学習の構文を初期コードに用意するときは、「おまじない」と書かず、その部分がどんな処理かを簡単に説明し、どのレッスンで詳しく学ぶかを書く（[未登場の要素を使わない](../spec/content-guidelines/no-unseen-elements.md)）。C のレッスンも同じとする（[C の章の教材の作成ルール](../spec/content-guidelines/c-lessons.md)「既習の内容だけを使う」）。
- 学ぶレッスンは、学習者が画面で見るレッスンの番号とタイトル（例: 「9-5「標準入力を読む」」）で書く。以下の理由は Claude が書いた。
  - 理由: 学習者の画面に出るのはレッスンの番号とタイトルで、レッスンの ID（ch09-05）は出ない。「第 N 章」だけでは、章の中のどのレッスンかが分からない。
- 何をするものかを言わずに「とりあえず書く」とだけ書くことも、同じ理由でしない。
- [ADR 0263](0263-c-chapters-scope-three-chapters.md) の「決定」の「`scanf` に付ける `&` は、ここではおまじないとし、理由は c02-02 で教える」を、「`&` が何をするかを簡単に説明し、理由は c02-02 で詳しく教える」に変える。理由を後のレッスンで教えることは変えない。

## 検討した他の案

- 案: 「おまじない」の語は残し、詳しく学ぶ章を書くことだけを決まりにする（これまでの書き方）
  - 採用しなかった理由: ユーザーが、学習者をばかにしている印象を受ける語だとした

## 影響

- 初期コードのコメントか問題文に、その部分の処理の説明を書く手間が増える。
- 見本の教材 ch04-04 の演習のコメント（初期コード・模範解答・解説）を、この決まりに合わせて直した。
- 採用した ADR（[ADR 0104](0104-teach-flush-after-print.md)、[ADR 0109](0109-generated-exercise-layout-and-starter-rules.md)）の本文には「おまじない」の語が残るが、書き換えない（[ADR の運用ルール](../conventions/decision-records.md)「変更」）。
