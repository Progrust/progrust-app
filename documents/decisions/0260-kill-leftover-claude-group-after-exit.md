- 関連仕様: [claude -p の呼び出しの共通ルール](../spec/claude-integration/invocation.md)「プロセスの止め方」
- 置き換え: なし

## 背景

`claude -p` は新しいプロセスグループで起動し、制限時間を超えたときと中断のときは、グループ全体に SIGTERM、3 秒後に SIGKILL を送る（[ADR 0257](0257-stop-claude-by-process-group.md)）。`claude` が自分で終わったときに、同じグループに残ったプロセスをどうするかは決まっていなかった。

Issue #10 の技術検証では、隔離していない `claude -p` が、正常に終わった後も、MCP サーバーの孫のプロセスを孤児として残した（[claude -p の子プロセスとしての扱いの技術検証](../verification/issue-10-claude-child-process.md)）。隔離した呼び出しには、いま子のプロセスが無い。

残ったプロセスが `claude` の標準出力・標準エラー出力のパイプを持っていると、出力の終わりが届かず、呼び出しを終えられない。

`claude -p` を呼ぶ部品を作るタスク（Issue #275）で、Claude が技術的な判断で決めた。

## 決定

- `claude` のプロセスが終わったら、刈り取る前に、同じプロセスグループに残ったプロセスに SIGKILL を送る（[claude -p の呼び出しの共通ルール](../spec/claude-integration/invocation.md)「プロセスの止め方」）。
  - 理由: Claude Code の版が変わって子のプロセスを作るようになっても、アプリの呼び出しのたびに孤児を残さない。残ったプロセスがパイプを持ち続けて、呼び出しが終わらないこともなくなる。
- 残ったプロセスには、SIGTERM を送って待たずに、すぐに SIGKILL を送る。
  - 理由: 残ったプロセスは `claude` の子で、アプリの子ではないので、終わったかを待って確かめられない。ADR 0257 で SIGTERM から送る理由にした、`claude` 自身の設定ファイルの書き込みは、`claude` が終わった後には起きない。
- 刈り取る前に送る。
  - 理由: 刈り取るまでは、グループの ID が別のプロセスに使い回されないので、ほかのプロセスを止めるおそれが無い。

## 検討した他の案

- 案: 残ったプロセスは止めず、出力の終わりも待たずに返す
  - 採用しなかった理由: 呼び出しのたびに孤児が残るおそれがある
- 案: 残ったプロセスにも、SIGTERM を送ってから 3 秒後に SIGKILL を送る
  - 採用しなかった理由: 残ったプロセスが無いときも含めて、終わったかを確かめる手段が無く、毎回 3 秒待つことになる

## 影響

- `claude` の子のプロセスが、`claude` が終わった後も動き続けることはできない。アプリは `claude` にツールを使わせないので、そのような子を要しない。
- 学習者のプログラムを動かす部品も、終わった後に同じグループに残ったプロセスを止めている（[コードの実行（run）](../spec/exercise-runner/run.md)「手順」）。`claude` でも、同じ扱いになる。
