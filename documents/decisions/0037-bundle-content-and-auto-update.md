## 背景

教材を修正・追加したときに、学習者の手元へ届ける方法が必要である。教材だけを配信するにはサーバーが必要になる。

## 決定

教材はアプリに同梱し、アプリの更新とともに更新する。配布物は GitHub Releases に置き、Tauri の自動更新機能で更新する（`non-functional.md`「配布と更新」）。

## 検討した他の案

- 案: 教材を同梱し、更新は学習者が手動でインストールする
  - 採用しなかった理由: 新しい教材や修正が学習者に届きにくい
- 案: 教材だけをサーバーから配信する
  - 採用しなかった理由: 配信用のサーバーと、教材とアプリのバージョンの整合を管理する仕組みが必要になる
- 案: 自前のサーバーに配布物を置く
  - 採用しなかった理由: GitHub Actions でビルドから公開まで自動化できる GitHub Releases の方が手間が少ない

## 影響

- 教材の修正だけでもアプリのリリースが必要になる。
- 自動更新のための署名鍵（OS のコード署名とは別）を管理する必要がある。
