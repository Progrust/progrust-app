## 背景

演習のコードは学習者の PC 上で、学習者の Rust ツールチェーンを使って実行する。macOS と Windows の両方で使えるサンドボックスを用意するのは難しく、Rust の標準ライブラリ（ファイル操作など）の学習も妨げる。

## 決定

学習者のコードは学習者のユーザー権限でそのまま実行する。AI が生成したコードを自動で実行する生成問題の検証では、指示文による制約と実行時間の制限で危険を抑える（`non-functional.md`「学習者のコードの実行」）。

## 検討した他の案

- 案: OS ごとのサンドボックス（macOS の sandbox-exec、Windows の AppContainer など）で実行する
  - 採用しなかった理由: OS ごとに実装が必要で、ファイル操作などを扱う演習が動かなくなる
- 案: コンテナや WebAssembly の環境で実行する
  - 採用しなかった理由: 学習者の環境に追加のソフトウェアが必要になる、または標準ライブラリの一部が使えない

## 影響

- 学習者が自分で書いたコードは、学習者が自分のターミナルで `cargo run` するのと同等のリスクとみなしている。
- AI が生成したコードについては、悪意のある、または危険なコードが生成される可能性をゼロにはできない。正式に公開する場合は見直す。
