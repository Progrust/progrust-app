## 背景

実装のループを 1 件だけ試しに回した（Issue #77）。実装する側の `claude` は、タスク #81 で `content/chapters.json` を作るために、一時的なスクリプト `tools/gen-chapters.tmp.ts` を作った。しかし、そのファイルを消せなかった。`rm` も `git clean` も許可されておらず、許可されていた `git rm` は、git に入っているファイルにしか使えない。`claude` は、中身を空にしたファイルを残した。レビューはこれを指摘して不合格にした。直す側も消せず、進められないと答えたので、ループは止まった（[ADR 0183](0183-stop-loop-when-blocked-by-permission-denials.md)）。

ループの `claude` の権限は、`dontAsk` と、許可する操作を書いたファイルで決める（[ADR 0161](0161-run-implementation-loop-locally-and-park-human-work.md)）。許可していない操作は、確認を待たずに拒否される。

## 決定

- 実装する側に、`git clean -f -- （パス）` を許可する。git に入っているファイルは、これまでどおり `git rm` で消す。決まりは [実装のループ](../conventions/implementation-loop.md)「権限」に定める。スキル `implement-task` に、一時的なファイルはなるべく作らず、作ったら消すこと、その消し方を書く。Claude が決めた。理由: `git clean` が消すのは、リポジトリの中の、git に入っておらず、無視の対象でもないファイルだけである。リポジトリの外のファイルと、`node_modules` のような無視の対象のファイルは消さない。`--` の後ろは、すべてパスとして読まれるので、無視の対象も消す `-x` などは付けられない。
- `rm` は許可しない。理由: 許可の書き方は、コマンドの先頭が合うかどうかで決まるので、`rm` を許可すると、どこのファイルでも消せる。

## 検討した他の案

- 案: `rm` を許可する。
  - 採用しなかった理由: 「決定」のとおり、消せる範囲を限れない。
- 案: 一時ファイルを、git に無視させるディレクトリに作らせ、消さなくてよいことにする。
  - 採用しなかった理由: 作った場所を間違えると、やはり消せない。ループの作業ツリーに、タスクをまたいでファイルが残る。
- 案: スクリプトが、コミットの前に、git に入っていないファイルを消す。
  - 採用しなかった理由: タスクで足したファイルと、消し忘れた一時ファイルを、スクリプトでは見分けられない。

## 影響

- 実装する側は、`git clean -f -- .` のように、作ったファイルをまとめて消すこともできる。消えるのは、タスクの作業ツリーの中で、まだコミットしていない新しいファイルだけである。消し過ぎたときは、機械のチェックとレビューで見つかる。
