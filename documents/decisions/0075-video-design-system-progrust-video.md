## 背景

スライドの中身の見た目は、画面とは別のデザインシステム「Progrust Slides」に定めていた（0047）。試作では、このデザインシステムの CSS（トークンと部品）をそのまま使えた。
動画の見た目をどこに定めるかと、動画で要る決まり（寄せ方、文字の最小サイズ、動きの種類と速さ、1 画面に載せる量）をどこに定めるかを決める必要があった。

## 決定

- 「Progrust Slides」を動画用に改め、名前を「Progrust Video」に変える。URL は変えない（`screens.md`「デザインシステム」）。
- 0047 の判断は引き継ぐ。動画の中身の見た目は画面とは別のデザインシステムに定め、値はそのデザインシステムを唯一の定義とし、画面と共通の値は「Progrust」を正とする。
- 寄せ方・文字の最小サイズ・動きの種類と速さ・1 画面に載せる量は、このデザインシステムの README に定め、仕様書は参照だけにする。
- 動画のデザインシステムの中の識別子（トークン名 `slide-*`、CSS クラス `.slide` など）も、動画の名前に変える。名前がそろい、実装で迷わない。
- 画面のデザインシステム「Progrust」の文言とプレーヤーの部品、画面デザインのキャンバスも、動画用に改める。
- ユーザーは、この提案への回答（「名前も変えてください。画面デザインのキャンバスも動画用に変えてください。その他も提案通りでお願いします。」）の理由として、「名前がスライドだとわかりにくい」「実装時に迷わないようにするため」の 2 つを挙げた。

## 検討した他の案

- 案: 動画用のデザインシステムを新しく作る
  - 採用しなかった理由: 試作で「Progrust Slides」のトークンと部品をそのまま使えた
- 案: 名前を「Progrust Slides」のままにする
  - 採用しなかった理由: ユーザーが挙げた 2 つの理由（「決定」を参照）
- 案: デザインシステムの中の識別子（トークン名 `slide-*`、CSS クラス `.slide` など）は、そのままにする（試作の CSS がそのまま使える）
  - 採用しなかった理由: 動画の中に slide という名前が残る

## 影響

- 仕様書は、動画のデザインシステムの README の「章カラーとの連動」「動画の原則」を参照する。
- 識別子を変えるので、試作で使った CSS は、識別子を書き換えないとそのままでは使えない。
- 0047 の影響（画面と共通の値が 2 か所にあり、「Progrust」を変えてから写しを合わせる）は、そのまま続く。
- スライドのデザインシステムを前提にした ADR（0048〜0051、0053〜0059）の扱いは 0076 で決めた。
