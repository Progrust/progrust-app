## 背景

教材を作り始めるには、章立てと学習順を決める必要があった。これまで仕様書では、章立ての内容を「作成者が別途用意する」として未決にしていた。

カリキュラムは 23 章・165 レッスン（うち章末復習レッスン 23）になり、章の分け方、レッスンの分け方、順序の 1 つ 1 つに理由を記録するのは手間に見合わない。

## 決定

- The Rust Programming Language（TRPL）を扱う内容の網羅の目安にし、章立て・順序・題材は独自に組み立てる（`curriculum.md`「方針」「章とレッスンの一覧」）。
- 理由: すでに一定の評価がある TRPL を網羅の目安にすることで、扱う内容が大きく外れた構成にはならないと考えたため。個々の章立て・レッスンの分け方・順序の理由は、この ADR にまとめ、個別には記録しない。
- TRPL の文章・コード・題材のプログラムは使わない（`curriculum.md`「方針」）。
- 理由: TRPL の文章や題材を使うと、このアプリの独自性がなくなるため。日本人の学習者に向けて、より良い書き方と題材にしたい。

### TRPL からの主な変更点

学習効率を優先して、TRPL の順序から次のように並べ替えた。

- パターンマッチ（TRPL 19 章）の基本を、列挙型の章（ch07）にまとめて前に出す。
- モジュール（TRPL 7 章）を、章末復習で複数ファイルの演習を使えるように、ジェネリクスより前（ch10）に置く。
- テスト（TRPL 11 章）を、以降の章で学習者が自分でテストを書いて確かめられるように、モジュールの直後（ch11）に置く。
- ジェネリクス・トレイトの言語機能（ch12）と、標準ライブラリのトレイトの使い方（ch13）を別の章にする。
- クロージャ（ch14）とイテレータ（ch15）を別の章にし、ライフタイム（ch16）より前に出す。
- 関連型・演算子のオーバーロード（TRPL 20 章）は、それぞれ ch12・ch13 で扱う。
- `Option`・`Result` のメソッド、独自のエラー型、`Box<dyn Error>`、エラー処理のクレートは、クロージャとトレイトオブジェクトを学んだ後の「エラー処理の発展」（ch19）で扱う。

### 扱わない内容

| 内容 | 理由 |
| --- | --- |
| Rust のインストール、rustup | アプリは導入手順の案内だけを表示する（0016）。レッスンにする内容がない |
| crates.io への公開、ワークスペース、`cargo install`、リリースプロファイル | 演習の判定に結びつかない。`Cargo.toml` はアプリが生成し、学習者は編集しない |
| 手続き的マクロ | `proc-macro` 用の別クレートが必要で、1 つのパッケージを組み立てる演習の仕組みでは作れない |
| FFI（`extern "C"`） | OS ごとにリンクされるライブラリが異なり、macOS と Windows で同じ演習にしにくい |
| ファイルの読み書き、環境変数、コマンドライン引数 | 演習は標準入力と標準出力（または隠しテスト）で判定するため |

## 検討した他の案

- 案: TRPL の章立てと順序をそのまま使う
  - 採用しなかった理由: 想定する学習者（0002）には、学習効率を優先して並べ替えたほうがよいため（上の「TRPL からの主な変更点」）
- 案: TRPL の文章・コード・題材を使う
  - 採用しなかった理由: アプリの独自性がなくなる。日本人の学習者に向けて、より良い書き方と題材にしたい
- 案: 章立て・レッスンごとに理由を ADR に記録する
  - 採用しなかった理由: レッスンの数が多く、記録の手間に見合わない

## 影響

- 個々のレッスンの配置の理由は記録に残らない。カリキュラムを変えるときは、`curriculum.md`「方針」と TRPL の網羅を基準に判断する。
- 23 章あるため、章カラーは ch13 から循環する（0040）。
- ch11 のテストの演習、ch19・ch21 の外部クレート、ch07-08 の let チェーン、ch01〜ch02 のテストケースの件数は、他の仕様の未決事項に依存している（`curriculum.md`「未決事項」）。
