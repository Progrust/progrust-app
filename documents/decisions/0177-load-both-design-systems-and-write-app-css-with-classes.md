## 背景

動画は、アプリの画面の中に、Remotion の Player で描く（[ADR 0061](0061-render-videos-with-remotion-player.md)）。レッスン専用の CSS はそのレッスンの動画の中に閉じ込める（[ADR 0093](0093-scope-lesson-css-with-build-time-prefix.md)）が、その逆向き、アプリの画面の CSS が動画の中にも効くことの扱いは、未決事項として残っていた。実装計画の M1 で、デザインシステムの CSS を読み込むために決める必要があった。

2026-11-23 に、デザインシステムの `components/bundle.css` を確かめたところ、次のとおりだった。

- 「Progrust」には、要素を指す土台の規則（`body`・`a`・`mark` と、フォーカスの枠）がある。ほかは `.pg-` で始まるクラスと、`data-chapter` の属性で書かれている。
- 「Progrust Video」には、要素を指す規則として `html`・`body` がある。ほかは `.video-stage` などのクラスと、`data-chapter` の属性で書かれている。
- 2 つの `tokens.css` は、どちらも `:root` と `data-theme` にトークンを書く。同じ名前のトークンが同じ値であることは、デザインシステムの検査で確かめている（[ADR 0155](0155-check-video-design-system-copied-tokens.md)）。

## 決定

- アプリは、2 つのデザインシステムの CSS を、どちらもアプリ全体に読み込む（[画面の見た目とテーマ](../spec/screens/appearance.md)「デザインシステムの CSS とアイコン」）。Claude が決めた。
  - 理由: 同じ名前のトークンは同じ値なので、両方を読み込んでも、画面の色と動画の色は食い違わない。動画ごとに CSS を読み込み分ける仕組みが要らない。
- アプリの画面のための CSS は、動画の枠の中の要素に当たらないように書く。要素を指すセレクタと、すべての要素に効くセレクタは、中に動画の枠を含まない部品のクラスの下でだけ使う。アプリの枠（`html`・`body`・`#root`）の大きさと余白の指定は書いてよい（[画面の見た目とテーマ](../spec/screens/appearance.md)「デザインシステムの CSS とアイコン」）。Claude が決めた。
  - 理由: 動画の枠を中に含む要素（画面全体など）の下で要素を指すと、動画の中の同じ要素にも当たる。部品のクラスの下に限れば、アプリの画面の CSS が動画の中に効かない。画面デザイン「Progrust UIデザイン」の見本の CSS には、画面全体のクラスの下で `p`・`h1` の余白を消す書き方があり、そのまま写すと動画の中に効く。
- デザインシステムの土台の規則（「Progrust」の `body`・`a`・`mark` とフォーカスの枠、「Progrust Video」の `html`・`body`）は、アプリの画面にも動画の中にも効くままにし、打ち消さない。Claude が決めた。
  - 理由: `html`・`body` の規則は、2 つのデザインシステムで同じトークンを使っている。`a`・`mark` の要素と、フォーカスできる要素は、動画の中では使わない（動画のマーカーは `mark` のクラスで書く。[動画の色の指定](../spec/content-format/video/colors.md)）。打ち消すには、デザインシステムの外に、デザインシステムの規則を上書きする CSS を書くことになる。

## 検討した他の案

- 案: 動画の枠の中で、アプリの画面の CSS を打ち消す（`all: revert` など）
  - 採用しなかった理由: 動画のデザインシステムの土台の規則まで打ち消すおそれがあり、打ち消す範囲の管理が要る。アプリの画面の CSS をクラスで書けば、打ち消すものが無い
- 案: 動画を Shadow DOM の中に描き、CSS を分ける
  - 採用しなかった理由: ADR 0093 で、Shadow DOM を使わないと決めている

## 影響

- アプリの画面の CSS を書くときは、画面全体のような、動画の枠を中に含む要素の下で、要素を指すセレクタを使えない。
- デザインシステムに、要素を指す規則を足すと、アプリの画面と動画の両方に効く。
