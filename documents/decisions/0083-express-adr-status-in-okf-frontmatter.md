- 関連仕様: [ADR の運用ルール](../conventions/decision-records.md)
- 置き換え: なし

## 背景

移行前の ADR は、タイトル行と本文の「状態」の行（採用、置き換え済み、廃止）を持ち、索引は ADR のディレクトリの README にあった。ADR を OKF v0.3 のバンドルに移すにあたり（0079）、OKF の concept として ADR の状態とタイトルをどう表すかを決める必要があった。

## 決定

- 状態は frontmatter で表す。「採用」は `status` を書かない（OKF では stable になる）。「置き換え済み」は `status: deprecated` と `superseded_by`（置き換えた ADR のパス）を書く。「廃止」は `status: deprecated` だけを書く。
- `title` は `ADR NNNN`、`description` は決定内容の一文（移行前のタイトル）にする。理由: 新しい文言を作らずに済む。
- 番号とファイル名は変えない。本文の「状態」の行は frontmatter に移して消し、「日付」「関連仕様」「置き換え」の行は本文に残す。関連仕様はリンクで書く。
- 「背景」「決定」「検討した他の案」は、これまでどおり書き換えない。移行で触ったのは、タイトル行と状態の行の frontmatter への移動と、関連仕様・置き換えの行のリンク化だけである。
- 索引は `decisions/index.md` に置き、関連仕様の先頭の仕様ごとに見出しで区切る。置き換え済み・廃止は末尾の見出しにまとめる。
- 以上は Claude の提案で、ユーザーが「すべて提案通りで大丈夫です。」「「決めてほしい点」もすべてあなたの推奨通りで問題ないので、この方針でドキュメントの整理をお願いします。」と承認した。

- なし

## 影響

- 古い ADR（0001〜0078）の本文は、移行前の文言のまま残る。本文に出る `qa-chat.md` のような名前は移行前の仕様書のファイル名で、いまは `spec/` の同じ名前のディレクトリに当たる。
- ADR の状態は、本文ではなく frontmatter の `status` と `superseded_by` を見て確かめる。
