手でメモリを管理すると起きる誤りを体験し、C がそれを防がないことと、誤りを避けるための取り決めを学ぶ

| ID | タイトル | 主に扱う内容 |
| --- | --- | --- |
| c03-01 | 未定義動作 | C の規格が結果を定めていないコードがあること、コンパイルが通って動いたように見えても正しいとは限らないこと、実行や環境によって結果が変わりうること、初期化していない変数とヒープの領域を読む誤り、コンパイラの警告が単純な場合しか見つけないこと、提出時のメモリの検査が見つけるものと見つけないもの |
| c03-02 | 範囲外アクセス | 配列の外を読み書きしても止まらないこと、隣の変数が書き換わる・異常終了する、要素数を 1 つ数え違える誤り、終端の `'\0'` の分を忘れる誤り、`strcpy`・`scanf("%s", ...)` によるバッファオーバーフローと安全上の問題 |
| c03-03 | 解放後の使用 | `free` した後もポインタにアドレスが残ること（ダングリングポインタ）、解放した領域が次の確保で使い回されること、解放後の読み書きで起きること、`free` の後に `NULL` を入れる習慣とその限界 |
| c03-04 | 二重解放 | 同じ領域を 2 回 `free` する誤り、2 つのポインタが同じ領域を指しているときに起きやすいこと、確保していない領域や領域の途中を `free` する誤り、`free(NULL)` は何もしないこと |
| c03-05 | メモリリーク | `free` を忘れる誤り、ポインタを上書きして領域への手がかりを失う誤り、エラーで早く戻る経路での解放漏れ、長く動くプログラムで起きること |
| c03-06 | 無効になるポインタ | `realloc` で領域が移ると古いポインタが無効になること、伸びる配列の要素を指すポインタを持ったまま要素を追加する誤り、指す先より長く生きるポインタという共通の形（c02-04・c03-03） |
| c03-07 | 浅いコピーと深いコピー | ポインタを持つ構造体を代入するとポインタだけがコピーされること、2 つの構造体が同じ領域を指して二重解放・解放後の使用になること、指す先まで複製する関数を書く |
| c03-08 | 誰が解放するのか | 確保した領域を解放する責任を誰が持つかの取り決め（所有）、ポインタを返す関数・受け取る関数の取り決め（渡したら相手が解放する、貸すだけで相手は解放しない）、取り決めがコメントにしか書けずコンパイラが確かめないこと、作る関数と壊す関数を対にする |
| c03-review | 章末復習 | |
