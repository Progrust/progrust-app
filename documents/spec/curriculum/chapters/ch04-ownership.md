Rust のメモリ管理の中心となる所有権の仕組みを学ぶ

| ID | タイトル | 主に扱う内容 | 主要素 |
| --- | --- | --- | --- |
| ch04-01 | メモリの仕組み | C の章で学んだスタックとヒープ（c02-04・c02-05）と、手でメモリを管理すると起きる誤り（c03）の振り返り、ガベージコレクションのある言語がその誤りをどう避けているか、Rust がガベージコレクションなしでこれらの誤りをコンパイル時に防ぐこと、そのための仕組み（所有権・借用・ライフタイム）をこの先の章で学ぶこと（動画のみのレッスン） | |
| ch04-02 | スコープと値の破棄 | 変数のスコープ、スコープの終わりで値が破棄されてメモリが解放される、C の `free` に当たる処理をコンパイラが入れるので `free` の書き忘れ（c03-05）が起きないこと | `ownership.scope_drop` |
| ch04-03 | String 型 | ヒープに置かれる文字列、`String` がスタックに持つポインタ・長さ・容量（c02-07 で作った伸びる配列と同じ形）、`String::from`、`push_str`、`format!`、文字列リテラルとの違い | `string.basic` |
| ch04-04 | 所有権のムーブ | 変数が値そのものを持つこと（Python・JavaScript の代入は同じオブジェクトの共有）、代入で所有権が移る、ムーブでコピーされるのはスタック上の部分だけであること（C の浅いコピーと同じ。c03-07）、元の変数を使えなくすることで二重解放（c03-04）を防ぐこと、ムーブ済みの値を使ったエラー | `ownership.move` |
| ch04-05 | clone と Copy | 明示的な深いコピー（C では自分で書いた。c03-07）、整数などがムーブされずにコピーされる理由 | `ownership.clone_copy` |
| ch04-06 | 関数と所有権 | 引数・戻り値での所有権の移動、C ではコメントで取り決めていた「誰が解放するのか」（c03-08）を、型とコンパイラが決めること | `ownership.function` |
| ch04-review | 章末復習 | | |
