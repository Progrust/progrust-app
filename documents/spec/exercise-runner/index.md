# コード実行・判定

* [コード実行・判定の目的とスコープ](scope.md) - コード実行・判定の仕様が扱う範囲と、判定方式とテストケースの形式の参照先を定める。
* [コード実行・判定の概要](overview.md) - `cargo` を使ったビルドと実行の前提、edition 2024 と dev プロファイル、実行・提出を同時に 1 つだけ行う制約、サンドボックスを使わないことを定める。
* [許可クレートと作業領域](crates-and-workspace.md) - 許可クレートの一覧（`runner/allowed-crates.toml`）と同梱の `Cargo.lock`、`workspace/` のディレクトリ構成とビルド先の分け方、アプリ起動時の初回準備の条件・手順・準備中や失敗時の動作、バックエンドが持つ初回準備の状態（`not_started`・`preparing`・`ready`・`failed`）、演習のビルドの失敗から初回準備のやり直しを判定する方法と、判定したときの実行・提出の扱いを定める。
* [実行・提出時のプロジェクトの組み立て](project-assembly.md) - 実行・提出のたびに作る `project/`（と生成問題の検証の `validate/`）の `Cargo.toml`・`Cargo.lock`・`src/**`・`tests/**` の内容と、受け付けるファイルパスの条件、`--offline` やビルド先などのビルド条件を定める。
* [コードの実行（run）](run.md) - 実行の手順、学習者が書いたテストを `cargo test` で動かすテスト実行の手順、ビルドの出力（コンパイラの診断と cargo 自身の標準エラー出力）の表示と送るとき、出力の送り方、停止のしかた、対話的な標準入力の扱い、結果の状態（`success`、`compile_error`、`runtime_error`、`timeout`、`stopped`、`crates_unavailable`）を定める。
* [コードの提出（submit）](submit.md) - 提出を学習者が途中で止められないこと、`stdout` 方式と `test` 方式それぞれの判定手順とテストケースの結果の決め方（`stdout` 方式で出力が一致しても終了コード 0 以外なら `runtime_error`、`test` 方式で隠しテストの入ったテスト実行ファイルの選び方）、`test` 方式で学習者が書いたテストを判定する手順、出力の正規化、判定結果の項目（`status`、`passed`、`total`、`cases[]`）と画面に表示する内容、判定をしなかった提出（`crates_unavailable`）と途中で止めた提出（`stopped`）の扱いを定める。
* [実行・判定の制限値](limits.md) - ビルド時間、実行時間（テスト実行を含む）、出力量、テストケースごとの実行時間と出力量、学習者のテストの判定の実行時間などの制限値と、超えた場合の扱いを定める。
* [実行・提出の試行ログへの記録](attempt-log.md) - 実行（テスト実行を含む）・提出が終わるたびに試行ログへ `run` / `submit` イベントを追記するときの、追記しない場合（`crates_unavailable`、途中で止めた提出、アプリの終了で止めた実行）と、`error_codes`、`stdout`、`stderr`、`stdin` の記録のしかたを定める。
* [コード実行・判定の受け入れ条件](acceptance.md) - コード実行・判定の仕様を満たしたと判断する条件を定める。
* [コード実行・判定の未決事項](open-questions.md) - コード実行・判定の仕様でまだ決まっていない事項（アプリの起動の後に `cargo` が見つかったときに初回準備を始めるか）を記す。
