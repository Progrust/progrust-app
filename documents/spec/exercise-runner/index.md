# コード実行・判定

* [コード実行・判定の目的とスコープ](scope.md) - コード実行・判定の仕様が扱う範囲と、判定方式とテストケースの形式の参照先を定める。
* [コード実行・判定の概要](overview.md) - Rust の演習を `cargo` で、C の演習を `clang` でビルド・実行する前提と、それぞれの手順の参照先、Rust の演習の edition 2024 と dev プロファイル、C の演習と Rust の演習を合わせて実行・提出を同時に 1 つだけ行う制約、サンドボックスを使わないことを定める。
* [許可クレートと作業領域](crates-and-workspace.md) - 許可クレートの一覧（`runner/allowed-crates.toml`）と同梱の `Cargo.lock`、`workspace/` のディレクトリ構成（C の演習の `c-project/` を含む）とビルド先の分け方、アプリ起動時と再検出のときの初回準備の条件・手順・準備中や失敗時の動作・アプリの終了のときの扱い、`prepared.json` の形、バックエンドが持つ初回準備の状態（`not_started`・`preparing`・`ready`・`failed`）、演習のビルドの失敗から初回準備のやり直しを判定する方法と、判定したときの実行・提出の扱いを定める。
* [実行・提出時のプロジェクトの組み立て](project-assembly.md) - Rust の演習の実行・提出のたびに作る `project/`（と生成問題の検証の `validate/`）の `Cargo.toml`・`Cargo.lock`・`src/**`・`tests/**` の内容と、受け付けるファイルパスの条件、`--offline` やビルド先などのビルド条件を定める。
* [コードの実行（run）](run.md) - Rust の演習の実行の手順、学習者が書いたテストを `cargo test` で動かすテスト実行の手順、ビルドの出力（コンパイラの診断と cargo 自身の標準エラー出力）の表示と送るとき、C の演習と共通の出力の送り方・停止のしかた・対話的な標準入力の扱い、結果の状態（`success`、`compile_error`、`runtime_error`、`timeout`、`stopped`、`crates_unavailable`）を定める。
* [コードの提出（submit）](submit.md) - Rust の演習の提出について、提出を学習者が途中で止められないこと、`stdout` 方式と `test` 方式それぞれの判定手順とテストケースの結果の決め方（`stdout` 方式で出力が一致しても終了コード 0 以外なら `runtime_error`、`test` 方式で隠しテストの入ったテスト実行ファイルの選び方）、`test` 方式で学習者が書いたテストを判定する手順、C の演習と共通の出力の正規化・判定結果の項目（`status`、`passed`、`total`、`cases[]`）と `detail` の形と画面に表示する内容、判定をしなかった提出（`crates_unavailable`）と途中で止めた提出（`stopped`）の扱いを定める。
* [C の演習の作業領域とビルド](c-project-assembly.md) - C の演習の実行・提出のたびに作る `c-project/` の置き場所と中身（`main.c`、実行ファイル `main`・`main-checked`、検査の報告とメモリリークの検査の結果のファイルを置く `reports/`、メモリリークの検査のライブラリを置く `leakcheck/`）、受け付けるファイルパス（`main.c` だけ）、検査なしと検査つきの `clang` のビルドとメモリリークの検査のライブラリのビルドのコマンドとオプション、ビルドの出力（`clang` の診断。色を付ける）の表示と送るとき、ビルド時間の制限、許可クレートの初回準備と `cargo` の有無に左右されないことを定める。
* [C のコードの実行（run）](c-run.md) - C の演習の実行の手順（検査なしでビルドし、`c-project/main` を起動する）、シグナルで終わったときにコンソールに出すシグナルの名前と意味の 1 行、実行ではメモリの検査をしないこと、テスト実行が無いこと、結果の状態（`success`、`compile_error`、`runtime_error`、`timeout`、`stopped`）を定める。
* [C のコードの提出（submit）](c-submit.md) - C の演習の提出の手順（検査なしと検査つきの 2 つのビルドとメモリリークの検査のライブラリのビルド、検査つきの実行ファイルでのテストケースの実行と `ASAN_OPTIONS`、メモリリークの検査のライブラリを `DYLD_INSERT_LIBRARIES` で差し込んだ検査なしの実行ファイルでのメモリリークの検査）、テストケースの結果の決め方（`memory_error` を含む）、メモリリークの検査のライブラリが数えるものと結果のファイル、検査の報告から `kind`・`location`・`report` を取り出す規則、メモリリークの検査のライブラリの作り方（バックエンドに埋め込んだソースを提出のたびに `clang` でビルドすること）と数えるものと結果のファイル、メモリリークの検査の起動がふつうに終わらなかったときの結果、判定結果の `cases[].status` の `memory_error` と `detail` の形（`kind` の一覧と日本語の名前、`location`、`report`）、画面に表示する内容を定める。
* [実行・判定の制限値](limits.md) - ビルド時間、実行時間（テスト実行を含む）、出力量、テストケースごとの実行時間と出力量、学習者のテストの判定の実行時間などの制限値と、超えた場合の扱いと、C の演習に当てる制限値（`clang` のビルド 1 回ごとのビルド時間、検査つきの実行ファイルの起動とメモリリークの検査の起動に別々に当てる 1 テストケースの実行時間）を定める。
* [実行・提出の試行ログへの記録](attempt-log.md) - 実行（テスト実行を含む）・提出が終わるたびに試行ログへ `run` / `submit` イベントを追記するときの、追記しない場合（`crates_unavailable`、途中で止めた提出、アプリの終了で止めた実行）と、`error_codes`、`stdout`、`stderr`、`stdin` の記録のしかたと、C の演習の記録（`files` のキーが `main.c`、`error_codes` が空、`stderr` に入れるもの、`memory_error` のテストケースの扱い）を定める。
* [コード実行・判定の受け入れ条件](acceptance.md) - コード実行・判定の仕様を満たしたと判断する条件を定める。
* [コード実行・判定の未決事項](open-questions.md) - コード実行・判定の仕様でまだ決まっていない事項（C の演習の提出で、`clang` の版が変わったときの検査の報告と警告の変化への対応）を記す。
