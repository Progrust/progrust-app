C の演習（[C の演習の作業領域とビルド](c-project-assembly.md)）の、演習画面の「実行」の手順を定める。出力の送り方・停止・対話的な標準入力は、Rust の演習と同じく [コードの実行（run）](run.md) の「出力の送り方」「停止」「対話的な標準入力」に従う。制限値は [実行・判定の制限値](limits.md)「C の演習」に従う。

## 手順

1. 検査なしのビルド（[C の演習の作業領域とビルド](c-project-assembly.md)「ビルド」）を行う。
2. ビルドに失敗したら、ビルドの出力（同じく「ビルドの出力の表示」）を表示して終了する（`compile_error`）。
3. 成功したら、`c-project/main` を、`c-project/` を作業ディレクトリとして、新しいプロセスグループで起動する。起動したら、標準入力を受け付けるようにしてから、`run_started` イベントを送る（[実行のコマンドとイベント](../architecture/commands/run.md)「イベント」）。
4. 標準出力・標準エラー出力を、[コードの実行（run）](run.md)「出力の送り方」のとおり `run_output` イベントで送る。
5. 学習者のプログラム（3 で起動したプロセス）が終了したら、[コードの実行（run）](run.md)「手順」の 5 と同じく、同じプロセスグループに残ったプロセスを止めて、実行を終える。
6. 学習者のプログラムがシグナルで終わったときは、「シグナルで終わったとき」の 1 行を送る。
7. 試行ログに `run` イベントを追記してから（[実行・提出の試行ログへの記録](attempt-log.md)）、`run_finished` イベントで結果を送る。

- ビルドに成功したときも、ビルドの出力（コンパイラの警告など）を表示する。
- ビルド中も停止ボタンで止められる。`clang` のプロセスグループ全体に SIGKILL を送り、結果を `stopped` とする。

## シグナルで終わったとき

学習者のプログラムが、自分の受けたシグナルで終わったときは、コンソールに、シグナルの名前と意味を 1 行で表示する。`run_output` の `system` の断片（[実行のコマンドとイベント](../architecture/commands/run.md)「イベント」）として、学習者のプログラムの出力を送り終えた後に送る。

| シグナル | 表示する 1 行 |
|---|---|
| `SIGSEGV` | シグナル SIGSEGV で終了しました（不正なメモリアクセス） |
| `SIGBUS` | シグナル SIGBUS で終了しました（不正なアドレスへのアクセス） |
| `SIGABRT` | シグナル SIGABRT で終了しました（異常終了。abort の呼び出しなど） |
| `SIGFPE` | シグナル SIGFPE で終了しました（算術演算の例外。整数の 0 での除算など） |
| `SIGILL` | シグナル SIGILL で終了しました（不正な命令） |
| ほかのシグナル | シグナル {名前} で終了しました |

- 名前の分からないシグナルは、名前の代わりにシグナルの番号を表示する。
- アプリが止めたとき（停止ボタン、実行時間の制限、出力量の上限、演習画面を離れたとき。[コードの実行（run）](run.md)「停止」）は、この 1 行を表示しない。

## メモリの検査をしないこと

- 実行では、メモリの検査（解放後の使用、範囲外アクセス、メモリリークなどの検査）をしない。C のそのままの動きで実行する。
- メモリの誤りがあるコードでも、エラーなしで終わったり、誤った値を出力したりすることがある。これは誤りとして扱わない。
- メモリの検査は、提出で行う（[C のコードの提出（submit）](c-submit.md)）。

## テスト実行が無いこと

- C の演習には、テスト実行（[コードの実行（run）](run.md)「テスト実行」）が無い。`run_code` の `mode` は `main` だけを受け付ける（[実行のコマンドとイベント](../architecture/commands/run.md)「run_code」）。
- 演習画面の「テスト」ボタンとショートカットの扱いは [演習画面](../screens/exercise-screen.md) に従う。

## 結果の状態

結果の状態は、[コードの実行（run）](run.md)「結果の状態」の表のうち、`success`・`compile_error`・`runtime_error`・`timeout`・`stopped` とする。意味も同じである。`crates_unavailable` は起きない。
