## C の演習の提出

[C のコードの提出（submit）](c-submit.md) について、次のことが決まっていない。技術検証で決める。

- 検査の報告（`reports/` の、名前が `case-{N}.` で始まるファイル）から、`detail` の `kind`（誤りの種類）と `location`（`main.c` の行）と `report`（報告の先頭）を取り出す具体的な方法。報告の書式に頼ることになる。報告のスタックに `main.c` の行が複数あるときに、どの行を `location` にするかを含む。
- メモリリークの検査のライブラリ（[C のコードの提出（submit）](c-submit.md)「メモリリークの検査」）の作り方と置き方。アプリにビルド済みのものを同梱するか、同梱したソースを学習者の `clang` でビルドするか、対応する CPU の種類、ライブラリのファイル名、結果のファイルのパスを渡す環境変数の名前、記録できる領域の数の上限（上限を超えたときの扱いを含む）を決める。教材チェックツールの判定（[教材チェックツール](../content-guidelines/check-tool.md)。判定のプログラムはアプリの `.app` に入らない）でのライブラリの置き方と、ライブラリを用意できなかったとき（ファイルが無い、ビルドに失敗した など）の扱いを含む。
- メモリリークの検査の起動（[C のコードの提出（submit）](c-submit.md)「手順」の 4）が、終了コード 0 以外で終わったとき、シグナルで終わったとき、結果のファイルができなかったとき、結果のファイルを読めなかったときの、テストケースの結果と、提出をアプリの側の失敗として終えるかどうか。
- Command Line Tools の更新で `clang` の版が変わったときの、検査の報告の書式の変化と、警告（`-Wall -Wextra`）の出方の変化への対応。Intel の Mac と、ほかの版の macOS は、対応環境の外である（[対応環境](../non-functional/environments.md)）。
