## 手順

1. `cargo build --offline --message-format=json-diagnostic-rendered-ansi` を、新しいプロセスグループで起動してビルドする。
2. ビルドに失敗したら、コンパイラの診断を表示して終了する（`compile_error`）。
3. 成功したら、生成された実行ファイルを `project/` を作業ディレクトリとして、新しいプロセスグループで起動する。
4. 標準出力・標準エラー出力を、「出力の送り方」のとおり `run_output` イベントで送る。
5. 学習者のプログラム（3 で起動したプロセス）が終了したら、同じプロセスグループに残ったプロセスを止める（「停止」）。その後に届く出力は最大 300ms だけ待って受け取り、実行を終える。パイプの終わり（EOF）は待たない。
6. `run_finished` イベントで結果を送り、試行ログに `run` イベントを追記する（[実行・提出の試行ログへの記録](attempt-log.md)）。

- 演習には必ず `src/main.rs` があるものとする（[演習のファイル形式](../content-format/exercise.md)「ファイル」）。
- コンパイラの警告も表示する。cargo 自身の進捗メッセージ（`Compiling ...` など）は表示しない。

## 出力の送り方

- 標準出力と標準エラー出力は、別々のパイプで受け取る。そのため、両者の前後関係は、プログラムが書いた順と違って表示されることがある。
- 受け取った出力は、16〜50ms ごとに、その間に受け取った分をまとめて 1 つの `run_output` イベントで送る。1 つのイベントには、stdout / stderr / system の断片を受け取った順に入れる。
- 改行で終わらない出力も、改行を待たずに送る。UTF-8 の文字の途中で切れたバイトだけは、次に受け取った分に持ち越す。

## 停止

- 停止ボタン、実行時間の制限、出力量の上限（[実行・判定の制限値](limits.md)）で止めるときは、学習者のプログラムのプロセスグループ全体に SIGKILL を送る。学習者のプログラムが作った子プロセスも、同じプロセスグループにいれば止まる。
- 学習者のプログラムが、自分で別のプロセスグループやセッションに移した子プロセスは止めない。
- 停止ボタンと実行時間の制限で止めたときは、まだ `run_output` で送っていない出力を送らずに捨てる。
- ビルド中も停止ボタンで止められる。cargo のプロセスグループ全体（cargo が起動した rustc を含む）に SIGKILL を送り、結果を `stopped` とする。

## 対話的な標準入力

- 実行中、コンソールの下部に入力欄を表示する。
- Enter で入力した 1 行に改行を付けてプログラムの標準入力に送り（`send_stdin`）、コンソールにも入力として区別できる色で表示する。
- 「入力終了」ボタン（または Ctrl+D）で標準入力を閉じる（`close_stdin`）。
- プログラムが終了したら入力欄を無効にする。

## 結果の状態

| 状態 | 条件 |
|---|---|
| `success` | 終了コード 0 で終了した |
| `compile_error` | ビルドに失敗した |
| `runtime_error` | 終了コードが 0 以外、またはシグナルで終了した（panic を含む）。出力量の上限を超えて停止した場合も含む |
| `timeout` | 制限時間を超えたため停止した |
| `stopped` | 学習者が停止ボタンを押した（ビルド中を含む） |
