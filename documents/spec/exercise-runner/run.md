## 手順

1. `cargo build --offline --quiet --message-format=json-diagnostic-rendered-ansi` を、新しいプロセスグループで起動してビルドする。
2. ビルドに失敗したら、ビルドの出力（「ビルドの出力の表示」）を表示して終了する（`compile_error`）。ただし、失敗が [許可クレートと作業領域](crates-and-workspace.md)「初回準備のやり直しが要る失敗」に当てはまるときは、ビルドの出力を表示せずに終了する（`crates_unavailable`）。
3. 成功したら、生成された実行ファイルを `project/` を作業ディレクトリとして、新しいプロセスグループで起動する。起動する実行ファイルは、1 のビルドの標準出力の JSON のうち、`reason` が `compiler-artifact` で、`profile.test` が `false` で、`target.kind` に `bin` があり、`target.src_path` が `project/src/main.rs` であるものの `executable` とする。`src/bin/` に置いたファイルの実行ファイルは起動しない。見つからないときは、アプリの側の失敗（[実行のコマンドとイベント](../architecture/commands/run.md)「イベント」の `run_finished` の `error`）として終える。
4. 標準出力・標準エラー出力を、「出力の送り方」のとおり `run_output` イベントで送る。
5. 学習者のプログラム（3 で起動したプロセス）が終了したら、同じプロセスグループに残ったプロセスを止める（「停止」）。その後に届く出力は最大 300ms だけ待って受け取り、実行を終える。パイプの終わり（EOF）は待たない。
6. 試行ログに `run` イベントを追記してから（[実行・提出の試行ログへの記録](attempt-log.md)）、`run_finished` イベントで結果を送る（[実行のコマンドとイベント](../architecture/commands/run.md)「イベント」）。`crates_unavailable` のときは、`run_finished` イベントは送るが、試行ログには追記しない。

- 演習には必ず `src/main.rs` があるものとする（[演習のファイル形式](../content-format/exercise.md)「ファイル」）。
- ビルドに成功したときも、ビルドの出力を表示する（コンパイラの警告など）。

## テスト実行

学習者が書いたテスト（単体テスト、`tests/` の統合テスト、ドキュメントテスト）を、演習画面の「テスト」ボタンで実行する。どの演習でも使える。隠しテストは組み込まない。

1. `cargo test --offline --quiet --no-run --message-format=json-diagnostic-rendered-ansi` を、新しいプロセスグループで起動してビルドする。
2. ビルドに失敗したら、実行の手順の 2 と同じく終了する（`compile_error` または `crates_unavailable`）。
3. 成功したら、`cargo test --offline --no-fail-fast` を、`project/` を作業ディレクトリとし、環境変数 `CARGO_TERM_COLOR=always` を付けて、新しいプロセスグループで起動する。
4. 3 の cargo の標準出力・標準エラー出力を、そのまま `run_output` イベントで送る。cargo が出す `Running ...`・`Doc-tests ...` などの行と、テストごとの結果の行（`test {名前} ... ok` など）も表示する。
5. 3 の cargo が終了したら、実行の手順の 5 と同じく、同じプロセスグループに残ったプロセスを止めて実行を終える。
6. 試行ログに `run` イベント（`mode` は `test`）を追記してから（[実行・提出の試行ログへの記録](attempt-log.md)）、`run_finished` イベントで結果を送る。`crates_unavailable` のときの扱いは、実行の手順の 6 と同じにする。

- 出力の送り方と停止は、実行と同じにする（「出力の送り方」「停止」）。制限値も実行と同じにする（[実行・判定の制限値](limits.md)）。
- 標準入力は、3 で起動した直後に閉じる。入力欄は表示しない。
- 結果の状態は「結果の状態」の表に従う。テストが 1 件でも失敗すると、cargo の終了コードが 0 以外になるので `runtime_error` になる。ドキュメントテストのコンパイルエラーは、1 では見つからず、3 でそのテストの失敗として出る。

## ビルドの出力の表示

ビルドの出力として、次の 2 つを表示する。

- コンパイラの診断: cargo の標準出力の JSON のうち、`compiler-message` の診断。エラーも警告も表示する。
- cargo 自身の標準エラー出力: そのまま表示する。`--quiet` を付けているので、cargo は進捗メッセージ（`Compiling ...`・`Finished ...` など）と、`Cargo.toml` の読み込みについての警告を出さない。cargo 自身のエラー（`error: could not compile ...` の行、cargo の設定ファイルを読み込めないときのエラーなど）と、cargo の lint の警告は出る。

ビルドの出力は、ビルド中には送らない。ビルドの cargo が終わり、結果が決まってから送る。

- ビルドに成功したときと、`compile_error` のときは、ビルド中に受け取った出力を、受け取った順に `run_output` イベントで送る。送り方は「出力の送り方」に従う。
- `crates_unavailable` のときは、送らずに捨てる（「手順」の 2）。
- ビルド中に停止ボタンで止めたときは、送らずに捨てる（「停止」）。
- ビルド時間の制限（[実行・判定の制限値](limits.md)）で中断したときは、`compile_error` として、中断するまでに受け取った出力を送り、続けてタイムアウトの旨を送る。

## 出力の送り方

- 標準出力と標準エラー出力は、別々のパイプで受け取る。そのため、両者の前後関係は、プログラムが書いた順と違って表示されることがある。
- 受け取った出力は、16〜50ms ごとに、その間に受け取った分をまとめて 1 つの `run_output` イベントで送る。1 つのイベントには、stdout / stderr / system の断片を受け取った順に入れる。
- ビルドの出力は、ビルドが終わってから送る（「ビルドの出力の表示」）。
- 改行で終わらない出力も、改行を待たずに送る。UTF-8 の文字の途中で切れたバイトだけは、次に受け取った分に持ち越す。

## 停止

- 停止ボタン、実行時間の制限、出力量の上限（[実行・判定の制限値](limits.md)）で止めるときは、学習者のプログラムのプロセスグループ全体に SIGKILL を送る。学習者のプログラムが作った子プロセスも、同じプロセスグループにいれば止まる。
- 学習者のプログラムが、自分で別のプロセスグループやセッションに移した子プロセスは止めない。
- 停止ボタンと実行時間の制限で止めたときは、まだ `run_output` で送っていない出力を送らずに捨てる。
- ビルド中も停止ボタンで止められる。cargo のプロセスグループ全体（cargo が起動した rustc を含む）に SIGKILL を送り、結果を `stopped` とする。
- 実行・テスト実行の途中で演習画面を離れたとき（[演習画面](../screens/exercise-screen.md)）も、停止ボタンと同じく止め、結果を `stopped` とする。試行ログへの記録も停止ボタンと同じにする。
- アプリを終了したときは、動いている実行・テスト実行を同じ方法で止める。このときは `run_finished` を送らず、試行ログに追記しない。提出の扱いは [コードの提出（submit）](submit.md)「途中で止めた提出」に従う。

## 対話的な標準入力

- 実行中、コンソールの下部に入力欄を表示する。
- Enter で入力した 1 行に改行を付けてプログラムの標準入力に送り（`send_stdin`）、コンソールにも入力として区別できる色で表示する。
- 「入力終了」ボタン（または Ctrl+D）で標準入力を閉じる（`close_stdin`）。
- プログラムが終了したら入力欄を無効にする。

## 結果の状態

| 状態 | 条件 |
|---|---|
| `success` | 終了コード 0 で終了した |
| `compile_error` | ビルドに失敗した |
| `runtime_error` | 終了コードが 0 以外、またはシグナルで終了した（panic を含む）。出力量の上限を超えて停止した場合も含む |
| `timeout` | 制限時間を超えたため停止した |
| `stopped` | 学習者が停止ボタンを押した（ビルド中を含む） |
| `crates_unavailable` | ビルドの失敗が [許可クレートと作業領域](crates-and-workspace.md)「初回準備のやり直しが要る失敗」に当てはまった。学習者のコードは実行していない |

テスト実行では、「終了」は 3 で起動した cargo の終了を指す。
