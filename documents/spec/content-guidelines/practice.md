Rust のレッスン（動画・演習・解説）と生成問題に当てはめる。C の章には当てはめない。C の章は、C を使えるようになるためではなく、Rust を深く理解するために学ぶからである（[C の章の教材の作成ルール](c-lessons.md)）。

## 伝えること

- 書き方を教えるときは、実務での使われ方も伝える。よく使われる場面、実務で避ける書き方とその理由、同じことをする書き方が複数あるときにどれがよく使われるか、である（例: 「`unwrap` は、失敗しないと分かっているところと、試しに書くコードで使います。実務のコードでは、失敗したときの扱いを書くことが多いです」）。
- 演習の題材の決まりは [演習の作成ルール](exercise.md)「問題」「解説」に定める。

## 根拠

- 「実務では」「コミュニティでは」と言うのは、根拠のある内容だけにする。根拠にするのは、次のものである。
  - TRPL（The Rust Programming Language）、標準ライブラリのドキュメント、Rust API Guidelines
  - Clippy の既定の警告（lint）と、rustfmt の既定の書式
- 動画では、根拠にした資料を台本の `ai_note` に書く。質疑応答の AI が、根拠を示して答えられるようにするためである。
- 意見が分かれている書き方は、分かれていることと、それぞれの理由を伝える。一方だけを正しい書き方のように言わない。
- 古い書き方（以前の edition の書き方、非推奨になった API）は、教材のコードに使わない。触れるときは、古い書き方であることを言う。

## 教材のコード

- 模範解答と動画のコードは、rustfmt の既定の書式にし、Clippy の既定の警告が出ないようにする。ただし、誤りや避ける書き方を見せるためのコードは除く。
- 実務での書き方が未学習の要素を使うときは、そのコードを載せず（[未登場の要素を使わない](no-unseen-elements.md)）、言葉で触れて、どのレッスンで学ぶかを伝える（例: 「実務では、エラーを呼び出し元に返す書き方をよく使います。9-3 で学びます」）。
