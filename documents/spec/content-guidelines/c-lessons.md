C の章（[カリキュラムの方針](../curriculum/policy.md)「C の章と Rust の章」）の教材は、[動画の作成ルール](video.md)・[演習の作成ルール](exercise.md) などのほかの決まりに加えて、次の決まりに従う。

## 目的と説明の深さ

- C の章の教材は、Rust を深く理解するための土台として作る。学習者が、C のメモリの扱いを自分の手で試して理解できることを目指す。
- Rust の学習アプリであることを理由に、C の説明を短くまとめない。そのレッスンの「主に扱う内容」（[章とレッスンの一覧](../curriculum/chapters/index.md)）を、C として正確に、丁寧に説明する。
- 学習者に C の経験はない前提で説明する（[想定する学習者](target-learner.md)）。
- メモリの上で起きていること（変数の置き場所、ポインタが指す先、確保と解放）は、図で示す（[動画の作成ルール](video.md)「図」）。

## C の規格とコンパイラ

- C17 の範囲で書く。コンパイラは Apple の clang（macOS）を前提とする。ビルドのオプションは [C の演習の作業領域とビルド](../exercise-runner/c-project-assembly.md) に従う。
- コンパイラの独自の拡張は使わない。
- 動画に載せるコードと、演習の初期コード・模範解答は、ビルドで警告が出ないように書く。誤りや警告そのものを見せるためのコードと、誤りを直させる演習の初期コードは除く。

## 既習の内容だけを使う

- C のレッスン（動画・演習・解説）には、そのレッスンと、学習順でそれより前の C のレッスンの「主に扱う内容」（[章とレッスンの一覧](../curriculum/chapters/index.md)）にある C の構文・関数・型だけを登場させる。
- C のレッスンは要素を持たないので、教材チェックツールはこれを検証しない。レビュー時にチェックリスト（[教材レビューのチェックリスト](review-checklist.md)）で確認する。
- どうしても未学習の構文が必要な場合の書き方は、[未登場の要素を使わない](no-unseen-elements.md) と同じとする（おまじないとして使うことと、どのレッスンで学ぶかを明記し、`starter/` に完成した形で用意する）。

## Rust に触れるとき

- C のレッスンの動画には、Rust のコードを登場させない。Rust ではどうなるかは、言葉で予告するだけにし、どこで学ぶかを添える（例: 「この誤りを Rust がどう防ぐかは、所有権の章で学びます」）。
- c01-01 の動画だけは、Rust のコンパイラが誤りを指摘する様子を見せるために、Rust のコードとコンパイラの出力を載せてよい。コードを読めることは前提にせず、何が起きているかをナレーションで説明する。
- 演習の問題文と解説には、Rust のコードを書かない。

## 動画

- コンパイラの出力（clang の診断）、プログラムの実行結果、メモリの検査の報告には、実際に得た出力を使う。説明に使わない行は省いてよい。載せる行は書き換えない。
- メモリの誤りを見せるときは、メモリの検査なしで実行した結果（エラーなしで誤った値が出る、異常終了する など）と、メモリの検査の報告（[C のコードの提出（submit）](../exercise-runner/c-submit.md)）の両方を見せる。
- 未定義動作の結果は、環境や実行のたびに変わりうる。結果を見せるときは、ある環境でのある 1 回の結果であることを、ナレーションか画面の文で伝える。
- アドレスの値は実行のたびに変わる。図の中のアドレスは、短い値（`0x1000` など）に置き換えてよい。

## 演習

- [演習の作成ルール](exercise.md) に従う。そこでの「主要素」は、そのレッスンの「主に扱う内容」と読み替える。
- 演習は、メモリの動きを学習者が自分の手で試す形にする。次の形を使う。
  - 誤りのあるコードを直す。初期コードは、実行するとエラーなしで動いたように見えても、提出するとメモリの検査で誤りが見つかるものにしてよい。
  - 途中まで書かれたコードを完成させる（確保・解放・コピーなどを学習者が書く）。
  - 仕様を満たすプログラムを一から書く。
- c03 の各レッスンの演習は、そのレッスンで扱う誤りを、学習者が実行と提出で体験できるものにする。
- 判定は、標準出力の比較とメモリの検査で行う（[C のコードの提出（submit）](../exercise-runner/c-submit.md)）。出力は、実行のたびに同じになるものにする。アドレスの値（`%p`）、初期化していない変数や領域の値、未定義動作の結果を出力させない。
- 模範解答は、すべてのテストケースで、メモリの検査で誤りが報告されないものにする（教材チェックツールで検証する）。メモリリークも誤りなので、確保した領域は、プログラムが終わる前にすべて解放する。
- テストケースは 3 件以上用意する。ただし、標準入力を学ぶ前の c01-02〜c01-04 の演習は、入力のない、出力が固定の演習にし、1 件以上でよい。
- 章末復習レッスンは、通常のレッスンより難易度を上げ、その章の複数のレッスンの内容を組み合わせる問題にする。主要素は持たない。
- 解説の「ポイント」には、そのレッスンの「主に扱う内容」がどう使われているかを書く。
- 解説の「よくある間違い」には、そのレッスンの内容で起きやすい誤りと、そのときのコンパイラの警告・実行結果・メモリの検査の報告を書く。
