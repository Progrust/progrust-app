# 技術検証の結果

* [Remotion Player の WebView での動作と性能の技術検証](issue-1-remotion-player-webview.md) - Remotion Player が Tauri の WKWebView で動き、再生開始 300ms・シーク 200ms の目安を満たすかを Issue #1 で検証した結果（ページ自身が計測して Tauri のコマンドで書き出す方法、再生開始とシークの表、1 倍と 2 倍の通しの再生のコマ落ち、AudioDecoder を消してまねた macOS 13 の状態、2 倍速で 1 フレームずつ飛ぶこと、再生中のシークの後の停止、それらを人が見て問題ないとした判断）を記す。
* [1 文 1 ファイルの音声の再生と同期の技術検証](issue-2-m4a-audio-sync.md) - 1 文 1 ファイルの .m4a を Player の中で同期して再生できるかを Issue #2 で検証した結果（@remotion/media の Audio と Html5Audio の動作、音声と絵のずれの表、0.75〜2 倍速での声の高さ、AAC の前後の無音と durations.json の seconds の食い違い、@remotion/media が文の頭で音を二重に鳴らすこと、人が聞いて Html5Audio を選び、許せるずれの量を数値で決めないとした判断）を記す。
* [独自のプレーヤー操作を Player の API で作れるかの技術検証](issue-3-player-custom-controls.md) - Remotion Player の外に動画画面の操作（再生位置の取得と変更、文ごとの移動、5 秒のスキップ、シークバーのシーンの印、枠の外の字幕、文の単位での位置の保存、Space・←→・Shift+←→ のキー操作）を作れるかを Issue #3 で検証した結果（自動確認 21 項目、キー操作の衝突を避ける controls={false} と spaceKeyToPlayOrPause={false}、合成イベントでの確認の限界）を記す。
* [レッスンごとの動画の遅延読み込みの技術検証](issue-4-lazy-load-lesson-video.md) - レッスンごとに動画のコード・音声・画像を遅延読み込みできるかを Issue #4 で検証した結果（Vite のプラグインで作るレッスンごとの仮想モジュール、塊の一覧、tauri:// で配信されたファイルの記録、音声の置き方 2 通りの比較、tauri:// が Range に 200 で全体を返すこと、ユーザーが音声の置き方を asset:// に決めた判断）を記す。
* [レッスン専用の CSS の閉じ込め方の技術検証](issue-5-scope-lesson-css.md) - レッスン専用の CSS をそのレッスンの動画の中に閉じ込める 5 つの候補（そのまま・CSS Modules・@scope・ビルド時の接頭辞・Shadow DOM）を Issue #5 で検証した結果（候補ごとの閉じ込めの結果の表、デザインシステムの CSS が効くこと、macOS 13 の WebKit の対応表、ユーザーがビルド時の接頭辞に決めた判断）を記す。
* [再生中のテーマと章カラーの切り替えの技術検証](issue-6-switch-theme-during-playback.md) - アプリのテーマと章カラーを Player の中の動画まで届け、再生を止めずに切り替えられるかを Issue #6 で検証した結果（CSS 変数の継承・inputProps・毎回新しい inputProps の 3 通りの渡し方の比較表、フレーム・音・色の変化、Shadow DOM では章カラーが祖先の属性で変わらないこと、人の目での確認が未実施であること）を記す。
* [動画の描画チェックを CI で実行できるかの技術検証](issue-7-render-check-in-ci.md) - 教材チェックツールの動画の描画チェックと禁止事項の lint が CI で実行できるかを Issue #7 で検証した結果（画面なしの描画とエラー検出、GitHub Actions の ubuntu-latest での実行と所要時間、ネットワークなしでの実行、Studio・チェックツール・Vite の 3 か所で同じコードが動くこと、ESLint と stylelint による禁止事項の検出と限界、ユーザーが Claude の推奨に任せた lint の範囲と CI で検査するレッスンの範囲の判断）を記す。
* [claude -p の隔離起動の技術検証](issue-8-claude-isolated-invocation.md) - claude -p を、ユーザー設定を読み込まず、ツールを使わせず、学習者のログイン状態のまま起動できるかを Issue #8 で検証した結果（フラグの組み合わせごとの効き方、--bare が OAuth を読まないこと、ツール無効の確認、設定ディレクトリに残るもの、推奨のフラグと再実行の 1 行のコマンド、ユーザーレベルの CLAUDE.md が読まれないことの追加の確認、--system-prompt で置き換えたときの追加の確認、ユーザーが Claude の推奨を承認した判断）を記す。
* [claude -p の出力の形とエラーの見分け方の技術検証](issue-9-claude-output-and-errors.md) - claude -p の json 出力から回答の本文を取り出せるか、stream-json で回答を少しずつ表示できるか、未ログインとモデル指定の誤りで終了コードと出力がどうなるかを Issue #9 で検証した結果（subtype が success のままになること、分類コードは stream-json にだけ出ること、エラーの文が標準出力に出ること、利用上限は未再現、ユーザーが Claude の推奨を承認した判断）を記す。
* [claude -p の子プロセスとしての扱いの技術検証](issue-10-claude-child-process.md) - claude -p を子プロセスとして扱えるかを Issue #10 で検証した結果（50 KB の日本語の標準入力、質疑応答とジョブの同時呼び出し、プロセスグループへの kill での子・孫プロセスの停止、Finder から起動したアプリでの claude の検出と認証、npm・Homebrew の探索先が決まっていないこと）を記す。
* [AI の応答時間と出力の安定性の技術検証](issue-11-ai-timing.md) - 記録・分析・問題生成・質疑応答の claude -p 呼び出しが制限時間に収まるか、質疑応答で最初の文字が出るまでの時間、生成した問題が検証に通る割合、記録・分析の出力が形式を守るかを Issue #11 で検証した結果（制限時間はすべて収まり、分析は 142 要素で 214.8 秒、検証は 14 問すべてが修正 2 回以内、pattern ラベルは新しい種類で揺れた）と、試作した指示文 6 本、ユーザーが割合の目安を 90 % 以上とし、その他を Claude の推奨に任せた判断を記す。
* [許可クレートのビルド結果の共有の技術検証](issue-12-reuse-prepared-crates.md) - 初回準備でビルドした許可クレートを、各演習が作り直さずに使えるかを Issue #12 で検証した結果（rand だけの今の一覧では作り直しなし、10 クレートの想定の一覧では feature の違いによる作り直し、Cargo.lock の不一致がエラーにならないこと、空のライブラリへの path 依存で作り直しがなくなること、空の main.rs で warmup が失敗すること、ユーザーが Claude の推奨に任せて案 b にした判断）を記す。
* [検証と学習者の実行の並行ビルドの技術検証](issue-13-parallel-build-lock.md) - 問題生成の検証と学習者の実行が互いを待たせずに並行できるかを Issue #13 で検証した結果（同じビルド先でのロックの待ち、同じパッケージ名で相手の実行ファイルを使ってしまう誤り、初回準備中のパッケージキャッシュのロック、APFS のクローンなどでビルド先を分ける方法の比較、ユーザーが Claude の推奨に任せてビルド先を分けた判断）を記す。
* [隠しテストを読み込む #[path] の解決の技術検証](issue-14-hidden-test-path-resolution.md) - 隠しテストを読み込む `#[path]` が `judge.target` の場所によらず解決されるかを Issue #14 で検証した結果（`../` の数の決め方、絶対パス案、テスト名へのモジュール経路の付加、`use super::*;` の基準、`judge.target` が `src/` 直下に限られるので仕様の値を変えなかった判断）を記す。
* [test 方式のテスト結果の読み取りの技術検証](issue-15-test-result-parsing.md) - test 方式の libtest の出力からテストごとの結果と panic メッセージを確実に読み取れるかを Issue #15 で検証した結果（出力形式、学習者の出力との混合、process::exit・abort・無限ループ、10 秒の制限での打ち切り、1 回起動する方式とテストごとに別プロセスで実行する方式の比較、テストごとに別プロセスで実行すると決めた判断）を記す。
* [学習者のプログラムの子プロセスとしての扱いの技術検証](issue-16-learner-process.md) - 学習者のプログラムを子プロセスとして扱えるかを Issue #16 で検証した結果（標準出力・標準エラー出力の受け取り、標準入力の送信と閉じ方、プロセスグループへの killpg による停止、1MB の出力量の上限、run_output イベントの送り方と表示量の上限、グループから抜けた子が残ること、停止の範囲・出力の送り方・コンソールの表示量の上限・flush を教えるレッスンを決めた判断）を記す。
* [ビルドの時間と初回準備のやり直しの技術検証](issue-18-build-time.md) - 実行のたびに project/ を作り直すときのアプリ側の処理時間、--offline のビルドが失敗する状態ごとの終了コードと stderr の文、cargo のキャッシュ自動削除（gc）が既定で有効なこと、許可クレートを増やしたときの初回準備の時間とディスク使用量を Issue #18 で検証した結果と、ユーザーが Claude の推奨に任せた初回準備のやり直しの条件の判断を記す。
* [署名なしの macOS アプリの自動更新の技術検証](issue-19-updater-unsigned-macos.md) - 署名なしの macOS アプリで Tauri の自動更新が動くかと、GitHub Actions でのビルドと Releases への公開、Windows インストーラーの WebView2 導入処理を Issue #19 で検証した結果（App Translocation されると更新が失敗すること、quarantine 属性の値ごとの結果、private リポジトリの Releases を認証なしで取れないこと、ad-hoc 署名の有無による違い）を記す。
