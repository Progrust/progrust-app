代入すると、所有権が移る

fn main() {    let s1 = String::from("hi");    let s2 = s1;}
所有権が移ることを、ムーブと呼びます。

このレッスンのまとめ

  • 関数に渡すと、String の所有権は引数に移る（ムーブ）
  • 渡したあとの元の変数を使うと、ムーブ済みの値を使ったエラーになる
  • 戻り値で返すと、所有権は呼び出し側に移る
  • i32 のようにコピーされる型は、渡したあとも元の変数を使える

このレッスンのまとめ

  • 値は、スタックかヒープに置かれる
  • 関数を呼ぶたびにスタックフレームが作られ、戻ると消える
  • Rust には、ガベージコレクションがない
  • メモリを手で解放する言語では、二重解放や解放後の使用が起きる

もし s1 と s2 の両方が所有者だとすると、スコープの終わりで、同じメモリを 2 回解放してしまいます。

i32 のようにコピーされる型は、代入しても元の変数を使えます。
