## 問題

通信に失敗したときの、再試行の待ち時間を決めるプログラムを、2 つのモジュールに分けて完成させてください。

多くのクライアントが同じ時刻に再試行すると、サーバーに通信が集中します。これを避けるために、実務では、待ち時間にランダムなばらつき（ジッター）を付けることがよくあります。

初期コードには、待ち時間を 1 つ決める `jitter` モジュールと、再試行の回数分の待ち時間を並べる `retry` モジュールがあります。どちらも、中の関数は仮の値を返すだけです。「出力」に書いた仕様どおりに動くように書き換えてください。`main` は、`retry::plan_delays` を呼んで、決めた待ち時間（ミリ秒）を表示します。

乱数には、外部クレートの `rand` を使います。`rand` はアプリが `Cargo.toml` に追加するので、`Cargo.toml` は書きません。

## 出力

次の 2 つの関数を実装してください。関数の名前・引数の型・戻り値の型は、このとおりにします。

```rust
// jitter モジュールの中
fn delay_ms(max_ms: u32) -> u32
```

- 0 以上 `max_ms` 以下の整数を、ランダムに 1 つ返します。

```rust
// retry モジュールの中
fn plan_delays(max_ms: u32, count: usize) -> Vec<u32>
```

- `jitter` モジュールの `delay_ms` を `count` 回呼び、その結果を、呼んだ順に並べた `Vec<u32>` を返します。
- `count` が 0 のときは、空の `Vec` を返します。

2 つの関数は、`jitter::delay_ms`・`retry::plan_delays` という名前で、モジュールの外（`main` と、隠しテスト）から呼べるようにします。`retry` モジュールの中では、`jitter::delay_ms` と書いて `delay_ms` を呼びます。

## 例

乱数を使うので、戻り値の値は呼び出すたびに変わります。

| 呼び出し | 戻り値の条件 |
|---|---|
| `jitter::delay_ms(500)` | 0 以上 500 以下の整数 |
| `jitter::delay_ms(0)` | 必ず `0` |
| `retry::plan_delays(500, 5)` | 長さ 5 で、どの値も 0 以上 500 以下 |
| `retry::plan_delays(500, 0)` | 空の `Vec` |

## 制約

- `max_ms` は、0 以上 10000 以下です。
- `count` は、0 以上 1000 以下です。
- 2 つの関数の名前・引数の型・戻り値の型と、モジュールの名前（`jitter`・`retry`）を変えないでください。
- 乱数の生成には、`rand` の `random_range` を使います。
