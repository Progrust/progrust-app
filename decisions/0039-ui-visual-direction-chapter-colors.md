# 0039. 画面のビジュアルデザインを、開いている章の色をアクセントにする方向性で進める

- 状態: 採用
- 日付: 2026-10-31
- 関連仕様: `screens.md`「見た目とテーマ」
- 置き換え: なし

## 背景

`screens.md` の未決事項に「画面のビジュアルデザイン（配色・フォント・アイコン）は、実装前にデザイン案を作成して決める」とあった。

デザイン案は2段階で作った。

1. ユーザーの希望（雰囲気は「エディトリアル・書籍的」と「親しみ・学習アプリ的」、ライトテーマを主にする、方向性を大きく振る）をもとに、方向性の異なる5案を作った。各案でトップページ・スライド画面・演習画面を描いた。
2. その中から案D を土台にして、派生の3案を作った。

## 決定

- 案D2「章カラー」の方向性で進める。
  - 案D の書体（Murecho、Red Hat Mono）、角の丸み、白と `#F5F6F9` の面の分け方を土台にする。
  - 開いている章の色を、その画面のアクセントにする。
- 案D の「路線図」のテーマ（コースを路線図、レッスンを駅に見立てる表現）は使わない。
- この方向性をデザインシステムにまとめた（0044）。章カラーの値は 0040、成功の表し方は 0041、章に属さない画面の色は 0042、アイコンは 0043 で決めた。
- 画面のレイアウト、書体ファイルの同梱方法、章カラーの定義場所は、この ADR では決めない（`screens.md`「未決事項」）。

## 検討した他の案

- 案: 案A「技術書」（明朝体、藍色、目次としおり紐）
  - 採用しなかった理由: テーマ性が少し強すぎると感じた（好み）
- 案: 案B「製図」（図面の枠と表題欄、青線と赤鉛筆）
  - 採用しなかった理由: テーマ性が少し強すぎると感じた（好み）
- 案: 案C「方眼ノート」（方眼、付箋、手書き風の書き込み、見出しタブ）
  - 採用しなかった理由: テーマ性が少し強すぎると感じた（好み）
- 案: 案E「切り絵」（紙を重ねた立体感、丸ゴシック、正解時の紙吹雪）
  - 採用しなかった理由: テーマ性が少し強すぎると感じた（好み）
- 案: 案D「路線図」をそのまま使う（コースを路線図、レッスンを駅として表す）
  - 採用しなかった理由: 雰囲気（書体、角の丸み、白と `#F5F6F9` の色分け）はよいが、「路線図」というテーマが少し分かりにくい
- 案: 案D1「スタンダード」（案D から路線図を外し、墨色と1色のアクセントだけにする）
  - 採用しなかった理由: 章ごとに色が変わる D2 の方が、学習者を飽きさせず、先に進んでいる感覚が得られそうだと感じた
- 案: 案D3「大きな見出し」（大きな文字と「スライド → 演習」の段階表示で、今どこにいるかを示す）
  - 採用しなかった理由: 章ごとに色が変わる D2 の方が、学習者を飽きさせず、先に進んでいる感覚が得られそうだと感じた

## 影響

- 章ごとに画面の色が変わる。学習者が飽きにくくなり、先に進んでいる感覚を得やすくなる。
- 章の数だけ色が必要になる。色の数と明るさ（0040）、意味の色との区別（0041）、章に属さない画面の色（0042）を決める必要があった。
- 章と章カラーの対応をどこで定めるか（`chapters.json` か、章の順番か）は未決である。
