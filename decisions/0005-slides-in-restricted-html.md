# 0005. スライドを、使える部品を決めた HTML で書く

- 状態: 採用
- 日付: 2026-10-31
- 関連仕様: `content-format.md`「スライド（slides.html）」、`content-guidelines.md`「教材チェックツール」
- 置き換え: なし

## 背景

スライドには「図や表、色合いを工夫して分かりやすさを重視する」と「全レッスンで統一したデザインにする」という 2 つの要件がある。
自由な HTML は表現力が高い一方で、レッスンが増えるとデザインがずれやすく、ダークモードで色が読めなくなる、スクリプトから Tauri の API を呼べてしまう、といった問題がある。

## 決定

スライドは HTML で書くが、使える要素・レイアウト・色のクラスを決め、直接の `style` 指定やスクリプトを禁止する。禁止事項は教材チェックツールで検出し、アプリでも表示前にサニタイズする（`content-format.md`「スライド（slides.html）」）。

## 検討した他の案

- 案: Markdown を基本にし、図の部分だけ HTML/SVG を許可する
  - 採用しなかった理由: 書くのは最も楽だが、図以外の表現（レイアウトや強調）が Markdown の拡張記法の範囲に限られる
- 案: 制限のない HTML
  - 採用しなかった理由: 表現力は最も高いが、デザインの統一・ダークモード対応・セキュリティを作者の注意に頼ることになる
- 案: JSON の構造化データ
  - 採用しなかった理由: デザインの統一は最も確実だが、書くのが手間で、図などの表現の幅が狭い

## 影響

- SVG を使った図など、HTML の表現力を使える。
- 部品の定義（テーマ CSS）と教材チェックツールを先に作る必要がある。
- 新しい表現が必要になったときは、部品の追加として `content-format.md` を変更する。
