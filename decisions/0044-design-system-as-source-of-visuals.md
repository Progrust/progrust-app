# 0044. 画面の見た目の値はデザインシステムを唯一の定義とし、仕様書には書かない

- 状態: 採用
- 日付: 2026-10-31
- 関連仕様: `screens.md`「見た目とテーマ」
- 置き換え: なし

## 背景

案D2（0039）の方向性をもとに、色・書体・余白・角丸・部品をまとめたデザインシステム「Progrust」を、Claude のアーティファクトとして作った。色・書体などの正式な値を、仕様書とデザインシステムのどちらに書くかを決める必要があった。仕様書は SSOT の原則に則り、同じ事実を複数の場所に書かない。

## 決定

- 画面の見た目（配色・書体・余白・角丸・アイコン・部品）は、デザインシステムに従う。
- 色・書体などの値はデザインシステムを唯一の定義とし、仕様書には書かない。仕様書はデザインシステムを参照する（`screens.md`「見た目とテーマ」）。

## 検討した他の案

- 案: 色・書体の値を仕様書に書く
  - 採用しなかった理由: デザインシステムと同じ値を二重に書くことになり、見本と一緒に確認・編集できない

## 影響

- 値を変えるときはデザインシステムを編集する。仕様書は変えなくてよい。
- デザインシステムはリポジトリの外（Claude のアーティファクト）にある。実装では、デザインシステムの値をもとにテーマ CSS を作る。
