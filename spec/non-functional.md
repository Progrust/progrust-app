# 非機能要件 仕様書

対応環境、オフライン時の動作、セキュリティ、配布と更新、ログ、性能などを定める。

## 1. 対応環境

| OS | 対応バージョン | アーキテクチャ |
|---|---|---|
| macOS | 13 以降 | Apple Silicon・Intel（ユニバーサルバイナリ） |
| Windows | 10（22H2）以降、11 | x64 |

- Windows のインストーラーには WebView2 ランタイムの導入処理を含める。
- 学習者の環境に必要なもの: Rust ツールチェーン（rustc 1.85 以上）、Claude Code（AI 機能を使う場合）。検出方法は `architecture.md` §3。

## 2. 言語

- UI・教材・AI の回答は日本語のみとする。

## 3. オフライン時の動作

| 機能 | オフライン時 |
|---|---|
| スライド・スライド検索 | 利用できる |
| 実行・提出 | 利用できる（初回準備が完了していれば、許可クレートを使う演習も利用できる） |
| 初回準備 | 失敗し、次回起動時に再実行する（`exercise-runner.md` §2.3） |
| 質疑応答・問題生成 | エラーを表示する |
| 学習記録・分析のジョブ | 失敗してリトライする。3 回失敗したら `failed` になり、設定画面から再実行できる |
| 更新の確認 | 何も表示しない |

## 4. セキュリティとプライバシー

### 4.1 学習者のコードの実行

- 学習者のコードはサンドボックスに入れず、学習者のユーザー権限で実行する。
- 生成問題の検証では、AI が生成した模範解答と初期コードを自動で実行する（`exercise-generation.md` §4.2）。問題生成の指示文で、ファイル・ネットワーク・プロセスを操作するコードを生成しないよう指示する。実行には `exercise-runner.md` §6 の制限時間をかける。

### 4.2 アプリ自体

- スライドの HTML はサニタイズしてから表示する（`content-format.md` §5.7）。
- フロントエンドに許可する Tauri の権限は最小限にする（`architecture.md` §6）。
- AI にはツールを使わせない（`claude-integration.md` §3）。

### 4.3 データの送信

- 学習データはすべて学習者の PC 内に保存する。アプリ独自のサーバーへの送信や利用状況の収集（テレメトリ）は行わない。
- AI 機能を使うと、学習者のコード・質問・学習記録・分析ファイルの内容が Claude Code を通じて Anthropic に送信される。このことを初回起動画面で説明する（`screens.md` §12）。
- 外部への通信は、Claude Code の呼び出し、クレートのダウンロード（初回準備）、更新の確認に限る。

## 5. 配布と更新

- 配布物（インストーラー、更新情報）は GitHub Releases に置く。
- GitHub Actions で、タグを作成したときに macOS・Windows 向けにビルドし、Releases に公開する。
- 形式: macOS は `.dmg`、Windows は `.msi` または NSIS インストーラー。
- OS のコード署名は行わない。初回起動時の OS の警告を回避する手順を配布ページに記載する。
- 自動更新には Tauri の更新機能を使う。更新ファイルは Tauri の更新用の鍵で署名する（OS のコード署名とは別）。秘密鍵は GitHub Actions のシークレットで管理する。
- 起動時と設定画面の「更新の確認」で新しいバージョンを確認する。新しいバージョンがあればトーストで通知し、学習者が「更新して再起動」を選んだときに更新する。
- 教材はアプリに同梱し、アプリの更新とともに更新する。

## 6. ログ

- `{app_data_dir}/logs/` にアプリのログを出力する。1 日 1 ファイルとし、7 日分を保持する。
- 記録する内容: 起動・終了、ツールの検出結果、ジョブの開始・終了・エラー、ビルド・実行の開始・終了と結果の状態、AI 呼び出しのエラーの詳細。
- 学習者のコードや質問の本文はログに記録しない。
- 設定画面から、ログのフォルダを OS の既定アプリで開けるようにする。

## 7. 性能の目安

| 項目 | 目安 |
|---|---|
| 起動してトップページを表示するまで | 3 秒以内 |
| スライドの切り替え | 100ms 以内 |
| スライド検索の結果表示 | 入力が止まってから 300ms 以内 |
| 実行・提出のアプリ側の処理時間（cargo のビルド・プログラムの実行時間を除く） | 500ms 以内 |
| 学習記録・分析のジョブ | 画面の操作を妨げない（バックグラウンドで実行する） |

## 8. データの互換性

- アプリが管理するファイルはすべて `schema_version` を持つ。
- `settings.json`・`progress.json`・`jobs.json` は、アプリ起動時に古いバージョンを検出したら自動で新しい形式に変換する。変換前のファイルは `.v{旧バージョン}.bak` として残す。
- 学習記録・分析ファイルの扱いは `learning-record-and-analysis.md` §8 に従う。
- 教材の更新でレッスンが削除・変更されても、過去の学習記録・試行ログは削除しない。存在しないレッスンの進捗は表示しない。

## 9. 受け入れ条件

- ネットワークを切断した状態で起動し、完了済みの初回準備を前提にレッスンを最初から最後まで進められる。
- macOS 13 の Intel 機と Apple Silicon 機、Windows 10 / 11 でインストールして起動できる。
- 新しいバージョンを Releases に公開すると、旧バージョンのアプリで通知が表示され、更新して再起動できる。
- ログのファイルに、学習者のコードや質問の本文が含まれない。

## 10. 未決事項

- 正式に公開するかどうか、および公開する場合の OS のコード署名（macOS の公証、Windows の証明書）。
- 署名なしの macOS アプリで Tauri の自動更新が問題なく動作するか（実装時に検証する）。
