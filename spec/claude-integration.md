# Claude Code 連携 共通仕様書

`claude -p` の呼び出し方、モデルの選択、ジョブキューなど、AI を使うすべての機能に共通するルールを定める。
各機能の入力・出力・検証は、それぞれの仕様書に定める。

| 機能 | 呼び出し方 | 仕様書 |
|---|---|---|
| 質疑応答 | 画面から直接呼び出す | `qa-chat.md` |
| 学習記録・分析・分析の再構築 | ジョブ | `learning-record-and-analysis.md` |
| 演習問題生成 | ジョブ | `exercise-generation.md` |

## 1. 設計方針

- AI にはファイルの編集・コマンドの実行などのツールを使わせない。結果は標準出力で返させ、アプリが検証してから保存する。
- AI に数値・日時・回数を計算させない（`learning-record-and-analysis.md` §1.1）。
- AI 機能が使えなくても、学習（動画・演習・完了）は続けられるようにする。

## 2. 検出と、使えない場合の動作

- `claude` の検出方法は `architecture.md` §3 に従う。
- `claude` が見つからない間は、次のように動作する。
  - 質疑応答の入力欄を無効にし、「Claude Code が見つかりません」と導入手順へのリンクを表示する。
  - 問題生成の「生成」ボタンを無効にする。
  - ジョブは登録するが実行しない（`pending` のまま残す）。`claude` が見つかったら実行を始める。
- 設定画面の「接続テスト」ボタン（`test_claude_connection`）で、短い指示文を質疑応答用のモデルで実行し、応答が返るかを確認できる。

## 3. 呼び出しの共通ルール

- 設定画面で選択したモデルを `--model` で指定する（§6）。
- ツールを使わせない設定で起動する。
- 学習者の Claude Code のユーザー設定（フック・MCP サーバー・`CLAUDE.md` など）を読み込まない設定で起動する。
- 作業ディレクトリは呼び出しごとに作る空の一時ディレクトリとし、終了後に削除する。
- 指示文は標準入力で渡す。
- `--continue` / `--resume` は使わない。会話の続きが必要な場合（質疑応答）も、アプリが履歴を毎回入力に含める。
- 出力形式:
  - ジョブ: `--output-format json` を指定し、結果のテキストを取り出す。
  - 質疑応答: ストリーミングの出力形式を指定し、回答を少しずつ表示する。
- 具体的なコマンドラインフラグは、実装時に使用する Claude Code のバージョンに合わせて確認する。

### 3.1 制限時間

| 用途 | 1 回の呼び出しの制限時間 |
|---|---|
| 質疑応答 | 120 秒 |
| 記録・分析 | 300 秒 |
| 問題生成 | 600 秒 |

制限時間を超えたらプロセスを終了し、エラー（§7）とする。

## 4. 指示文（プロンプト）

- 各機能の指示文はリポジトリの `prompts/` に Markdown で置き、アプリに同梱する。
- 指示文に埋め込む値は `{{name}}` 形式で書き、アプリが置き換える。
- 指示文に何を含めるか（入力の項目）は各機能の仕様書に定める。指示文の文面は実装の一部として扱い、仕様書には書かない。

| ファイル | 用途 |
|---|---|
| `prompts/record.md` | 記録セッション |
| `prompts/analysis.md` | 分析セッション |
| `prompts/generate.md` | 問題生成 |
| `prompts/chat-video.md` | 動画についての質疑応答 |
| `prompts/chat-explanation.md` | 解説表示後の質疑応答 |

## 5. ジョブキュー（jobs.json）

```json
[
  {
    "job_id": "job_20261031T133100_001",
    "type": "record",
    "session_id": "20261031T130200_ch04-03",
    "record_id": null,
    "generation_id": null,
    "status": "pending",
    "attempts": 0,
    "last_error": null,
    "created_at": "...",
    "updated_at": "..."
  }
]
```

| 項目 | 仕様 |
|---|---|
| `type` | `record` / `analysis` / `rebuild` / `generate` |
| 対象 | `record` は `session_id`、`analysis` は `record_id`、`generate` は `generation_id` を持つ |
| `status` | `pending` / `running` / `done` / `failed` |
| 実行順 | 1 件ずつ直列に実行する。`pending` のジョブから、優先度（`generate` > `record` > `analysis` > `rebuild`）の高いもの、同じ優先度では登録の古いものを選ぶ |
| 依存 | `analysis` は対応する `record` が `done` になってから登録する |
| リトライ | 失敗時は最大 3 回まで再実行（間隔 30 秒 → 2 分 → 10 分）。3 回失敗したら `failed` |
| `claude` 未検出時 | 実行せず `pending` のまま残す。`attempts` は増やさない |
| 起動時 | `running` のまま残っているジョブは `pending` に戻す |
| 保持 | `done` のジョブは 7 日後に削除 |
| UI | 状態が変わるたびに `job_updated` イベントを送る。ヘッダーに実行中のジョブを表示し、`failed` のジョブは設定画面に一覧表示して手動で再実行できる（`screens.md`） |

- 質疑応答はジョブキューを通さず、ジョブの実行中でも並行して呼び出せる。

## 6. モデルの選択

設定画面で、用途ごとにモデルを選ぶ。

| 設定 | 用途 | 既定値 |
|---|---|---|
| 質疑応答のモデル | 質疑応答、接続テスト | `sonnet` |
| 記録・分析・問題生成のモデル | すべてのジョブ | `opus` |

- 選択肢は `opus` / `sonnet` / `haiku`（Claude Code のモデルのエイリアス）と「その他（モデル ID を入力）」とする。
- 設定は `settings.json` に保存する（`screens.md` §8）。

## 7. エラーの分類と表示

| 分類 | 判定 | 表示・動作 |
|---|---|---|
| 未検出 | `claude` が見つからない | §2 |
| 未ログイン | 終了コードと出力から認証エラーと判定できる場合 | 「ターミナルで `claude` を起動してログインしてください」 |
| 利用上限 | 出力から利用上限・レート制限と判定できる場合 | 「Claude の利用上限に達しました。時間をおいて再試行してください」。ジョブは通常のリトライに従う |
| タイムアウト | §3.1 の制限時間を超えた | 「応答がありませんでした」 |
| 出力不正 | 各機能の出力検証に失敗した | 質疑応答では発生しない。ジョブは失敗としてリトライする |
| その他 | 上記以外で終了コードが 0 以外 | 「AI の呼び出しに失敗しました」と、詳細（標準エラー出力の先頭）を折りたたんで表示 |

- ジョブの `last_error` には分類と詳細を保存する。
- エラーの詳細はログ（`non-functional.md` §6）にも記録する。

## 8. 受け入れ条件

- 学習者の `~/.claude/CLAUDE.md` やフックの設定が、アプリからの AI 呼び出しに影響しない。
- AI の呼び出し中に、AI がファイルを作成・変更・削除することがない。
- `claude` をアンインストールした状態でレッスンを完了すると、記録ジョブが `pending` のまま残り、`claude` を導入して再検出すると実行される。
- 記録ジョブの実行中でも、質疑応答の回答が返ってくる。
- 問題生成のジョブは、先に登録された記録・分析のジョブより先に実行される（実行中のジョブの完了は待つ）。
- 設定画面で選んだモデルが、用途ごとに `--model` に渡される。
