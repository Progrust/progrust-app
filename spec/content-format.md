# 教材データ形式 仕様書

アプリに同梱する教材（章・レッスン・動画・演習・要素マスタ）のファイル形式を定める。
教材の書き方のルール（内容面）は `content-guidelines.md` に定める。
AI が生成する演習もこの形式に変換して保存する（`exercise-generation.md`）。

## 1. ディレクトリ構成

リポジトリの `content/` に置き、アプリに同梱する。同梱のしかたは `architecture.md` §2・§4.2 に定める。

```
content/
├── chapters.json                   # 章とレッスンの並び（§2）
├── elements.json                   # 要素マスタ（§3）
├── voice.json                      # 声の設定（§5.3）。全レッスン共通
├── readings.json                   # 読みの対応表（§5.3）。全レッスン共通
├── assets/                         # 全レッスン共通の画像
└── lessons/
    └── {lesson_id}/
        ├── lesson.json             # レッスン定義（§4）
        ├── video/                  # 動画（§5）。章末復習レッスンにはない
        │   ├── script.json         # 台本（§5.2）
        │   ├── index.tsx           # 動画の入口（§5.5）
        │   ├── …                   # シーンとレッスン専用の部品（.tsx / .ts / .css）
        │   ├── voice/              # 音声。1 文 1 ファイル（§5.3）
        │   ├── durations.json      # 音声の長さ（§5.3）
        │   └── cue-reference.json  # 合図を合わせたときの音声の長さ（§5.4）
        ├── assets/                 # このレッスン専用の画像
        └── exercise/               # 演習（§6）
            ├── problem.md
            ├── explanation.md
            ├── starter/            # 初期コード
            ├── solution/           # 模範解答
            ├── cases.json          # judge.mode = stdout の場合
            └── judge_tests.rs      # judge.mode = test の場合
```

- 動画の共通部品（§5.5）と音声を作るツール（§5.3）は `content/` の外に置く（`architecture.md` §5）。

## 2. 章とレッスンの並び（chapters.json）

カリキュラム（章立てと学習順）の唯一の定義とする。

```json
[
  {
    "id": "ch04",
    "title": "所有権",
    "description": "Rust のメモリ管理の中心となる所有権の仕組みを学ぶ",
    "lessons": ["ch04-01", "ch04-02", "ch04-03", "ch04-review"]
  }
]
```

- 配列の順序が章の学習順、`lessons` の順序が章内の学習順である。
- 全レッスンをこの順に一列に並べたものを「学習順」と呼ぶ。「過去のレッスン」は学習順で前にあるレッスンを指す。
- 要素の「導入レッスン」は、学習順で最初にその要素を `primary_elements` に含むレッスンとする。
- あるレッスンにとっての「既習の要素」は、導入レッスンが学習順でそのレッスンより前にある要素とする。
- 各章の最後のレッスンは章末復習レッスン（`ch{NN}-review`）とする。

## 3. 要素マスタ（elements.json）

```json
[
  {
    "id": "ownership.move",
    "chapter": "ch04",
    "name": "所有権のムーブ",
    "description": "値の代入・関数呼び出しによる所有権の移動",
    "related_errors": ["E0382", "E0505"]
  }
]
```

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | `{分類}.{要素}` 形式の snake_case。一度公開したら変更しない |
| `chapter` | string | その要素を主に扱う章の ID |
| `name` | string | 表示名 |
| `description` | string | 要素の説明（AI への入力・生成設定画面の説明に使用） |
| `related_errors` | string[] | その要素の誤解で発生しやすいコンパイルエラーコード |

- `related_errors` は、試行ログ中のエラーコードから躓いた要素の候補を出すために使う（`learning-record-and-analysis.md` §6.1）。
- 要素 ID を廃止する場合は、削除せず `"deprecated": true` を付ける。

## 4. レッスン定義（lesson.json）

```json
{
  "id": "ch04-03",
  "chapter": "ch04",
  "kind": "lesson",
  "title": "所有権のムーブ",
  "summary": "代入や関数呼び出しで所有権が移動する仕組みを学ぶ",
  "tags": ["ムーブ", "move", "代入", "E0382"],
  "primary_elements": ["ownership.move"],
  "secondary_elements": ["fn.basic", "string.basic"],
  "estimated_minutes": 20,
  "exercise": {
    "layout": "single",
    "judge": { "mode": "stdout", "target": "src/main.rs" },
    "dependencies": [],
    "readonly_files": [],
    "case_labels": {}
  }
}
```

| フィールド | 説明 |
|---|---|
| `id` / `chapter` | レッスン ID と所属する章の ID。`chapters.json` と一致すること |
| `kind` | `lesson` / `chapter_review` / `generated`（生成問題のみ） |
| `title` / `summary` | 表示名と、レッスン一覧に表示する 1 行の説明 |
| `tags` | 検索ワード（string[]）。レッスン検索の対象にする語（`screens.md` §9）。`kind` が `lesson` のレッスンでは必須で、1 件以上を書く。空の文字列と、同じレッスンの中での重複は書けない |
| `primary_elements` | 主要素の ID（1〜2 件） |
| `secondary_elements` | 副要素の ID |
| `estimated_minutes` | 目安の所要時間（分） |
| `exercise.layout` | `single`（`src/main.rs` の 1 ファイルのみ）/ `multi`（複数ファイル） |
| `exercise.judge.mode` | `stdout` / `test`（§6.4） |
| `exercise.judge.target` | `test` 方式で隠しテストを組み込むファイル（`src/main.rs` または `src/lib.rs`）。`stdout` 方式では `src/main.rs` 固定 |
| `exercise.dependencies` | 使用する許可クレートの名前（`exercise-runner.md` §2.1 の一覧にあるもの） |
| `exercise.readonly_files` | 学習者が編集できないファイルのパス（`multi` のみ） |
| `exercise.case_labels` | `test` 方式でテスト関数名に付ける表示名（例: `{"empty_input": "空の入力"}`）。省略時は関数名を表示する |

- 章末復習レッスン（`chapter_review`）と生成問題（`generated`）の `lesson.json` は、`tags` を持たない。

## 5. 動画（video/）

### 5.1 構成

1 レッスンの動画を、`video/` の次のファイルで表す。

| ファイル | 内容 | 書くもの |
|---|---|---|
| `script.json` | 台本（§5.2） | 作者 |
| `index.tsx` | 動画の入口（§5.5） | 作者 |
| そのほかの `.tsx`・`.ts`・`.css` | シーンと、このレッスン専用の部品（§5.5） | 作者 |
| `voice/{文の ID}.m4a` | 音声（§5.3） | 音声を作るツール |
| `durations.json` | 音声の長さ（§5.3） | 音声を作るツール |
| `cue-reference.json` | 合図を合わせたときの音声の長さ（§5.4） | 音声を作るツール |

- 動画は、動画ファイルに書き出さない。アプリが Remotion の Player（`@remotion/player`）で描画する。
- 画面は 16:9、30fps とする。作者は 1280×720 の基準サイズで内容を作り、アプリが表示領域に合わせて拡大・縮小する。
- 動画は、シーンを台本の `scenes` の順に並べたものである。シーンと文の位置は、音声の長さから決まる（§5.4）。
- アプリは、再生するときにテーマ（ライト／ダーク）、章、レッスン定義（§4）を指定する。動画のコードには、テーマも章も書かない。
- 見た目（書体・色・余白・部品）は、動画のデザインシステム（`screens.md` §10.1）に従う。アプリは、動画のデザインシステムの CSS（トークンと部品のクラス）を動画に適用する。
- 再生の操作と字幕は `screens.md` §5 に定める。

### 5.2 台本（script.json）

ナレーションを文ごとに並べ、シーンと、画面に出すコードを宣言する。

```json
{
  "ai_note": "学習者には表示しない、AI への補足説明",
  "code_blocks": [
    { "id": "main", "label": "src/main.rs", "language": "rust", "code": "fn main() {\n    let s1 = String::from(\"hi\");\n    let s2 = s1;\n    println!(\"{s1}\");\n}" },
    { "id": "error", "language": "text", "code": "error[E0382]: borrow of moved value: `s1`\n --> src/main.rs:4:16\n…" }
  ],
  "scenes": [
    { "id": "title", "name": "表紙", "lead": 1.3 },
    { "id": "move", "name": "ムーブの図解", "lead": 1.7, "tail": 1.6 }
  ],
  "sentences": [
    { "id": "t1", "scene": "title", "text": "このレッスンでは、所有権のムーブを学びます。", "say": "このレッスンでは、所有権のムーブを学びます。" },
    { "id": "m1", "scene": "move", "text": "2 行目で、変数 s1 に String の値を入れました。", "say": "二行目で、変数エスワンにストリングのあたいを入れました。" },
    { "id": "m2", "scene": "move", "text": "文字列の中身はヒープにあり、s1 がその所有者です。", "say": "文字列のなかみはヒープにあり、エスワンがその所有者です。", "pause_after": 0.8 },
    { "id": "m3", "scene": "move", "text": "3 行目で、s1 を s2 に代入します。", "say": "三行目でエスワンをエスツーに代入します。" }
  ]
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `ai_note` | string | 画面にも字幕にも出さない補足。質疑応答で AI に渡す（`qa-chat.md` §3.1）。省略できる |
| `code_blocks` | object[] | 画面に出すコードとコンパイラの出力（§5.6）。質疑応答で AI に渡す（`qa-chat.md` §3.3）。省略時は空 |
| `scenes` | object[] | シーン。配列の順序が再生の順序である。1 件以上 |
| `sentences` | object[] | 文。配列の順序が再生の順序である |

**`code_blocks` の 1 件**

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | コードブロックの ID |
| `label` | string | ラベル（ファイル名・言語名）。省略できる |
| `language` | string | 言語（§5.6） |
| `code` | string | 表示する文字列。行の区切りは `\n` とする |
| `start_line` | number | 載せた 1 行目の、ファイルでの行番号（1 以上の整数）。省略時は 1 |
| `diff` | boolean | Diff として表示する（§5.6）。省略時は `false` |

**`scenes` の 1 件**

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | シーンの ID |
| `name` | string | シーンの名前（例: 「表紙」「まとめ」） |
| `lead` | number | シーンの先頭から最初の文までの間（秒。0 以上）。省略時は 0.9 |
| `tail` | number | 最後の文の音声が終わってからシーンの末尾までの間（秒。0 以上）。省略時は 0.7 |

**`sentences` の 1 件**

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 文の ID |
| `scene` | string | この文を読み上げるシーンの ID |
| `text` | string | もとの文。字幕（`screens.md` §5）と質疑応答（`qa-chat.md` §3.1）に使う |
| `say` | string | 読ませる文。音声を作るときに VOICEPEAK に渡す（§5.3）。140 字以下とする |
| `pause_after` | number | この文の音声が終わってから次の文までの間（秒。0 以上）。省略時は 0.45。シーンの最後の文には書けない |

- ID は、英小文字で始まり、英小文字・数字・`-` からなる文字列とする。`code_blocks`・`scenes`・`sentences` のそれぞれの中で重複しない。
- 同じシーンの文は続けて並べる。シーンが現れる順序は、`scenes` の順序と同じにする。
- どのシーンにも、文が 1 件以上ある。
- `text` と `say` は空にできない。
- 文字数は Unicode のコードポイントで数える。

### 5.3 音声

- ナレーションの音声は、教材の作者の環境で、VOICEPEAK の CLI から作る。作った音声はリポジトリに入れ、アプリに同梱する。学習者の環境に VOICEPEAK は要らない。CI では音声を作らない。
- 音声は 1 文 1 ファイルとし、`voice/{文の ID}.m4a` に置く。形式は AAC、モノラルとし、ビットレートは 64kbps を目安とする。

**声の設定（`content/voice.json`）**

```json
{
  "narrator": "Natsuki Karin",
  "speed": 120,
  "pause": 0.2,
  "emotion": { "hightension": 20, "buchigire": 5, "nageki": 0, "sagesumi": 20, "sasayaki": 80 }
}
```

| フィールド | 説明 |
|---|---|
| `narrator` | VOICEPEAK のナレーター名。`Natsuki Karin` は夏色花梨である |
| `speed` | 読む速さ（VOICEPEAK の速さの値） |
| `pause` | 「、」の間の長さ（秒。0 以上） |
| `emotion` | 感情の項目名と値。項目はナレーターごとに決まる |

- 声の設定は全レッスンで共通とする。
- 声の設定を変えたら、全レッスンの音声を作り直す。

**読みの対応表（`content/readings.json`）**

```json
{
  "Rust": "ラスト",
  "String": "ストリング",
  "値": "あたい"
}
```

- 読み間違えやすい語と、`say` に書く読みの対応を、全レッスン共通で持つ。キーが語、値が読みである。
- 作者は `say` を書くとき、この表に従う（`content-guidelines.md` §4.2）。音声を作るツールは `say` を書き換えない。

**音声の長さ（`durations.json`）**

```json
{
  "m1": {
    "seconds": 3.757,
    "say": "二行目で、変数エスワンにストリングのあたいを入れました。",
    "voice": {
      "narrator": "Natsuki Karin",
      "speed": 120,
      "pause": 0.2,
      "emotion": { "hightension": 20, "buchigire": 5, "nageki": 0, "sagesumi": 20, "sasayaki": 80 }
    }
  }
}
```

| フィールド | 説明 |
|---|---|
| `seconds` | その文の音声ファイル（`voice/{文の ID}.m4a`）の長さ（秒） |
| `say` | その音声を作ったときの `say` |
| `voice` | その音声を作ったときの声の設定（`voice.json` と同じ形） |

- キーは文の ID とする。台本のすべての文について 1 件ずつ持つ。
- 音声を作るツールが書く。作者は手で書き換えない。

**音声を作るツール**

`tools/` に置く。作者の環境の VOICEPEAK と ffmpeg を使う。

- 台本の文を 1 文ずつ順に VOICEPEAK に渡して、音声を作る。VOICEPEAK を同時に 2 つ以上動かさない。
- `durations.json` の `say`・`voice` が台本の `say`・`voice.json` と同じで、音声ファイルがある文は、作り直さない。すべての文を作り直す指定もできる。
- `say` が 140 字を超える文があるときは、エラーにして音声を作らない。
- 「、」の間は次のように作る。`say` をそのまま VOICEPEAK に渡して音声を作り、できた音声の中の「、」にあたる無音を `pause` 秒まで切り詰める。`pause` 秒より短い無音と、文の途中の「。」にあたる無音は、そのままにする。
- 切り詰めたあとの音声を `.m4a` に変換し、変換後のファイルの長さを `durations.json` の `seconds` に書く。
- 台本にない文の音声ファイルと、`durations.json`・`cue-reference.json` の記録は消す。
- `cue-reference.json` の書き方は §5.4 に定める。

### 5.4 タイムラインと合図

アプリは、台本と `durations.json` から、シーンと文の開始位置を決める。

- シーンは、台本の `scenes` の順に、間を空けずに並べる。最初のシーンの開始位置が動画の先頭である。
- シーンの中では、先頭から `lead` 秒後に最初の文を始める。次の文は、前の文の音声が終わってから、前の文の `pause_after` 秒後に始める。最後の文の音声が終わってから `tail` 秒後が、シーンの末尾である。
- 文の音声は、その文の開始位置から再生する。文の音声の長さは、`durations.json` の `seconds` とする。
- 秒で表した長さ（`lead`・`tail`・`pause_after`・`seconds`）は、それぞれフレーム数に四捨五入してから足し合わせる。
- 動画の長さは、すべてのシーンの長さの合計とする。

**合図**

絵を動かす位置は、合図で指定する。合図は「文の ID」と「その文の開始位置からの秒」の組で表し、共通部品 `useCues()`（§5.5）が返す次の関数で書く。

| 関数 | 返す位置 |
|---|---|
| `at(文の ID, 秒)` | 文の開始位置から、指定した秒だけ後の位置。秒を省略すると 0 とする。負の秒は、文の開始位置より前を指す |
| `endOf(文の ID, 秒)` | 文の音声が終わる位置から、指定した秒だけ後の位置。秒を省略すると 0 とする |

- どちらも、シーンの先頭を 0 としたフレーム数を返す。
- 合図で指せるのは、その合図を書いたシーンの文だけとする。台本にない文の ID と、ほかのシーンの文の ID を指すと、描画時にエラーになる。
- `at` の正の秒は、`cue-reference.json` に記録した長さの音声での位置として書く。アプリは、その秒に、いまの音声の長さとの比（`durations.json` の `seconds` ÷ `cue-reference.json` の長さ）を掛けて位置を決める。
- `at` の負の秒と `endOf` の秒には、比を掛けない。
- `cue-reference.json` にない文では、比を 1 とする。

**合図を合わせたときの音声の長さ（`cue-reference.json`）**

```json
{
  "m5": 6.389,
  "m6": 3.363
}
```

- キーは文の ID、値は、作者がその文の合図を合わせたときの音声の長さ（秒）とする。
- 音声を作るツール（§5.3）は、`cue-reference.json` にない文の音声を作ったとき、その音声の長さを書き足す。すでにある文の値は、音声を作り直しても書き換えない。
- 作者が合図を合わせ直したときは、音声を作るツールの指定で、その文の値をいまの音声の長さに書き換える。

### 5.5 シーン

シーンは React（TSX）の部品として書く。使える要素と部品、動き、レイアウトは制限しない。守ることは、この節の決まりと §5.6〜§5.8 とする。

`index.tsx` は、シーンの ID をキー、そのシーンを描く部品を値とするオブジェクトを default export する。

```tsx
// index.tsx（import は省略）
export default {
  title: TitleScene,
  move: MoveScene,
};
```

- `index.tsx` のキーは、台本の `scenes` の ID と過不足なく一致させる。
- アプリは、タイムライン（§5.4）に従ってシーンを順に表示し、音声を再生する。動画のコードには、シーンを並べる処理と音声を再生する処理を書かない。
- シーンの部品は、基準サイズ（1280×720）の領域に描く。props は受け取らない。
- シーンの中の現在の位置は、Remotion の `useCurrentFrame()` で得る（シーンの先頭が 0）。シーンの長さは、`useVideoConfig()` の `durationInFrames` で得る。
- 絵は、現在のフレームだけから決まるように書く。同じフレームは、通して再生したときも、再生位置を移した直後も、同じ絵になる。CSS のアニメーションとトランジション、タイマー、乱数は使わない。
- 見た目は、動画のデザインシステムのトークン（CSS 変数）と部品のクラス（`callout`・`mark` など）で指定する。
- レッスン専用の部品と CSS を、`video/` の中に作ってよい。
- 画像は、レッスンの `assets/` か全レッスン共通の `content/assets/` に置いたファイルを import して使う。
- 図（SVG）には `role="img"` と、図の要点を表す `aria-label` を付ける。画像には `alt` を付ける。

**共通部品**

全レッスンで使う部品を `src/video/` に用意する。動画のコードは、ここから import して使う。

| 部品 | 役割 |
|---|---|
| `useCues()` | 合図の関数 `at`・`endOf`（§5.4）を返す。シーンの部品の中で呼ぶ |
| `useLesson()` | アプリが指定した章とレッスン定義から、章の番号・章名・レッスンの番号・レッスン名を返す |
| `LessonTitle` | 表紙のレッスン名。`lesson.json` の `title` を表示する |
| `CodeBlock` | 台本の `code_blocks` の 1 件を表示する（§5.6） |
| `Camera` | 寄せ。基準サイズの領域のうち、映す範囲（左上の位置と倍率）を指定する |
| 動きの補助 | 進み具合の計算、補間、要素の出現などの関数 |

- 最初のシーンは表紙とし、`LessonTitle` を 1 つ表示する。
- 章の番号・章名・レッスンの番号・レッスン名を画面に出すときは、`LessonTitle` か `useLesson()` を使う。動画のコードに書き写さない。
- 寄せる倍率と動きの速さは、動画のデザインシステムに従う（`content-guidelines.md` §4.7）。

```tsx
// シーンの例（import は省略）
export const MoveScene = () => {
  const frame = useCurrentFrame();
  const { at } = useCues();
  // 文 m5 の開始から 0.5 秒後に、3 行目の s1 にマーカーを引く
  const marked = frame >= at("m5", 0.5) ? 1 : 0;
  return <CodeBlock block="main" marks={[{ line: 3, text: "s1", progress: marked }]} />;
};
```

### 5.6 コードの表示

画面に出すコードとコンパイラの出力は、台本の `code_blocks` に書き、共通部品 `CodeBlock` で表示する。同じコードを TSX に書き写さない。

**言語（`language`）**

| 値 | 用途 | 表示 |
|---|---|---|
| `rust` | Rust のコード | シンタックスハイライトする |
| そのほかの言語名（例: `python`、`toml`） | Rust 以外の言語のコード | シンタックスハイライトしない |
| `plaintext` | ターミナルの出力ではないテキスト（入力ファイルの中身など） | シンタックスハイライトしない |
| `text` | ターミナルの出力（コンパイラ・cargo の出力、プログラムの実行結果、標準入力とのやりとり） | 行番号を表示しない。rustc の出力は色付けする |

**行番号と Diff**

- `language` が `text` 以外のコードブロックには、左に行番号を表示する。行番号はファイルの行番号である。
- ファイルの途中から載せるときは、`start_line` に、載せた 1 行目のファイルでの行番号を書く。
- `diff` が `true` のコードブロックは、Diff として表示する。`code` の各行の先頭の 1 文字に `+`（追加）・`-`（削除）・半角空白（変わらない行）を書き、その後ろにコードを書く。空の行は変わらない行として扱う。削除行には行番号を表示せず、行番号は変更後のファイルの行番号になる。`start_line` と併用するときは、変更後のファイルで最初の行の番号を書く。
- 表示する最後の行番号は 999 以下とする。
- この決まりに違反する `code_blocks`（`start_line` が 1 以上の整数でない、Diff の行の先頭が `+`・`-`・半角空白のどれでもない、999 を超える行番号）は、教材チェックツール（`content-guidelines.md` §6）でエラーとする。

**`CodeBlock` の指定**

| 指定 | 内容 |
|---|---|
| `block` | 表示する `code_blocks` の `id` |
| `scopes` | 変数が生きている範囲を枠で示す。範囲ごとに、ラベルと開始行・終了行を書く（例: `{ label: "r", from: 2, to: 7 }`） |
| `marks` | 字句を強調する（マーカー）。字句ごとに、行番号と、その行の中の文字列を書く（例: `{ line: 3, text: "s1" }`） |
| `errors` | エラーの箇所に波線を引く。書き方は `marks` と同じとする |
| `lines` | 行ごとの動き。行番号ごとに、行の差し込み（`open`）・入力の進み具合（`typed`）・淡くする度合い（`dim`）を 0〜1 で書く |

- 指定に書く行番号は、`code_blocks` の行番号（`code` の 1 行目を `start_line` として数えた番号。Diff では変更後のファイルの行番号）とする。行を差し込む動きの途中でも、この番号で書く。`language` が `text` のコードブロックの `lines` では、1 から数えた行の位置で書く。
- `scopes` の範囲は 1 つのコードブロックに 3 つまで、入れ子は 2 段までとする。範囲の一部だけが重なる指定はできない。範囲は `code_blocks` の行番号の中に収める。`diff` が `true` のコードブロックでは使わない。
- `marks` と `errors` は、字句単位で指定する。同じ文字列がその行に複数あるときは、何個目かを `nth`（1 始まり。省略時は 1）で指す。`language` が `text` のコードブロックでは使わない。
- `scopes`・`marks`・`errors` の 1 件ごとに、進み具合（`progress`。0〜1。省略時は 1）を書いて、現れ方を動かせる。
- 行を差し込む動きでは、まだ差し込んでいない行を数えずに行番号を表示する。差し込みが終わると、表示される行番号は `code_blocks` の行番号と同じになる。
- この節の制約に違反する指定（範囲の重なり・入れ子・個数の違反、`code_blocks` の行番号の外の範囲と行、その行にない字句、`text` の中の `marks`・`errors`、`code_blocks` にない `id`）は、描画時にエラーになる。教材チェックツールは、これを描画のチェック（`content-guidelines.md` §6）で検出する。
- `CodeBlock` にない動きが要るときは、レッスン専用の部品を作ってよい。その場合も、この節の表示の決まりと §5.7 に従う。

### 5.7 色の指定

動画のコード（TSX・CSS・SVG）では色を直接指定せず、動画のデザインシステムのトークン（CSS 変数）と、以下の色クラスを使う。各クラスの実際の色は、動画のデザインシステムの CSS がライト・ダークモードそれぞれで定める。

| クラス | 意味 | 色 |
|---|---|---|
| `c-primary` | 主役（注目させたいもの） | 再生するときに指定された章の章カラー |
| `c-accent` | 補助的な強調 | 再生するときに指定された章の章カラー（淡い段） |
| `c-ok` | 正しい・成功 | 章によらない固定の色 |
| `c-ng` | 誤り・エラー | 章によらない固定の色 |
| `c-muted` | 背景的な情報・無効になったもの | 章によらない固定の色 |

- 文中では、強調する語句に付ける（例: `<strong className="c-ng">できない</strong>`）。
- SVG では `fill-*` / `stroke-*` の接頭辞を付けて使う（例: `className="fill-primary stroke-muted"`）。
- SVG では、さらに次のクラスを使える。
  - `fill-on` / `stroke-on`: 主役などの塗りの上に置く文字・線
  - `fill-surface`: 動画の地の色で塗る
  - `code`（`text` / `tspan` に付ける）: 変数名・型名・値などを等幅の書体で書く
- `callout` の 5 種類（`info`: 補足の情報、`tip`: ヒント、`warn`: 注意、`ng`: 誤り、`ok`: 正しい）とマーカー（`mark`）の色も、章によらない固定の色とする。
- 章カラーは、アプリが再生するときに指定した章（§5.1）で決まる。同じ動画は、どの章で再生してもその章の色になる。
- 章カラーを使うときの実際の色と、章に属さずに表示するときの色は、動画のデザインシステム（`screens.md` §10.1）に従う。

### 5.8 禁止事項

以下を含む動画のコード（`video/` の `.tsx`・`.ts`・`.css`）は、教材チェックツール（`content-guidelines.md` §6）の lint でエラーとする。

- 色の直接指定: 16 進表記（`#fff` など）、色の関数（`rgb()`・`hsl()`・`oklch()` など）、色の名前（`red` など）で色を書くこと。CSS の宣言、`style` に渡す値、SVG の色の属性（`fill`・`stroke` など）のどこに書いても対象とする。`none`・`currentColor`・`transparent`・`inherit` は書いてよい。
- Tauri の API へのアクセス: `@tauri-apps/` で始まるモジュールの import、`window.__TAURI__` などバックエンドを呼び出す手段の使用。
- ネットワークへのアクセス: `fetch`・`XMLHttpRequest`・`WebSocket`・`EventSource`・`navigator.sendBeacon` の使用、外部の URL（`http:`・`https:`・`//` で始まるもの）の参照（import、画像などの `src`、CSS の `url()`・`@import`）。
- ファイルへのアクセス: Node.js の組み込みモジュール（`fs` など）の import、`file:` の URL の参照。

これ以外（部品の作り方、動き、レイアウト）は、lint で制限しない。

## 6. 演習

### 6.1 ファイル

| ファイル | 内容 |
|---|---|
| `problem.md` | 問題文（Markdown） |
| `explanation.md` | 解説（Markdown） |
| `starter/` | 初期コード。cargo パッケージのルートからの相対パスで配置する（例: `starter/src/main.rs`）。`Cargo.toml` は置かない（アプリが生成する）。`src/main.rs` を必ず含める |
| `solution/` | 模範解答。構成は `starter/` と同じ |
| `cases.json` | `stdout` 方式のテストケース（§6.4） |
| `judge_tests.rs` | `test` 方式の隠しテスト（§6.4） |

### 6.2 問題文（problem.md）

以下の見出しを持つ。

| 見出し | 内容 |
|---|---|
| `## 問題` | 何を作るか |
| `## 入力` | 標準入力の形式（`stdout` 方式で入力がある場合） |
| `## 出力` | 出力の形式（`stdout` 方式）、または実装する関数のシグネチャと仕様（`test` 方式） |
| `## 例` | 入出力例、または呼び出し例 |
| `## 制約` | 使ってはいけないもの、守るべき条件など（任意） |

以下の見出しを持つ。

| 見出し | 内容 |
|---|---|
| `## 考え方` | 解き方の方針 |
| `## 模範解答` | 模範解答のコード（`solution/` と同じ内容） |
| `## ポイント` | このレッスンの主要素がどう使われているか |
| `## よくある間違い` | 想定される誤りと、そのときに出るエラー |

### 6.4 判定方式

**`stdout` 方式**: プログラムに標準入力を与えて実行し、標準出力を期待値と比較する。

```json
[
  { "name": "基本の例", "stdin": "3\n1 2 3\n", "expected_stdout": "6\n" },
  { "name": "空の入力", "stdin": "0\n\n", "expected_stdout": "0\n" }
]
```

| フィールド | 説明 |
|---|---|
| `name` | テストケースの表示名 |
| `stdin` | 標準入力として与える文字列 |
| `expected_stdout` | 期待する標準出力 |

**`test` 方式**: 隠しテストを学習者のコードに組み込んで `cargo test` で実行する。

```rust
// judge_tests.rs
use super::*;

#[test]
fn empty_input() {
    assert_eq!(sum(&[]), 0);
}
```

- `judge.target` のファイルの子モジュールとして組み込まれるため、`use super::*;` で学習者のコードを参照する。
- テスト関数名は snake_case の英語とし、表示名は `lesson.json` の `case_labels` で与える。
- 比較方法・組み込み方法・制限時間は `exercise-runner.md` §5 に定める。

## 7. 受け入れ条件

- `chapters.json` に載っているすべてのレッスンについて、`lesson.json` と必要なファイルが揃っていることを教材チェックツールで確認できる。
- どのレッスンの `primary_elements` にも含まれない要素（`deprecated` を除く）は、教材チェックツールでエラーになる。
- `kind` が `lesson` で `tags` のない `lesson.json` は、教材チェックツールでエラーになる。
- 色を 16 進表記で直接指定した動画のコードと、`@tauri-apps/` で始まるモジュールを import した動画のコードは、教材チェックツールでエラーになる。
- ダークモードに切り替えたとき、動画の中の文字・図の色がすべてテーマに合わせて変わる。
- 第4章の動画では `c-primary` が第4章の章カラーで表示され、同じ動画を第2章に移すと第2章の章カラーで表示される。`c-ok`・`c-ng`・`callout`・マーカー（`mark`）は、どの章でも同じ色で表示される。
- `start_line` が 118 のコードブロックは、行番号が 118 から表示される。
- `diff` が `true` のコードブロックでは、削除行に行番号が表示されず、ほかの行は変更後のファイルの行番号で表示される。
- `language` が `text` のコードブロックには行番号が表示されない。
- 範囲の一部だけが重なる `scopes` を指定した動画は、教材チェックツールでエラーになる。
- 台本にない文の ID を合図で指した動画は、教材チェックツールでエラーになる。
- `say` が 141 字の文がある台本は、教材チェックツールでエラーになる。音声を作るツールも、その台本の音声を作らない。
- 1 つの文の `say` を変えて音声を作るツールを実行すると、その文の音声だけが作り直され、`durations.json` のその文の記録が更新される。
- `voice.json` の `speed` を変えて音声を作るツールを実行すると、すべての文の音声が作り直される。
- `say` を変えたあと音声を作り直していない動画は、教材チェックツールでエラーになる。
- 音声を作り直して文の音声の長さが変わると、後ろの文とシーンの開始位置がその分だけ移り、絵と音声が合ったまま再生される。
- `cue-reference.json` の長さが 6.0 秒で、いまの音声の長さが 3.0 秒の文では、`at(文の ID, 2.0)` が文の開始位置から 1.0 秒後を指し、`at(文の ID, -0.2)` が文の開始位置の 0.2 秒前を指す。
- 表紙には、`lesson.json` の `title` と同じレッスン名が表示される。最初のシーンに `LessonTitle` がない動画は、教材チェックツールでエラーになる。
- 再生位置を動画の途中に移したとき、その位置まで通して再生したときと同じ絵が表示される。
